# 报告结构模板

从 v1.1 起产物分成两件，各管各的，**不要互相重抄**：

- **仪表盘 HTML**（`render_report_html.py` 生成）：一屏之内摆出全部证据——
  90 天成交价曲线、供给曲线、报价分位数、标准报价矩阵、折价、源健康度。
  这些全部由脚本从 evidence 确定性地渲染，模型一个数字都不用手抄。
- **报告 Markdown**：写仪表盘表达不了的东西——为什么、凭什么、什么证据会推翻它。

所以报告里**不要再复制报价表和标准报价矩阵**，那是仪表盘的活。报告引用数字是为了
支撑某个判断，不是为了把表再列一遍。

## frontmatter：仪表盘唯一认的判断契约

仪表盘顶部那块判断区只读这里。脚本原样搬运，不改一个字，也**不会替你生成结论**——
`verdict` 缺失时它会显示「报告未提供整体判断」，而不是编一个。

```yaml
---
date: 2026-08-25
window_days: 90
schema: gpu-compute-monitor/report/1.1

verdict:
  badge: 未确认宽松拐点          # 一个短语，定档用
  badge_tone: watch              # tight / watch / loose / unknown
  headline: 一句话说清今天的主要变化   # 20–30 字，是判断不是描述
  summary: >-
    120–160 字。讲清结论是什么、靠什么看出来的、以及有什么理由暂时不下定论。
  models:
    B200:
      status: 偏紧               # 显示出来的文字，自己拟
      tone: tight                # 决定颜色；文字始终在场，不靠颜色单独承载信息
      note: 库存 Low · spot 折价最小 −50.4% · 90D +23.4%    # 一行依据，30 字内
    H200 SXM: { status: …, tone: watch, note: … }
    H100 SXM: { status: …, tone: tight, note: … }
---
```

`tone` 的语义是**供需状态**，不是好坏：`tight` 偏紧、`watch` 观察中、`loose` 偏松、
`unknown` 数据不足。评分 `usable=false` 时多数情况该给 `watch` 或 `unknown`，
不要因为价格在涨就直接写 `tight` ——那是价格单腿，方法论不认。

## 正文结构

```markdown
# GPU 算力价格与供给监控 · 2026-08-25

## 市场判断与供需拐点
整体结论展开讲。frontmatter 的 summary 是压缩版，这里是完整版：
结论是什么、几条证据怎么互相印证或打架、哪些话现在还不能说。

## 市场成交价趋势
三个型号各自的走势和幅度，再说它们之间的关系——代际溢价在扩还是在收，
能不能分辨是产能到位还是需求迁移。必要时用 A100 / RTX 5090 两个参照系
判断是整条曲线在动还是某一代在动。

## 可用供给趋势
供给三件套怎么动：offer 份额、可用 GPU 数、库存档位。
核心问题是「价格那边的动作，供给这边认不认」。

## 报价与折价读法
不重列表格。只讲表里读出来的东西：分散度说明什么、挂牌价与成交中枢差多远、
折价梯度指向谁最紧。

## 数据完整性
今天缺了什么、对结论的影响有多大。逐源明细在仪表盘里，这里只说影响。

## 观察点
接下来盯什么，什么信号出现就该改判。
```

**长度**：正文 600–1000 字。比 v1.0 短，因为表格搬走了。

## Markdown 书写约束（渲染器的硬要求）

**每个段落写成一行，每条 bullet 写成一行，不要在句中硬折行。**
共享的 Markdown 引擎不支持 lazy continuation：bullet 的续行会掉出列表变成独立段落，
段落的续行会被当成断行渲染，读起来是一句话被拦腰截断。写长句就让它长，交给浏览器折行。

## 写作要求

**文风**：像跟懂行的人当面把事讲清楚——句子通顺、有逻辑衔接，给判断时把话说透。
不要模板腔，不要成段堆套话。

**罗列**：同一维度的多个条目用 bullet，一条一项，但每条用完整通顺的话写完，
不要退化成「字段A - 字段B - 字段C」式的横杠拼接。

**数字**：价格两位小数，单位 USD/GPU·hour；百分比一位小数带正负号。
每个数字都要能在 evidence 里找到出处。

**边界**：
- 不给买卖建议、不给目标价、不给仓位。
- 不用前值冒充最新值。缺就写缺。
- `usable=false` 的变化率不许出现在结论里。
- 状态必须用文字表达，不能只靠颜色。
- 说「可能是 X」时要说清凭什么，以及什么证据会推翻它。
