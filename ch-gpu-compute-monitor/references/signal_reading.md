# 怎么读评分、告警与拐点判断

`metrics.py` 给的是压缩过的证据，不是判断。这份文件讲怎么把它读成判断，
以及什么时候必须拒绝下判断。

## 一、Supply-Demand Score 是什么，不是什么

**是**：把价格 7D/30D、供给份额 7D、可用 GPU 7D、折价相对 30 日均值的偏离，
各自用 `tanh(x / scale)` 压到 [-1,1]，按 40/40/20 加权后乘 100。正值偏紧、负值偏松。

**不是**：一个可以直接抄进结论的判断。写报告时永远先看 `components` 里每一项的
`raw_pct` 和在场情况，再决定采不采信这个总分。

拒绝出分的三种情况（`usable=false`，`blockers` 里会写明原因）：

- 跨平台中枢的观测日少于 `min_history_days`（默认 21 天）——7D/30D 变化率不可信。
- 在场价格信号不足 2 个，或供给信号不足 1 个。
- 各分项全部缺失。

**遇到 `usable=false`，报告里就写"评分未出 + 原因"，不要自己心算一个近似值填进去。**
冷启动期没有分数是正确状态，不是缺陷。

`comparable_across_days=false` 意味着参与打分的源集合变了。分数本身还能看，
但**不能和昨天的分数比**——比出来的差值是数据源上下线造成的。

## 二、变化率的三重闸门

evidence 里每个 `changes` 条目都带 `usable`。三种情况会被判为不可用：

1. `date_drift_days` 超过容差——找到的基准点离目标日太远，不该当成"7 日前"。
2. `basis_match=false`——两端参与计算的源集合不同。**这是本项目最容易出的假信号**：
   实测新接入 Runpod+Vast 的当天，H100 跨平台中枢会凭空"跌" 25%。
3. 窗口起点根本没有观测。

`usable=false` 的百分比不许出现在结论里，连"约莫下跌了"都不行。要么写"不可比 + 原因"，
要么退回到单源序列（比如 Ornn 的 `by_source.ornn.transaction_index`，那条口径是稳定的）。

## 三、锚点为什么不是最后一天

Ornn 是 T-1 结算，所以"今天"的跨平台中枢结构性地只剩 Runpod+Vast。
`metrics.py` 因此不锚在最后一天，而是取最近 14 天里出现最多的那个口径
（`anchor_basis`），锚在该口径下最新的一天（`anchor_date`），在同口径内做同期比较。

写报告时：**用 `anchor_date` 的数当"最新"，并在旁边注明它比日历日晚几天
（`anchor_lags_raw_latest_days`）。** `raw_latest` 只用来说明"今天还采到了什么"。

## 四、告警怎么读

`alerts.mode` 默认 `record_only`：只入库不推送。原因是阈值还没按各 GPU 的
真实波动率校准，积累 2–3 个月历史之前，触发只代表越过了配置里那条线。

告警是**双边**的。PRD 原稿六条规则里五条指向宽松，但实测 2026-05~08 三个月
OCPI-B200 是 +23%、H100 +5%，方向是收紧。单边告警在这种行情下会长期零触发，
看起来像系统坏了。所以 `config/thresholds.yaml` 补了 `fast_price_spike`、
`trend_price_rise`、`supply_contraction`。

一条触发的告警要不要写进报告，看三件事：

- 触发它的 `observed` 值背后的 `usable` 是不是 true。
- 同方向还有没有别的信号（价格跌 + offer 份额涨才叫一致，只有价格跌可能是单源噪音）。
- 样本量够不够（Vast 那边 15 条 offer 上的分位数变化基本是噪音）。

## 五、确认型拐点

`confirmation` 的门槛是：价格类 ≥3 个信号 + 供给类 ≥2 个信号，
**连续 ≥10 个真实采到数的日子**，中间不允许有缺口（`allow_gap_days: 0`）。

这跟"快速降价"那类单日告警是两级：单日告警是预警，确认型是定性。
报告里两者不能混着说——预警说"出现了什么"，确认说"是不是拐了"。

对称地，确认型收紧用同一套门槛，方向相反。

## 六、价格降了到底意味着什么

同样是降价，成因不同，结论完全不同。分辨要靠供给侧和折价侧：

- 价格跌 + offer 份额涨 + 可用 GPU 涨 → 供给释放。这是真宽松。
- 价格跌 + offer 份额没动 + 库存档位没升 → 更可能是需求走弱，或者只是某个源的促销。
- 价格跌 + 折价（spot vs on-demand）扩大 → 闲置算力在增加，供给侧压力。
- 价格跌但只发生在一个源 → 先怀疑口径，再怀疑市场。查 `by_source` 里其它源同期是不是同向。
- 代际溢价收窄 + B200 供给份额上升 → 新一代产能到位。
- 代际溢价收窄 + B200 供给份额没变 → 老一代在贬值，是需求迁移不是产能到位。

## 七、什么时候该说"不知道"

以下任一情况成立，就在报告里明确写出来，不要硬凑一个判断：

- P0 源当天挂了两个及以上。
- 跨平台中枢的 `usable` 变化率一个都没有。
- 三个型号里有型号完全没有当日观测。
- 供给序列只有 1 天历史（冷启动第一周必然如此）。

用户要的是可信的边际判断，不是每天都有的判断。
