# 推理 token 的量与价：口径定义与可比性规则

这份文件回答一件事：**手里这个 token 数字到底是什么量、什么价，它能跟谁比。**
价格侧那份 `pricing_taxonomy.md` 管的是 USD/GPU·hour，这份管的是 USD/Mtok 与
tokens/day。**两边不是一个量纲，任何跨维度的减法都是错的**；把它们接起来要等
成本地板（P1，本轮未启用）。

## 一、为什么不是 ATSI

用户最初的构想是 `ATSI = (V_t/V_0) × (P_t/P_0) × 100`。数学没错，但落到真实数据源
上有硬伤：像 SDLLMTK 那类指数自己的定义就是「按用量加权的平均单价」，而用量加权
平均单价 ≡ 总支出 ÷ 总 token 数，于是 `V × P ≡ 总支出`——同源是恒等式，异源
（A 家的价 × B 家的量）则是两个不同市场的交叉乘积。对数分解 `g_spend = g_V + g_P`
同样两边恒等，**不可证伪的东西没有信息量**。

所以本 skill 做的是它的三分解：把价格拆成「真降价」与「购买结构迁移」两块。

## 二、四类"降价"，只有前两类是真的变便宜

一次混合价下跌里通常混着四件性质完全不同的事：

| 成分 | 是不是"AI 变便宜了" | 落在哪个指标里 |
|---|---|---|
| 同一模型真降价 | 是 | 固定篮子指数（Laspeyres） |
| 同家族的新版本更便宜 | 是，而且是最有价值的技术通缩 | 固定篮子指数 |
| 简单任务下沉到廉价模型 | **否**，是需求结构变化 | mix_shift |
| batch / 缓存折扣占比上升 | **否**，纯粹账单口径 | 拆不了，见第五节 |

**mix_shift = 混合价变化 − 固定篮子变化**，单位是百分点。它是本 skill 唯一的原创
信息：市场上争论「token 价格跌了 20% 是不是 AI 见顶」的人，没有一个把这 20% 拆开。

## 三、篮子：成员是"模型家族 × 变体"

家族 = 剥掉 `-20YYMMDD` 后缀的 slug。这个切法决定了第二类和第三类的分界线：

- **家族内的版本升级降价 → 真降价。** `deepseek-v4-flash-20260423` 换到 `-20260731`
  是同一条产品线自己变便宜。
- **跨家族迁移 → mix_shift。** 从 Claude 迁到 DeepSeek 是购买结构变化。

为什么非这么切不可：实测 2026-08-24 当天有 4 个家族同时挂着多个日期版本，合计
**16.3%** 的 token，其中 `deepseek/deepseek-v4-flash` 一家 **13.8%** 横跨两个版本。
按 slug 当篮子成员，版本迭代会被整块记成结构迁移，mix_shift 系统性高估。

篮子还锁住输入输出比例：家族的单价按**基期**的 prompt/completion 结构合成，之后
只让单价动。这样连"输入输出比例变了"这层 mix 也被锁住。

篮子从基期那天的观测确定性地重算，不手工维护成员名单、不落盘——口径改了直接
重跑，也不会出现配置与库里对不上的漂移。成员或基期变了，`basket_fingerprint`
就变，两段指数不许直接相减。

## 四、八条可比性规则

1. **同 `variant` 才能比。** `standard` / `free` / `batch` / `thinking` 是四个价格档。
   **join 键必须是「剥掉日期的 base + variant」**：`:batch` / `:free` 条目与标准条目
   共用同一个 `canonical_slug`（实测 69 处碰撞），按 canonical_slug 建索引会让标准
   流量被按半价甚至零价计。实测差别：spend $5.33M → $8.69M（+63%）、
   混合价 $0.529 → $0.797/Mtok。这是全案最大的坑。
2. **同 `coverage_scope` 才能比。** gateway（OpenRouter 这类网关）/ production_app
   （Vercel 这类单公司生产环境）/ hyperscaler（超大厂披露）/ benchmark。
3. **同 `price_basis` 才能比。** list（挂牌价）/ realized（真实账单）/
   synthetic_blended（按固定输入输出比合成，比如 Artificial Analysis 常用的 3:1）。
   **拿 realized 的支出去和 list 的支出相加是最容易犯的错**，量纲一样、口径不同。
4. **付费与零价不能混。** 实测零价占当日 token 40.1%，其中 free 变体只有 7.8%，
   主体是榜首那个匿名 stealth 模型（一家 32.3%）。量的主轴只用 paid。
5. **同结算频率才能比。** `view=day` 是已结算的 T-1（实测相隔 20 分钟的两次快照
   逐行一致，说明冻结）；`view=week` / `view=month` 是滚动窗口总量，不进日度序列。
6. **同 `query_fingerprint` 才能比。** 采集口径（view、join 方式）变了序列就断了。
7. **同源集合才能比。** 将来接第二个源时，源集合变动那天的合成中枢会跳——
   价格侧实测过：新接入 Runpod+Vast 当天 H100 跨平台中枢凭空"跌" 25%。
8. **同篮子指纹才能比。** 见第三节。

## 五、拿不到的东西，要明说

- **缓存命中率不可观测。** `total_native_tokens_cached` 在全部 530 行里都是 0——
  字段在、值不给。而 prompt token 占付费 token 的 **97.3%**、占 spend 的 **91%**，
  缓存读只按约 12% 计费（实测 `input_cache_read / prompt` = 0.119）。所以
  **spend 只能定义成「按挂牌价计的名义支出」**，敏感性：命中率 20% / 40% / 60%
  分别对应名义高估 19% / 47% / 93%。更要紧的是**趋势也被污染**——缓存采用率在涨，
  名义增速会系统性高于真实账单增速。因此对外结论的重心放在价格结构分解，
  不放 spend 水平。
- **reasoning token 通胀拆不了。** `total_native_tokens_reasoning` 与
  `total_tool_calls` 同样全为 0。只能用 `tokens/request` 做代理，并承认它同时
  混着"任务变复杂"和"同样的任务烧更多 token"两件事。
- **provider 份额看不到。** 同一模型在不同 provider 上单价不同（实测 glm-5.2 有 36 个
  endpoint、$0.50–$2.31）。价取模型默认价，实测 spend 加权 默认→中位 **1.152x**、
  最低 0.840x、最高 1.632x，带宽随 spend 一起报成不确定性区间。
- **日度模型级的历史补不回来。** rankings 只回当下，序列从首采日往后长。
  `view=month` 的滚动总量只能给上线首日一个水平锚，那是一个数不是一条线。
  （厂商级周度的历史能补，但那是另一条序列、另一个口径，见下一节。）

## 五之二、能补回来的历史：厂商级周度，另一条序列

日度模型级序列补不回去，但 `/api/frontend/v1/rankings/market-share` 有真历史——
**厂商级、周度、51 个已结算点、回到 2025-09-01**。它落在另一张表
`token_volume_history`，**不是**日度序列的延长线。三条硬规矩：

1. **最后一个点必须丢。** 相隔几分钟的两次取数，最后一点从 2.78443e13 降到
   2.75664e13——会往下走说明是滑动窗口而不是在累积。倒数第二点两次逐键一致，
   已结算的周是冻结的。采集时就丢，不给它进库的机会。
2. **不与日度序列相减。** 同一天按厂商比对，比值从 1.42（xiaomi）到 1.75（google），
   **不是常数倍**，成因未定（大概率是跨模型可比的归一化计数）。所以 `unit_basis`
   标成 `provider_reported_unverified`，只出份额、增速、指数，不出绝对水平。
   桥接比值要等日度序列盖满一个已结算周才算得出来；算不出来就报 `usable=false`。
3. **粒度只有厂商级。** 实测所有 grouping / by / level 参数都不改变返回的键集合，
   拿不到模型级历史。**厂商内部的模型迁移看不见**，这是这条序列的固有盲区。

### 结构效应指数

`Σ_a (历史份额_{a,t} × 今天的厂商均价_a)`，基期归 100。只有份额在动，价格锁死在今天，
所以它测的**只有购买结构迁移这一件事**，不含任何真实降价。

首跑结果：2025-09-01 = 100 → 2026-08-17 = **44.8**，也就是说光是买家往便宜厂商迁移
这一项，过去一年就把均价拉低了约 55%。同期量指数从 100 涨到 2030。份额搬家看得很直白：
一年前是 x-ai 25.2% / google 21.4% / anthropic 15.0%，现在是 deepseek 21.9% /
stealth 12.4% / xiaomi 11.2%。

它和日度的 `mix_shift` 是同一件事的两个尺度：日度那个是模型家族级、短窗口、
用真实价格变动；这个是厂商级、一年跨度、价格锁死。**不要把两者的百分比放进同一个句子里比大小。**

## 五之三、日度构成图的两条口径

仪表盘上的日度量用**堆叠面积图**：总量拆成前 7 个模型 × 变体 + 「其他」。
两件事必须固定下来，否则图会骗人：

1. **条带由锚定日的排名一次定死，之后每天按同一组条带拆。** 每天各取前 N 名的话，
   同一条带子今天代表 A 模型、明天代表 B 模型，叠出来的面积看着连续，其实是一堆
   不同的东西拼在一起。锚定日不在前 N 的模型，历史上那几天一律落进「其他」。
2. **「其他」是减出来的余数**（当日总量 − 前 N 之和），不是把长尾再数一遍。

排名依据在 `config/token_basket.yaml` 的 `composition.rank_by`，默认 `tokens`。
选它是为了自洽——图上画的就是 token 量，用调用次数排名会出现"排第一的模型在图里
只有一条缝"。两个口径的差别是真的：实测同一天 `deepseek-v4-flash-20260423` 有 7300 万次
调用却只占 4.4% 的 token，而 `stealth/ox-alpha` 用 7000 万次调用吃掉 32.3%。
想按调用次数排就把 `rank_by` 改成 `requests`，一行配置的事。

**量用总 token（含零价）**，因为这张图回答的是"用量的构成"。但每条带子都标了
是否有价——榜首那条 32.3% 是匿名 stealth 模型在免费放量，把它当成收入或需求强度
看都会高估一大截。

## 六、样本边界

OpenRouter 是 **merchant API 层的一个偏斜样本**（编码 agent 与 roleplay 主导），
**不是全市场**。真正的大头在它外面：first-party 订阅（按座位不按 token 计费）、
超大厂内部推理（没有市场价格）、企业直签折扣合同、云厂商的私有计量。
所有结论必须冠上这个前缀，不能说成"全球 AI token 支出"。

## 七、将来接其他源

不许把多个源平均或合并成一个"全市场指数"——它们不是同一个指标的多次测量，
而是不同指标的碎片。

| 源 | 实际给的是 | 够格担任的角色 |
|---|---|---|
| OpenRouter | 量 + 挂牌价，唯一两边都有 | **主干**：主指数只能由它建 |
| Artificial Analysis | 逐模型价格与吞吐，没有量 | 价格校验位，产出背离度 |
| Vercel AI Gateway | 真实账单支出，没有独立价格指数 | 水平校验位，须归一到 per-app |
| 超大厂披露 | 量，含无价格的内部推理 | 规模锚，季度频率 |
| Epoch | 能力恒定价 | 另一根轴，不与上面任何一层相减 |

唯一合法的合并场景：出现第二个同样能给量又能给价的网关时，才可按各自 token 量
加权合成"网关层中枢"。校验 Artificial Analysis 时必须先用**同一个合成假设**
（它的固定输入输出比）把我们的混合价重算一遍，否则背离度全是口径造成的假象。
