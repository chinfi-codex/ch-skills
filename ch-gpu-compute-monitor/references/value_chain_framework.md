# AI 产业链六层监控框架：数据源、指标与分析含义

这份文件回答一个比「再加几个指标」更靠前的问题：**AI 行业要监控的到底是什么结构，
每一格该看什么数，看到了怎么解释。** 现有的 GPU 租金（L3）与推理 token 量价（L4）
是这条链上相邻的两格，本文把上下游补齐，并给出跨层解读规则。

口径定义仍以 `pricing_taxonomy.md`（USD/GPU·hour）与 `token_taxonomy.md`（USD/Mtok）
为准，本文只管**层与层之间怎么接**。

---

## 零、为什么按链条组织，而不是按指标堆

指标堆到一定数量之后，问题不是不够多，而是**互相之间不知道该信谁**。同一天里
GPU 租金在涨、token 均价在跌、台股月营收在飙、neocloud 债券在跌，这四件事不矛盾，
它们只是发生在链条的不同格上、处在不同的时间位置。

所以每个指标进来之前必须回答三个正交的问题：

- **它在链条的哪一层**：决定它跟谁可比、它的变化该传导到哪里去。
- **它是什么性质的量**：分四类——「量」是实际发生了多少，「价」是边际稀缺程度，
  「约束」是天花板在哪，「预期」是参与者认为未来会怎样（订单、积压、拍卖、利差）。
  预期类天然领先，但也最容易反身性失真，不能单独定性。
- **它相对 L3（GPU 租金）是领先、同步还是滞后**：同步指标堆再多也只能互相印证，
  提前量为零。现有的两个指标恰好都是同步的，这是当前体系最大的结构性缺陷。

有了这三个标签，跨层信号才有可能被证伪：如果 L1 的出货在三个月前就在飙，
而 L3 的供给指数至今没有松动，那要么是传导被 L2 卡住了，要么是这批货没进租赁市场。
这是一个可以去查的问题，而不是一句「产能在放量」。

## 一、链条总图与物理时间常数

```
L0 资本与信用  ──3~6月──▶  L1 芯片与服务器产能  ──1~3月(有电才算)──▶  L2 电力与机房
                                                                          │
                                                                      2~5年(接入)
                                                                          ▼
L5 应用侧收入  ◀──即时──  L4 推理 token 量价  ◀──即时──  L3 GPU 租金（上架即定价）
      │
      └──12~24月（叙事验证：收入池能不能反过来支撑 capex）──▶ 回到 L0
```

这些时间常数是整套框架的骨架，因为它们让「预测」变得可证伪：L0 的一笔融资，
应该在 3~6 个月后出现在 L1 的月营收里，再过 1~3 个月出现在 L3 的供给侧。
**说好的传导没有按时出现，本身就是信号**，通常意味着中间某一层有个没被看到的约束。

注意 L2 是唯一一个时间常数以年计的环节。这决定了当前周期的瓶颈位置：芯片可以加单，
机柜可以赶工，但电力接入排队排的是三到五年。**任何认为「产能马上就上来了」的判断，
都必须先在 L2 找到对应的电。**

## L0 · 资本与信用

这一层决定整条链的燃料供给，也是**转折出现得最早的一层**——融资条件恶化会先于
出货下滑、先于价格见顶。

### 主锚：超大厂 capex 与其折旧假设

微软、谷歌、亚马逊、Meta、甲骨文的季度资本开支，加上折旧年限假设的变化。
走 SEC XBRL 取数（实测可用，需带 User-Agent）：

```
https://data.sec.gov/api/xbrl/companyconcept/CIK{10位}/us-gaap/PaymentsToAcquirePropertyPlantAndEquipment.json
```

实测微软截至 2026-03-31 的季度 capex 为 308.8 亿美元。这条序列要看三个数，不是一个：

- **capex 绝对额与同比**，这是燃料的流量。
- **capex ÷ 经营现金流**，这是自给率。长期超过 100% 意味着扩张要靠举债或发股，
  链条从此对利率敏感，L0 的信用指标才真正开始有约束力。
- **折旧年限假设的变更**。服务器折旧从 3 年拉长到 5、6 年，会在不改变现金流的前提下
  凭空抬高利润。**这个动作出现时，等于管理层在赌 GPU 的经济寿命比市场想的长**，
  而 L3 的二手残值就是检验这个赌注的外部证据。

陷阱：capex 口径是战场。融资租赁算不算、自建电厂算不算、各家披露不一致，
跨公司比绝对值意义有限，比同比与自给率更稳。

### 最早的转折指标：neocloud 的融资成本

CoreWeave、Nebius、Crusoe、Lambda 这类公司的资本结构就是「借钱买 GPU、用租金还本息」，
所以它们的债券收益率与利差是**整条链上对 L3 前景定价最直接的市场指标**。
利差走阔的含义很明确：市场认为未来的 GPU 租金还不上这笔债。

数据可得性较差，FINRA TRACE 只有网页查询没有免费 API，实务上要么手工补录，
要么用上市 neocloud 的股价与可转债隐含收益率做代理。频率上建议做成周度手工表，
跟 `attested_prices.yaml` 同一种模式。

### 边际供给的资金闸门：GPU 抵押融资

以 GPU 为抵押的 ABS 与私募信贷，是中小 neocloud 扩张的主要渠道。KBRA、Moody's 这类
评级机构的 pre-sale 报告公开可读，里面通常带着**抵押 GPU 的估值假设与折旧曲线**，
这是极少数能看到市场对 GPU 残值真实假设的地方。发行量骤停等于边际新供给停止扩张，
这个信号会比 L1 的出货下滑早半年以上。

### 佐证层

一级市场融资额（模型公司与基础设施分开看）反映风险偏好，走 `ch-news-reporter` 的
新闻聚合能拿到大额事件，系统性数据要收费库。二级市场的 AI 篮子相对表现与隐含波动率
反映的是叙事定价而非基本面，但叙事本身就是 L0 的资金来源，不能不看。

## L1 · 芯片与服务器产能

这一层回答「未来 6~12 个月会有多少算力上架」。

### 主锚：台股月营收（已实测，免费无 key）

这是整个框架里**性价比最高的一条数据**：月度披露、滞后约十天、免费无需注册、
一次调用拿全市场。

```
上市：https://openapi.twse.com.tw/v1/opendata/t187ap05_L
上柜：https://www.tpex.org.tw/openapi/v1/mopsfin_t187ap05_O
```

返回字段含当月营收、上月营收、去年同月营收、月增减%、年增减%、累计与累计年增减。
实测 2026-07 数据（8/17 出表）：

- 广达（2382）3663 亿新台币，同比 **+131%**
- 鸿海（2317）9465 亿，同比 +54%
- 台积电（2330）4676 亿，同比 +45%
- 纬创（3231）3082 亿，同比 +61%
- 纬颖（6669）1177 亿，同比 +39%
- 技嘉（2376）442 亿，同比 +60%
- 世芯-KY（3661）74 亿，同比 +182%

它比季报路径（`us-ai-semi-earnings`）快一整个身位：季报滞后一到两个月且只讲过去，
月营收是**当月实际销货**。要按三层读，不要拉平成一个数：

- **整机 ODM** 看广达、纬创、纬颖。纬颖的 AI 服务器纯度最高，适合当主锚；
  广达有笔电、鸿海有 iPhone，业务混杂。
- **散热与电源** 看奇鋐（3017）、双鸿（3324）、台达电（2308）。这一层的增速
  通常领先整机，因为它们更早备料，而且液冷渗透率的变化会体现在这里。
- **代工与 ASIC** 看台积电、世芯。世芯代表的是自研 ASIC 路线，
  它跟英伟达系的相对增速，是「客户在多大程度上想绕开英伟达」的直接读数。

陷阱有两个，都会致命：其一，**必须看同比不看环比**，因为九到十一月是 iPhone 拉货季，
鸿海、广达的环比会被消费电子的季节性完全淹没。其二，月营收含全部业务，
所以增速的绝对水平不能当成 AI 业务增速，只能看**边际变化与公司间的相对关系**。

### 佐证：英伟达的采购承诺

英伟达 10-Q 里的 purchase obligations 与 supply commitments 是**前瞻性的**：
它是英伟达对上游锁下的单，通常领先自身收入两到三个季度。这比数据中心收入本身
更有信息量，因为收入是已经发生的事。同样走 SEC XBRL 或直接读 10-Q。

### 佐证：HBM 与先进封装

SK 海力士、美光、三星的 HBM 产能与定价，台积电的 CoWoS 产能指引。这两样是
过去两年 GPU 出货的实际瓶颈，一旦紧张缓解，L1 的产出上限会跳一档。频率是季度，
走财报与电话会议，`us-ai-semi-earnings` 已覆盖这条路径。

### 佐证：交期与政策

从下单到交付的 lead time 没有公开系统性数据，只能从电话会议与新闻里抽取，
走 `ch-news-reporter`。出口管制与对华出货许可属于阶跃型事件，
一次政策变化能瞬间改变某个区域市场的供需，必须单独跟踪，不能指望从价格里反推。

## L2 · 电力与机房

**这是当前周期真正的物理天花板**，也是最容易被忽略的一层——因为它的数据频率低、
可得性差，而且不像价格那样每天跳动。但它决定了 L1 的货能不能变成 L3 的供给。

### 主锚：数据中心密集区的电价与负荷

PJM 的 DOM zone（北弗吉尼亚）与 ERCOT 是全球数据中心最集中的两个区域，
它们的批发电价与负荷曲线是**算力扩张的实时物理体现**。

- EIA API：`https://api.eia.gov/v2/...`，实测无 key 返回 403，注册后免费。
- PJM Data Miner 2：`https://api.pjm.com/api/v1/...`，实测 401，注册后免费。
- ERCOT public reports：`https://api.ercot.com/api/public-reports`，实测 401，需注册。

三个都要注册但都免费，日度甚至小时级。含义在于：如果某个区域的电价与负荷同步抬升，
说明新增数据中心负荷已经落地了；如果电价涨而负荷平，那是供给侧问题（发电或输电），
对算力扩张同样是坏消息。

### 约束指标：容量拍卖与互联队列

PJM 的容量拍卖出清价是年度的，但它是**市场对未来三年电力稀缺程度的直接定价**，
是这一层信息密度最高的单个数字。互联队列（interconnection queue）的容量与等待时长
则是最硬的产能天花板，LBNL 每年出免费报告，含义是领先两到五年的物理约束。

这两个指标的用法跟价格指标完全不同：它们不用来判断拐点，**用来判断某个乐观预测
在物理上是否可能**。当一份研究说未来两年新增多少 GW 算力时，先去队列里看有没有这些电。

### 约束指标：空置率与在建容量

CBRE、JLL 的半年度数据中心报告免费公开，datacenterHawk 部分免费。北弗吉尼亚的
空置率已长期贴近零，含义是新增算力只能靠新建而不能靠填空，这直接把 L1→L3 的
传导时滞从「一到三个月」拉长到「按新建周期计」。

### 约束指标：发电与配电设备的积压

燃气轮机、变压器、开关设备的交期与在手订单，看 GE Vernova、西门子能源、
三菱重工的季报 backlog。**这是当前物理瓶颈的最尖端**：重型燃机的交付已排到数年后，
意味着即便拿到了并网许可，发电设备本身也是排队项。

### 事件层：电力采购新闻

核电 PPA、自建燃气电厂、就地发电（behind-the-meter）的签约，属于阶跃事件，
走 `ch-news-reporter`。这类新闻的价值在于它揭示了**厂商愿意为绕开电网排队付多少溢价**，
溢价越离谱，说明 L2 的约束越紧。

## L3 · GPU 租金（已有）

现有的四层价格框架（成交价、即时 offer、市场聚合报价、标准云报价）加供给指数，
口径见 `pricing_taxonomy.md`。这里只讲**还缺的三样**。

### 缺口一：合约期限结构

现在四层价格里已有 committed 口径，但没有把「现货 / 一年 / 三年承诺」的价差
做成一条序列。这个价差就是算力市场的期限结构：长约相对现货**贴水**说明市场预期
未来供给宽松，**升水**说明预期持续紧缺。它是 L3 内部唯一带前瞻性的指标，
其余全是当期。

### 缺口二：二手 GPU 残值

现有边界明确排除了二级市场买卖价。建议重新考虑，理由是它在框架里承担着独一无二的
角色：**它是 L0 折旧假设的唯一外部检验**。当超大厂把折旧年限拉长、
当 ABS 用某个残值曲线给 GPU 定价时，二手市场的实际成交价是唯一能证伪这些假设的数。
A100 的残值曲线尤其有价值，因为它已经走完了一个完整的代际周期，
可以用来标定 H100 未来的折旧路径。

### 缺口三：拥堵度

原本设想用 OpenRouter 的 provider 侧延迟与吞吐做拥堵代理，**实测不可行**：
`/api/v1/models/{id}/endpoints` 返回的 `latency_last_30m` 与 `throughput_last_30m`
在多个模型上全为 null。可用的替代是同一接口里的 `uptime_last_5m / 30m / 1d` 与 `status`，
逻辑是 provider 容量吃紧时会先表现为限流与报错，即 uptime 下降。这条比延迟弱，
但方向可信，且零新增数据源。

另一个方向是从 Vast 的 offer 快照里算**挂单存活时长**：同一台机器在榜上待多久被租走。
存活时间缩短等于需求吃掉供给的速度加快，这比 offer 数量本身更接近利用率。

## L4 · 推理 token 量价（已有）

现有的量指数、双价格指数（当期权重 blended 与锁基期 Laspeyres）、mix_shift 三分解、
名义 spend 重建，口径见 `token_taxonomy.md`。缺的是**结构维度与外部标尺**。

### 缺口一：应用维度（已实测可用）

现在只有模型 × 变体维度，没有「谁在消费」。`https://openrouter.ai/api/frontend/v1/rankings/apps?view=day`
免费可用，返回 app_id、total_tokens、total_requests 与应用元信息。实测当日结果：

- 榜上前二十名几乎全是 agent 与 coding harness，Hermes Agent 单家 2.47T tokens/日
  占榜内 34.6%，其后是 Claude Code 14.1%、Kilo Code、DeepSeek Harness、Cline、Codex、OpenClaw
- 这些应用的 tokens/request 普遍在 6 万到 19 万之间，聊天类应用根本进不了榜

这个结构有很强的解释力：**token 量的增长主轴可能是 agent 化带来的单次调用膨胀，
而不是用户数增长。** 两者对算力需求可持续性的含义完全不同——前者随 agent 产品形态
变化可能急停，后者是慢变量。现有指标体系区分不了这一层，
`tokens_per_request` 只看得到总量效应，看不出是哪类应用推起来的。

必须写进口径的坑：这个榜只回 top-20，且 rank 序列有洞（实测返回 1、5、6、7…，
2/3/4 缺席说明有应用选择不公开）。**只能做结构与趋势，不能当总量分母。**

### 缺口二：能力-成本前沿

现有的 Laspeyres 篮子测的是「同一模型或同一家族变便宜了多少」，但没有测
「达到同样能力水平现在要花多少钱」。这条决定了 mix_shift 会不会继续：
只要便宜模型在能力上持续追赶前沿，简单任务下沉就还没结束，结构迁移就会继续压低均价。
Artificial Analysis 有 API（实测 `https://artificialanalysis.ai/api/v2/data/llms/models` 返回 401，
注册后有免费额度），Epoch AI 有公开数据集。

用法是构造一条「达到某能力阈值的最低价格」时间序列，它的斜率就是**真实的技术通缩率**，
跟 Laspeyres 的差额则是「能力升级」与「同款降价」的分界。

### 缺口三：样本外的校准

OpenRouter 是 merchant API 层的偏斜样本这件事已经写进边界，但没有任何外部标尺
去估计偏斜有多大。可用的粗校准是拿超大厂财报里披露的 token 处理量
（部分厂商在电话会议里给过）跟 OpenRouter 同期的量做比值，比值本身不稳定，
但**比值的变化方向**能说明 merchant 层是在扩张还是在被 first-party 抽走。

## L5 · 应用侧收入

这一层回答整条链的终极问题：**这些 token 最后有没有人付钱，付的钱够不够还 L0 的债。**
也是数据最差的一层，几乎没有干净的公开源，但不能因为难就不看。

### 硬数据：企业 AI 采用率

美国 Census 的 BTOS（Business Trends and Outlook Survey）双周发布、按行业与企业规模
拆分实际使用 AI 的企业占比。这是**唯一一个覆盖全经济体、非自报商业口径的采用率硬数据**。
实测 `api.census.gov/data/timeseries/btos` 返回 302 没有可用 API，
但 `https://www.census.gov/hfp/btos/data` 页面提供 CSV/XLSX 下载，只能做成半自动补录。

它的价值在于校验 L4：如果 token 量在飙而企业采用率横盘，
说明增长集中在开发者与个人用户，而不是能签长期合同的企业预算。

### 收入代理：模型公司 ARR 与应用流量

OpenAI、Anthropic 没有公开披露，只能靠媒体报道与泄露数据，走 `ch-news-reporter`
并标注证据等级。应用流量方面 Similarweb 的免费层能看主要站点的月度趋势，
应用商店榜单可抓但收入估算要收费库。这些都是弱证据，用法是**看方向不看水平**。

### 收入代理：上市公司的 AI 收入披露

SaaS 与软件公司在财报里披露的 AI 相关收入、席位定价、附加模块渗透率。
口径极不统一，但它是唯一有审计的 L5 数字。走 `us-ai-semi-earnings` 的取数路径扩展。

### 单位经济：推理毛利

这是现有 P1 的成本地板工作（`usable=false` 的键位已留）。做出来之后，
L3 的 USD/GPU·hour 与 L4 的 USD/Mtok 才第一次可以放进同一个算式：
用吞吐表把小时租金换算成每百万 token 的成本地板，跟 L4 的实际售价相减就是毛利。
**在这之前，两个量纲之间的任何减法都是错的**，这条纪律不能松。

---

## 二、闭环判据：从 L5 回到 L0

链条不是直线而是环。最终要检验的命题只有两个：

**收入覆盖率 = L5 的年化 AI 相关收入 ÷ L0 的年化 AI capex。** 这个比值在扩张早期
必然很低（先建后卖），关键不是水平而是**趋势**：如果 capex 持续加速而收入池增长跟不上，
缺口只能靠 L0 的信用继续填，而信用的成本就写在 neocloud 的利差里。

**折旧覆盖率 = GPU 全生命周期的租金收入现值 ÷ 采购成本。** 这个数直接由 L3 的
租金曲线与 L0 的折旧假设决定，而 L3 的二手残值是它的外部检验。当租金下行速度
快于折旧假设隐含的速度时，整条链的资产负债表就开始出问题——**这是最终的爆点，
而且它会先出现在 L0 的利差里，再出现在 L1 的订单里，最后才出现在 L3 的价格里。**

## 三、跨层解读规则

单层信号永远不能定性。**任何定性判断至少要两层同向**，且必须说明传导方向。
四种典型形态：

**需求拉动（健康）**：L4 的量在涨且 paid token 占比稳定，L3 价格随之上行，
L1 月营收跟着走高，L0 的 capex 指引上修。这四件事按时间常数依次发生，
每一格都能在前一格找到解释。

**供给收缩（价涨但不健康）**：L3 价格上行而 L4 的量横盘。这时候涨价不是需求好，
要去 L2 和 L1 找原因——是电力接不上，还是交付延迟。**这种涨价对产业链是坏消息**，
因为它抬高了 L5 的成本却没有对应的需求，会压缩下游变现空间。

**产能过剩前夜（最危险的组合）**：L1 月营收高增，同时 L3 价格见顶回落，
L0 的利差开始走阔。含义是大量供给正在路上而定价能力已经开始松动，
且融资市场先于现货市场看到了这一点。这三个信号同时出现时，
**优先信 L0**——它的时间位置最靠前。

**技术通缩吸收（容易误读）**：L4 的量在涨但 spend 走平甚至下降，因为
mix_shift 与真降价一起吃掉了量增。这时 L3 的需求不一定跟着涨，
因为同样的业务量需要的算力在下降。**不能从「token 量涨」直接推出「算力需求涨」**，
中间隔着一个效率变量，而这个变量正是 Laspeyres 与能力-成本前沿要测的东西。

## 五、口径纪律

这三条是从现有 skill 的教训里长出来的，跨层之后只会更重要：

**不同层的数不进同一个减法。** USD/GPU·hour 与 USD/Mtok 之间隔着一张吞吐表，
新台币月营收与美元 capex 之间隔着汇率与口径，企业采用率与 token 量之间隔着抽样框。
**要接起来必须显式写出中间那一步，并让它可审计。**

**每个跨层指标都要带 usable 与原因码。** 现有体系里价格与 token 的变化率都有三重闸门，
新增层同样需要：月营收遇到季节性时不可用，电价遇到极端天气时不可用，
BTOS 遇到问卷改版时不可用。缺就是缺，不许用前值冒充，也不许心算近似值。

**领先指标不能用同步指标的阈值去校准。** L3 的告警阈值按日度波动率定，
但 L1 的月营收波动率完全不同，L0 的利差更是跳变型。每一层要有自己的
波动率标尺与最小观测数，混用会让告警要么长期不触发、要么天天触发。
