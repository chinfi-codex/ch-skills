# ai_daily 分析框架 · v1 agent 主形态

> 本文件是 ai_daily **分析框架的唯一可信源**。框架契约——两条论点轴的 frame 维度、regime 失效触发器、输出板块——都收敛在这里。
> 跨框架不变的方法论常量（数据信息分层、输出判断边界、通用反例）见同目录 `methodology.md`；状态机制见 `../watchboard.md`；重点公司清单与别名见 `config/report_profiles.yaml` 的 `company_groups`（采集/归类字典，供 Agent 阅读）。
> **变更框架只改这一个文件。** 当 regime 质变（agent 不再是主形态）时，由慢思考层生成新版本框架整体替换，经人确认后切换。

## 模型区 — 本框架的领域判定逻辑与写作要点

### 两条坐标轴（报告主干）

当前 AI 产品的主形态是 **AI agents**。本日报把每天的多信源新闻，落到一个二维坐标系里——

1. **纵轴 · 能力与技术演进（供给 / 能力侧，键 `agent_eng_vectors`）**：模型和产品的能力、技术今天往哪走了？两路证据并到同一条"矢量"上看——前沿实验室（OpenAI / Anthropic / Google 等）发了什么模型、加了什么能力（读成"解锁了哪类 agent 行为"）；开源项目在解哪个"把 agent 做出来"的工程痛点。同一条方向当天有多个证据一起推 = 这条在**收敛**。
2. **横轴 · 渗透率（需求 / 采用侧，键 `product_forms`）**：AI 产品今天有没有让更多人、更多场景真用上？看新载体 / 新用户段 / 新自主度 / 新分发入口，以及最关键的**真实使用信号**（不是 star / votes）。没有就直说"今日无新渗透信号"，不硬凑。

**两轴就是主干，不是十节里的两节。** 证据用两个引擎（见下）捞齐后，**直接并进它最该落的那条轴**——能力 / 技术的归纵轴，谁能用上 / 用得更多的归横轴；不再单列"新项目雷达 / 公司矩阵"两节把同一批对象重抄一遍。大盘里跟两轴无关的大事，一句话带过。

### frame 字段填写约定

- **`agent_eng_vectors`（纵轴）**：每条 `{vector, stage: 实验→收敛中→事实标准, open_pain（当前卡在哪）, side: lab|oss|both}`。至少 1 条。
- **`product_forms`（横轴）**：每条 `{form, segment: 开发者|专业用户|大众|企业, penetration_stage: 萌芽→早期采用→主流化, usage_signal（真实使用证据，非 star/votes）}`。
- **`watch_companies`**：预期近期有动作的重点公司。**`watch_projects`**：标了"值得继续观察"的开源项目/产品，带 id 进台账，等热度兑现成趋势再结算。

### 第一性原理：为什么用双引擎

AI 行业的边际信息在两个源头交替出现，单看都不够：公司只看不开源会丢早期信号（Agent/MCP/Coding Agent 的前沿常先在 Show HN 和 GH Trending 跑出来）；只看开源不看公司会丢规模化判断（真正决定能不能用、能不能赚钱的还是大厂 API、定价、产品入口）。所以先各自捞齐证据，再收敛到两条坐标轴。

### 引擎 A · 新项目发现（GitHub Trending + Product Hunt + Show HN）四步

1. **项目特征定性**：归入统一标签——基础模型与权重 / Agent 框架与编排 / 开发者工具链 / 推理与部署 / 数据与 RAG / 应用产品 / 评测与基准 / 开源基础设施。
2. **解决的 agent 工程痛点画像**：一句话回答"真实需求、给谁用"；agent 项目落到具体痛点（编排 / 记忆与上下文 / 工具标准化 MCP / 可观测 / 沙箱与运行时 / eval / 成本可靠性）。非 agent 项目登记但标"大盘背景"。
3. **热度真伪辨别**：star / votes / comments 只代表注意力。看 GH 的 stars/day、release、license、pricing、issues、push 活跃；看 PH 是否有 pricing/docs/API/enterprise 入口、是否 AI 原生；看 Show HN 回帖是积极采用还是技术质疑。
4. **趋势聚类**：同类项目当天 ≥ 2 个才单列一条方向信号，**单点不写趋势**。

### 引擎 B · 重点公司动作

完整公司清单与别名见 `config/report_profiles.yaml` 的 `company_groups`（国际：OpenAI/Anthropic/Google/Meta/Mistral/NVIDIA/HuggingFace；中国：Kimi/智谱/Minimax/腾讯/阿里/字节/DeepSeek/百度）。

把当日公司动作按四类识别：① 模型发布（基础 / 推理 / 多模态 / 专用 / 开源权重 / 版本号）；② 产品更新（C 端 App、Agent 平台、IDE 插件、企业版）；③ API & 定价（新端点、企业入口、token 定价、免费额度）；④ 融资 & 政策（融资、并购、合作、监管、人事）。**这只是识别口径，不是输出章节**：①②③ 里属"能力 / 技术"的并进纵轴、属"降低渗透门槛 / 扩用户"的并进横轴；④ 融资 & 政策不进两轴，落到「原始证据附录」的"资本与政策"短 list。

**三个分析维度**：每个动作先过 agent 透镜（解锁了哪类 agent 能力 / 是否降低渗透门槛，分别归纵轴 / 横轴）；模型 vs 产品分开（别把加个按钮当模型升级）；中美阵营对照（同一窗口内是呼应还是错位）；商业化层级（研究→权重→API→产品→企业→生态，今天在哪层）。

### 两轴综合（证据写完后必做）

- **纵轴定档**：每条矢量给档位（实验→收敛中→事实标准），判档看证据强度不看热度；**收敛判定**：同一矢量当天 ≥ 2 个独立证据（理想一个实验室 + 一个开源）攻同一痛点 → 进 `agent_eng_vectors`，写清 `open_pain`。
- **横轴五追问**：载体 / 入口、用户段、自主度（copilot→有监督→后台自治）、渗透信号 vs 注意力信号（只有真实使用进 `usage_signal`）、分发入口。每条给渗透档位（萌芽→早期采用→主流化）。**今天没有新渗透变化就如实写"今日无新渗透信号"，绝不硬凑**。
- **横向对照**：供给↔需求是否对得上、开源↔公司谁填了谁的空、中美各自集中 / 空缺在哪条矢量或形态——只写关系，不重抄证据。

> 参考矢量库（从当日证据自然聚类，别硬套）：长任务可靠性 / 工具标准化(MCP) / 多智能体编排 / 记忆与上下文 / computer use / 推理成本与小模型 / agent eval / 沙箱与运行时。

### 价值定级（两轴归类后必做，决定谁值得深挖）

两轴综合把每个对象落到了轴上、给了档位，但"落哪条轴"只回答了**方向**，没回答**分量**——同样落在纵轴，一个 flagship 模型发布和一次社区小工具不该同等笔墨。这一步显式给每个当日对象定一个价值级，决定它在报告里占多少篇幅、要不要触发深挖 enrichment。这也是把日报从"广度齐全"推向"重点有深度"的那道门：先判出今天真正重要的东西，再把火力集中砸下去。

**三档锚点（按满足的最高档取，不是叠加打分）：**

- **S 级 · 今日重点（深度拆解 + 深挖 enrichment）**——满足任一：
  - 让某条纵轴矢量**当天进档**（实验→收敛中、收敛中→事实标准）或**新开一条矢量**，即真的解锁了一类此前做不到的 agent 行为 / 明确的能力跃迁，且有官方一手证据；
  - 横轴**新开一个形态 / 入口**，或让现有形态**跨档**（萌芽→早期采用→主流化），且有真实使用信号（不是发布会 demo / PR 稿）；
  - 头部厂商 flagship 级动作（新一代基础模型、新产品线、重大定价重构），且**同时影响 ≥2 个 frame 维度**（例：既解锁能力又压低成本、既是能力发布又自带渗透入口）。
- **A 级 · 轴内详展**：明确落在某条轴、值得在该轴里写清 4-5 行，但没到"改变格局"的分量。绝大多数有效证据都是 A 级。
- **B 级 · 附录一句话**：登记即可，只在原始证据附录里一句定性 + 指针。

**排除项（写死，命中就最多 A 级，不得升 S）：**

- 纯刷榜 / 跑分登顶，只有榜单和叙事、无第三方独立复核；
- 单源转述、未见厂商官方页面确认；
- demo / 发布会演示 / 内测预告，能力或产品尚未真实开放使用；
- star / votes / score 高但无采用、付费、迁移等真实使用证据。

**硬上限与纪律：S 级每天 0-2 个，宁缺毋滥。** "今天没有够 S 级的对象"是常态、要如实接受（和横轴"今日无新渗透信号"同一个纪律）——天天都能凑出"今日重点"，等于把深度又稀释回广度，定级就失效了。定为 S 级的对象，后续三件事必做：走深挖 enrichment（见 `enrichment.md` 的"深挖 pass"）、在报告的「今日重点·深度拆解」板块展开、开 / 更新一条 watchboard 跟踪项记录这次价值判断（links_to 指向它推动的 `agent_eng_vectors` / `product_forms`），供后续结算战绩。

### 各输出板块写作要点（新结构，报头之后约 7 块）

每条证据全文只详展一次（硬约束见 template 顶部"去重铁律"）。口吻日常化——像给懂行的朋友发消息讲今天的事：主语是公司 / 项目 / 人，判断词用日常说法，矢量名和档位词只在定档处出现、周围解释全用大白话，档位和判断照样要准；同维度多条目一律 list，每条说完整通顺的话，别退化成"字段A - 字段B"横杠拼接（完整常量见 `methodology.md` 文风常量）。

- **① 一句话结论（唯一速读层）**：3-4 句，站在框架高度写"认知地图今天动没动"，不是新闻摘要。第一句必须是**框架移动**——哪条矢量 / 渗透进档、新开或被证伪，紧跟一句关系级判断（供给 vs 需求谁快、开源在替公司补哪块、中美错位怎么走）；地图没动就直说"证据积累日"。再点 S 级重点（→深拆）和 24-72h 最该盯的对象。**不再单设"今日全景速读"**。
- **② 今日重点 · 深度拆解（0-2 个，可整节省略）**：只放价值定级判为 **S 级** 的对象，每个一段深拆（是什么 → 方法论落点 → 产业位置 → 证据与反例 → 兑现路径），约 300-500 字。**这是 S 级对象全文唯一的详展处**——纵 / 横轴里对应条目只留档位 + 指针（→重点①）。今天没有 S 级就整节省略，不硬凑（结构见 template）。
- **③ 纵轴 · 能力与技术演进**：按"两轴综合"的纵轴定档组织，逐条矢量 list；每条把实验室证据 + 开源证据并在一处，写清档位、卡点、反例。模型 / 产品的能力动作只在这里展开（已进②深拆的只留指针）。
- **④ 横轴 · 渗透率**：横轴五追问，用表格（形态 × 档位适合对照）；没有新渗透就直说。降低渗透门槛的产品 / API / 定价动作落这里（已进②深拆的只留指针）。
- **⑤ 原始证据附录**：把双引擎当天捞到的原始 feed 压成一张精简表——对象 / 来源 / 热度 / 一句定性 / 落点。已在 ②③④ 展开的只写指针（→重点① / →纵轴矢量X / →横轴形态Y），**不重述**；没进两轴的（纯大盘背景、还在观察）给一句定性。融资 & 政策另起"资本与政策"短 list。
- **⑥ 横向速记 & 降噪**：横向速记 3-5 条只写关系（供需对没对上 / 开源 vs 公司 / 中美错位）；降噪 list **只写今天的具体对象** + 降级理由，通用告诫（star ≠ 采用等）是 methodology 常量、不每天重抄。
- **⑦ 待跟踪 & 本期变更**：待跟踪三栏是本期 watchboard 投影（待印证矢量=`agent_eng_vectors`、待观察渗透=`product_forms`、待发布 / 验证=`watch_companies`+`watch_projects`）；本期变更只用 `T-编号` 引用，渲染约定见 `../watchboard.md`。S 级重点开的跟踪项在这里跟着结算，把当初的价值判断兑现或证伪。

### 冷启动

首次无上一期时，按当日两轴结果直接构造第一份 watchboard；若上一期还是旧的 `hot_themes` 字段，把那些方向迁移进 `agent_eng_vectors` / `product_forms`。
