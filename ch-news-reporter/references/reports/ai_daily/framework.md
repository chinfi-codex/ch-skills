## 模型区 — 本框架的领域判定逻辑与写作要点

### 两条坐标轴（报告主干）

当前 AI 产品的主形态是 **AI agents**。本日报把每天的多信源新闻，落到一个二维坐标系里——

1. **纵轴 · 能力与技术演进（供给 / 能力侧，键 `agent_eng_vectors`）**：模型和产品的能力、技术今天往哪走了？两路证据并到同一条"矢量"上看——前沿实验室（OpenAI / Anthropic / Google 等）发了什么模型、加了什么能力（读成"解锁了哪类 agent 行为"）；开源项目在解哪个"把 agent 做出来"的工程痛点。同一条方向当天有多个证据一起推 = 这条在**收敛**。
2. **横轴 · 渗透率（需求 / 采用侧，键 `product_forms`）**：AI 产品今天有没有让更多人、更多场景真用上？看新载体 / 新用户段 / 新自主度 / 新分发入口，以及最关键的**真实使用信号**（不是 star / votes）。没有就直说"今日无新渗透信号"，不硬凑。

**两轴就是主干，不是十节里的两节。** 证据用两个引擎（见下）捞齐后，**直接并进它唯一的正文位置**——能力 / 技术的归纵轴，谁能用上 / 用得更多的归横轴，融资 / 并购 / 监管等归资本与政策；不再单列"新项目雷达 / 公司矩阵 / 原始证据附录"把同一批对象重抄一遍。与这些板块都无关的低价值背景项只在后台保留；确实影响当天行业判断的例外，可在结论末尾用一句话写清并就地附原文链接。

### frame 字段填写约定

- **`agent_eng_vectors`（纵轴）**：每条 `{id, vector, stage: 实验→收敛中→事实标准, open_pain（当前卡在哪）, side: lab|oss|both}`。至少 1 条。
- **`product_forms`（横轴）**：每条 `{id, form, segment: 开发者|专业用户|大众|企业, penetration_stage: 萌芽→早期采用→主流化, usage_signal（真实使用证据，非 star/votes）}`。
- **canonical id 是跨天结算的锚（务必守）**：每条矢量 / 形态开一个稳定 id——语义短 slug 即可（矢量 `v-长任务可靠性` / `v-推理成本`，形态 `f-企业知识工作`），或 `v-001` / `f-001` 也行。**id 一旦开就不改，显示名（vector / form 文案）随行情随便改**。收敛判定"同一矢量当天 ≥2 证据"、跨天"这条昨天到哪档、今天进没进档"全靠 id 认人；名字换了 id 不换，才接得上。历史教训：一个月里"长任务可靠性"这条矢量换了 ≥5 个显示名（"长任务与 coding agent harness"→"长任务可靠性与自我纠错"→"长任务可靠性/企业级 agent"…），跨天结算直接断线。碰到旧 watchboard 没 id，就现补一版 id 并沿用。
- **`watch_companies`**：预期近期有动作的重点公司。**`watch_projects`**：标了"值得继续观察"的开源项目/产品，带 id 进台账，等热度兑现成趋势再结算。
- **HTML 双轴图要用的四个选填字段（填了图才有信息量，不填不报错）**：网页版会把两轴画成一张坐标图，坐标 = **档位整数 + 档内完成度小数**。完成度不是新标准，就是本框架已有的判据结构化一次：
  - 矢量加 `graduation: {multi_impl, third_party, pain_cleared}` 三个布尔——即"毕业三条"。判档时你本来就要过一遍，顺手记下来；三条全 true 却还写着"收敛中"，图上会顶在格子天花板，等于自查。
  - 形态加 `five_asks: {carrier, segment, autonomy, real_usage, distribution}` 五个布尔——即横轴五追问，`real_usage` 只认真实使用信号。
  - 两边各加 `links`（对面的 canonical id 列表）：某条矢量在喂哪个产品形态、某个形态靠哪条矢量撑着。**没挂钩就别写**——图上会落到"未挂钩"带，那本身就是一条判断（有人在做技术，还没有产品接得住）。
  - 顶层 `axis_objects` 记当天进正文的对象落点：`{name, grade, vector_id, form_id, note}`，grade 用 `s_confirmed / s_candidate / a / b`。S 级也可以只在 `grading_audit` 里加 `axis_hit: {vector_id, form_id}`，渲染器两处都读、按 name 去重。B 级可以不记。
- **台账预算与母题（防膨胀，务必守）**：open 跟踪项软上限 `open_budget=10`（见 `config/report_profiles.yaml`）。超预算时**先把同一条矢量下的多条细证据归并进一个母题（`sub_items`），别在顶层平铺**——母题占 1 个名额、子线各留独立到期时钟与 status（机制见 `../watchboard.md §4`）。归并后仍超，就把连续 3 期无实质进展的项转 `expired` 或直接结算掉。**别靠加预算解决膨胀**：持续平铺 16-18 条 open、且 `sub_items` 一个都没用，就是该精简的信号（对照地缘日报靠母题把顶层压到 9 条）。

### 第一性原理：为什么用双引擎

AI 行业的边际信息在两个源头交替出现，单看都不够：公司只看不开源会丢早期信号（Agent/MCP/Coding Agent 的前沿常先在 Show HN 和 GH Trending 跑出来）；只看开源不看公司会丢规模化判断（真正决定能不能用、能不能赚钱的还是大厂 API、定价、产品入口）。所以先各自捞齐证据，再收敛到两条坐标轴。

### 引擎 A · 新项目发现（GitHub Trending + Product Hunt + Show HN）四步

1. **项目特征定性**：归入统一标签——基础模型与权重 / Agent 框架与编排 / 开发者工具链 / 推理与部署 / 数据与 RAG / 应用产品 / 评测与基准 / 开源基础设施。
2. **解决的 agent 工程痛点画像**：一句话回答"真实需求、给谁用"；agent 项目落到具体痛点（编排 / 记忆与上下文 / 工具标准化 MCP / 可观测 / 沙箱与运行时 / eval / 成本可靠性）。非 agent 项目登记但标"大盘背景"。
3. **热度真伪辨别**：star / votes / comments 只代表注意力。看 GH 的 stars/day、release、license、pricing、issues、push 活跃；看 PH 是否有 pricing/docs/API/enterprise 入口、是否 AI 原生；看 Show HN 回帖是积极采用还是技术质疑。
4. **趋势聚类**：同类项目当天 ≥ 2 个才单列一条方向信号，**单点不写趋势**。

### 引擎 B · 重点公司动作

完整公司清单与别名见 `config/report_profiles.yaml` 的 `company_groups`（国际：OpenAI/Anthropic/Google/Meta/Mistral/NVIDIA/HuggingFace；中国：Kimi/智谱/Minimax/腾讯/阿里/字节/DeepSeek/百度）。

把当日公司动作按四类识别：① 模型发布（基础 / 推理 / 多模态 / 专用 / 开源权重 / 版本号）；② 产品更新（C 端 App、Agent 平台、IDE 插件、企业版）；③ API & 定价（新端点、企业入口、token 定价、免费额度）；④ 融资 & 政策（融资、并购、合作、监管、人事）。①②③ 里属"能力 / 技术"的并进纵轴、属"降低渗透门槛 / 扩用户"的并进横轴；④ 融资 & 政策不进两轴，落到独立但精简的「资本与政策」板块。

**三个分析维度**：每个动作先过 agent 透镜（解锁了哪类 agent 能力 / 是否降低渗透门槛，分别归纵轴 / 横轴）；模型 vs 产品分开（别把加个按钮当模型升级）；中美阵营对照（同一窗口内是呼应还是错位）；商业化层级（研究→权重→API→产品→企业→生态，今天在哪层）。

### 两轴综合（证据写完后必做）

- **纵轴定档**：每条矢量给档位（实验→收敛中→事实标准），判档看证据强度不看热度；**收敛判定**：同一矢量当天 ≥ 2 个独立证据（理想一个实验室 + 一个开源）攻同一痛点 → 进 `agent_eng_vectors`，写清 `open_pain`。
  - **三档判据锚点（别让"事实标准候选"变成滞留区）**：
    - `实验`：单点证据、某家在试，痛点还很明显。
    - `收敛中`：同一痛点 ≥2 独立证据在攻，方向明确，但还在换方案 / 卡点未解。
    - `事实标准`：**毕业要三条同时满足**——① ≥2 个独立实现（含至少一个开源）收敛到同一套做法；② 有第三方独立复现 / 采用（不是自评、不是刷榜）；③ 这条矢量**不再冒新工程痛点**（`open_pain` 实质清空）。缺任一条，最多停在收敛中。
  - **"事实标准候选"是收敛中的高位子态、不是独立一档**：只在"三条判据满足 2 条、就差一个独立复现 / 采用"时才用，且**必须写明差哪一条、什么事件会补上**。一条矢量在"候选"挂过 3 期还没补齐那一条 → 退回"收敛中"（承认它其实没那么近），别让它长期挂着"就快毕业"的名头空转。历史教训：多条矢量在"候选"挂了一周以上、无一真正毕业到事实标准，顶档形同虚设。
- **横轴五追问**：载体 / 入口、用户段、自主度（copilot→有监督→后台自治）、渗透信号 vs 注意力信号（只有真实使用进 `usage_signal`）、分发入口。每条给渗透档位（萌芽→早期采用→主流化）。**今天没有新渗透变化就如实写"今日无新渗透信号"，绝不硬凑**。
- **横向对照（后台分析，不单独展示）**：供给↔需求是否对得上、开源↔公司谁填了谁的空、中美各自集中 / 空缺在哪条矢量或形态。它用于校验结论；当天最关键的一条关系可收进「一句话结论」，不再生成独立章节。

> 参考矢量库（从当日证据自然聚类，别硬套）：长任务可靠性 / 工具标准化(MCP) / 多智能体编排 / 记忆与上下文 / computer use / 推理成本与小模型 / agent eval / 沙箱与运行时。

> **边界观察（治理层 early-warning，别当日常矢量硬推）**：`模型自改进 / RSI` 与 `具身智能 / 机器人 agent` 踩在"agent 软件为主形态"的框架边界上。当前仍按普通矢量登记就好，但如果它们连续多日聚集证据、开始重新定义"什么算 agent"，那就是 regime 可能向"具身 / 自改进"扩展的信号——属于 `framework_state` 治理层的换代评估（见 `framework_governance.md` 与 invalidation_triggers 第一条），不是往双轴里硬塞。已登记为 framework_state 挑战 **AC-004**，慢思考层跟踪。

### 价值定级（两轴归类后必做，先找候选、再确认重点）

两轴综合只回答对象落在哪个方向，价值定级回答它有多重。定级分两步：先判断是否值得进入 **S-candidate / A+ 重点候选**，候选拿到深挖资源后，再判断能否升级为 **S-confirmed 今日重点**。这层不能倒过来：缺官方页、尚未开放或缺独立复核会阻止“确认 S”，但不能阻止一个结构上重要的对象进入候选并接受补证，否则会落入“证据不足所以不深挖、不深挖所以一直证据不足”的循环。

写作前先按实体 / 事件聚类：同一个模型或产品在 Product Hunt、RSS、HN、GitHub、金十出现多次时合成一个对象再定级。来源条数不等于独立证据数；共同转述同一篇 PR 的多个页面只算一条证据链。

**四档锚点：**

- **S-confirmed · 今日重点**：通过下方确认门槛，进入深度拆解。
- **S-candidate / A+ · 重点候选**：结构重要性可能达到 S，但一手证据、真实可用性或独立复核仍有缺口；必须深挖并在成品明示，不能静默降成普通 A。
- **A · 轴内详展**：明确落在某条轴、值得写清，但没有改变格局的分量。
- **B · 对应板块一句话**：与两轴或资本 / 政策有关、但不值得展开；与当前框架无关的背景项只留在后台。

**S-candidate 触发（满足任一结构条件，且未命中“候选排除项”）：**

1. 重点厂商出现旗舰级新一代基础模型、新产品线，或重大定价 / 许可 / 开放权重重构；即使首发证据尚未齐，也必须进入候选复审。
2. 单一事件可能同时改变至少两个 frame 维度（能力、成本、开放性、部署门槛、基础设施依赖、产品渗透），而且每个维度至少已有一条可核查事实；不能把同一句 PR 文案换两个标签凑数。
3. 同一对象跨至少三个来源族出现，其中至少两个来源族提供非重复的实质信息（如官方规格、第三方技术评测、可调用 API、可下载权重、开发者实测、独立定价对比），并触及至少一个结构性维度。
4. watchboard 关键节点到期只负责**触发复查**；必须同时满足 1-3 中至少一条，日期到期本身不能制造候选。

**候选排除项（命中就不进 S-candidate）：**

- 只有 star / votes / score / 单项跑分等注意力信号，没有结构影响；
- 多个页面只是重复转述同一篇 PR，没有新增规格、可用性或验证证据；
- 只有发布会 demo、概念视频或无产品对象的口号，连“可能改变哪一维”都说不清；
- 仅因 watchboard 日期到期出现重复提醒，当天没有实质新证据。

**S-confirmed 升级门槛（四项必须同时满足）：**

1. **结构影响成立**：让纵轴矢量进档 / 新开、让横轴形态跨档 / 新开，或旗舰动作同时实质推动至少两个 frame 维度。
2. **一手证据成立**：至少一个官方公告、发布博客、model card、API / 定价文档或开源权重页。
3. **真实可用成立**：权重可下载、API 可调用或产品入口已开放，不是 waitlist、demo 或仅预告未来日期。
4. **独立复核成立**：至少一个第三方技术评测、benchmark / 定价 / 可用性验证，或社区可复现的开源运行证据。首发日若尚无独立 benchmark，保持 S-candidate，并把 24-72h 补证节点写清，不为赶首发降低确认门槛。

**候选与重点纪律：** 先把达到结构门槛的对象排序，只有排序前 2 个进入 S-candidate；S-confirmed 也包含在这 2 个候选预算里。超出预算的对象按 A 级处理，不额外写入 `grading_audit`，避免突破 `candidate_budget` 硬门禁；入选对象的 `rationale` 必须说明它为什么优先于其他潜在候选。S-candidate 与 S-confirmed 都触发深挖 enrichment；候选若已明确因某类证据不可得而无法确认，可提前结束深挖，但必须记录缺口。S-confirmed 进入「今日重点·深度拆解」；未确认的 S-candidate 进入「重点候选·待验证」，两者都不得重复在两轴正文详展。

**定级审计（写入 watchboard 顶层 `grading_audit`，不把后台表整张抄进成品）：** 每个进入候选评审的对象必须记录稳定 `entity_id`、触发条件、候选排除项检查、已有证据、确认阻断项、证据缺口、深挖状态 / URL、初始与最终级别、最终理由。当天无候选也要写 `grading_audit: []`，把“确实审过但没有候选”和“忘了做定级”区分开。

### 各输出板块写作要点（新结构，报头之后约 6-7 块）

每条证据全文只详展一次（硬约束见 template 顶部"去重铁律"）。口吻日常化——像给懂行的朋友发消息讲今天的事：主语是公司 / 项目 / 人，判断词用日常说法，矢量名和档位词只在定档处出现、周围解释全用大白话，档位和判断照样要准；同维度多条目一律 list，每条说完整通顺的话，别退化成"字段A - 字段B"横杠拼接（完整常量见 `methodology.md` 文风常量）。

横向对照和降噪继续在写作前完成，但它们是后台判断，不是读者章节：关系判断只在确实影响当天结论时写进「一句话结论」；被降级但仍值得登记的对象在对应正文板块留一句，低价值背景项只在后台保留，不再展示单独的「横向速记」或「降噪」清单。

证据不再集中到附录。每个对象都在全文唯一展开的位置就地附一行证据元信息：`来源｜热度 / 体量（有则写，没有不硬造）｜[查看原文](URL)`。S-confirmed 放在深度拆解，S-candidate 放在重点候选，A / B 放在对应纵轴、横轴或资本与政策板块；同一对象不要在多个板块重复这行证据。每个展示对象至少要有一个有效的绝对 HTTP(S) 原文链接；packet 没给链接时先通过 enrichment 或官方页面补查，仍找不到就不要把该对象写进成品，严禁编造 URL。

- **① 一句话结论（唯一速读层）**：3-4 句，站在框架高度写"认知地图今天动没动"，不是新闻摘要。第一句必须是**框架移动**——哪条矢量 / 渗透进档、新开或被证伪，紧跟一句关系级判断（供给 vs 需求谁快、开源在替公司补哪块、中美错位怎么走）；地图没动就直说"证据积累日"。再点 S-confirmed（→深拆）或 S-candidate（→待验证）以及 24-72h 最该盯的对象。**不再单设"今日全景速读"**。
- **② 今日重点 · 深度拆解（0-2 个，可整节省略）**：只放价值定级判为 **S-confirmed** 的对象，每个一段深拆（是什么 → 方法论落点 → 产业位置 → 证据与反例 → 兑现路径），约 300-500 字。**这是已确认重点全文唯一的详展处**——来源、热度 / 体量和原文链接也只附在这里；纵 / 横轴里对应条目只留档位 + 指针（→重点①）。今天没有 S-confirmed 就整节省略，不把候选硬写成重点（结构见 template）。
- **③ 重点候选 · 待验证（0-2 个，可整节省略）**：只放深挖后仍为 **S-candidate / A+** 的对象，短写“为什么重要 → 被什么阻断 → 下一步验证什么”，并附已有的一手 / 第三方入口。它不是第二个深拆区；纵 / 横轴只留指针（→候选①），24-72h 节点写进 watchboard。
- **④ 纵轴 · 能力与技术演进**：按"两轴综合"的纵轴定档组织，逐条矢量 list；每条把实验室证据 + 开源证据并在一处，写清档位、卡点、反例，并在各个具体证据下方就地附来源、热度 / 体量和原文链接。模型 / 产品的能力动作只在这里展开（已进②深拆或③候选的只留指针，不重复证据元信息）。
- **⑤ 横轴 · 渗透率**：横轴五追问；没有新渗透就直说。降低渗透门槛的产品 / API / 定价动作落这里，每个形态 / 产品写完判断后就地附来源、热度 / 体量和原文链接（已进②深拆或③候选的只留指针）。
- **⑥ 资本与政策（可整节省略）**：融资、并购、合作、监管、人事等不硬塞进两轴，按重要性写成短 list；每条就地附来源、金额 / 规模等体量信息和原文链接。当天没有就省略整节。
- **⑦ 待跟踪 & 本期变更**：待跟踪三栏是本期 watchboard 投影（待印证矢量=`agent_eng_vectors`、待观察渗透=`product_forms`、待发布 / 验证=`watch_companies`+`watch_projects`）；本期变更只用 `T-编号` 引用，渲染约定见 `../watchboard.md`。候选 / 重点开的跟踪项在这里跟着结算，把当初的价值判断兑现或证伪。
