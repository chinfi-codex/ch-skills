# AI 日报方法论

## 目标

把当天多信源中的 AI 新闻、开源项目、产品发布和社区讨论转化为可追溯的日报判断。日报不是新闻列表，而是帮助读者判断：今天有哪些新对象值得看、哪些信号可能持续、哪些只是短期热度。

## 分析框架

1. 先分层：基础模型与算力、Agent 与工作流、开发者工具、应用产品、企业软件、开源基础设施、投融资与政策。
2. 再定性：确认事实、社区热度、产品采用线索、商业化线索、产业风险分别标注，不把它们混成一个结论。
3. 看交叉验证：同一对象若同时出现在 GitHub Trending、Product Hunt、Hacker News、RSS 或快讯中，优先作为重点观察对象。
4. 看可持续性：开源 star、PH votes、HN score 只能说明注意力；README、官网、文档、pricing、API、企业入口、release 活跃度才帮助判断是否可能沉淀为产品或产业信号。
5. 看反例：说明信息缺口，如项目刚发布、README 夸张但无 release、官网只有 waitlist、社区争议多于采用证据。

## 输出判断边界

- 可以说“值得进入后续观察”“可能代表某类需求升温”。
- 不直接说“必然成功”“会替代某产品”“确定商业化”。
- 涉及上市公司或资产价格时，只写影响路径与观察点，不给交易指令。
