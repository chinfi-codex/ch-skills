# 自定义关注主题方法论(通用分析底线)

> 适用于所有 `custom_<slug>` 关注主题日报,与具体领域无关。
> watchboard 滚动机制(每日闭环、结算铁律、台账规模控制)见 `../watchboard.md`;
> 本文件只写跨主题不变的分析常量。单个主题的判断锚点 = `config/custom_topics.yaml`
> 里该主题的 `focus` 自然语言描述——不为单主题另建 framework(D5)。

## 目标

把多通道证据(新闻库 / 实时检索 / Vault 笔记 / 结构化数据)整理成**一份**合并的
自定义主题日报:`config/custom_topics.yaml` 里注册的每个关注事项在报告里占一个
板块,写清今天这个事项有没有增量、增量改变了什么判断、接下来 24-72h 盯什么。
脚本只负责取数、去重、落库、打包;哪些证据重要、算不算边际变化、判断怎么更新,
全由 Agent 基于各事项 focus 完成。

本日报不提供交易建议,不把单源消息当结论,不在无增量的事项上硬凑内容。

## 必读 references

1. 本文件(方法论常量)。
2. `../watchboard.md`:活动状态机制;上一期 open 跟踪项今天必须逐条结算。
3. `template.md`:输出骨架(含"无增量短报"形态)。
4. `config/custom_topics.yaml` 中该主题的 `focus`:今天的判断锚点。

## 证据分层

每条证据进报告前先归层,写法不同:

1. **确认事实**:多源一致或官方口径、时间可追溯。可以写进结论。
2. **信号**:价格、订单、产能、人事、融资、供应链动作等可观察变化。单源也可登记,
   但必须标可信度,措辞留余地。
3. **推断**:基于证据链的判断。必须写明不确定性和可能反例,不许伪装成事实。

传闻、匿名源、社媒截图、二手转述一律降级:只能作线索登记,不作结论依据,
并在文中显式标注"未经证实"。

## 通道证据特性(读证据包时按通道调权重)

证据包的 `channels` 段按通道组织,每个通道的证据性质不同:

- **news_db**(库内已采集新闻):已过采集去重,时效以 `date_key` 为准,窗口由
  `time_window_days` 控制。是主题的常规信息流。
- **web_search**(当日实时检索):每条带 `query` 与 `retrieved_at`,可回指到具体
  检索动作。Tavily 返回的 content 是二手压缩摘要,关键数字、引语、表态在下定论前
  最好回到 url 原文核对。与 news_db 重复出现 = 跨通道互证,可信度上调;只在一侧
  出现不自动等于可疑。
- **alpha_vault**(本地知识库笔记):是历史认知与既有判断,**不是新证据**。用途是
  对照"我们之前怎么想的":笔记里的待验证问题是否被今天的证据回答、既有判断是否
  需要修正。注意 mtime,陈旧笔记只作背景,不作当日增量。
- **pg_data**(结构化数据):行情 / 主线 / 跟踪表等硬数据,是校验锚。新闻说法与
  数据不一致时以数据为准,并在报告里指出矛盾。
- **coverage**:某通道降级、跳过或失败时,相关判断整体降一档。**不设覆盖说明段**——
  就地在被影响的那条判断旁边写明哪个通道缺了、判断因此弱到什么程度;通道都正常时
  什么都不写。不能用"其他通道有内容"掩盖关键通道缺失。

## 边际变化判定

写进「今日边际变化」的,必须改变判断或改变跟踪状态。满足任一即可:

1. **事实新增**:出现此前未确认的出货、订单、产能、表态、数据或节点事件。
2. **量级或时间表变化**:数量、节奏、指引、节点日期被上修 / 下修 / 推迟 / 提前。
3. **证伪或确认**:上一期 open 跟踪项被今天的证据兑现或推翻。
4. **新不确定性**:出现需要新开跟踪项的变量(新的供给瓶颈、新的政策风险等)。

不算边际变化:旧闻重转、无新事实的评论文章、与主题 focus 无关的同公司新闻、
单纯情绪性标题。这些留在后台,不进正文。

## 无增量事项与无增量日

- **单个事项无增量**:板块压到 100 字内——一句话"今日无增量,判断沿用上一期"
  + 仍有效的观察点。不把旧闻重新包装成新闻,不为篇幅复述背景。
- **全部事项无增量**:整份日报出短报形态(一句话结论 + 各事项一行现状 + 仍有效的
  观察点),不超过 500 字。
- 某事项连续多个无增量日,考虑在它的 watchboard 里收紧 `expires_after`、了断陈旧
  跟踪项,或把该事项改为 `status: paused`——别把日报写成复读机。

## 判断与跟踪纪律

- 先读各事项证据包里的 `Prior Watchboard`:每个事项上一期的 open 跟踪项今天必须
  逐个结算(确认 / 证伪 / 顺延 / 过期),一条不许漏;无上一期按该事项 focus 冷启动
  建立第一份 watchboard。**结算只落在 watchboard,合并日报里不设「跟踪项」段**;
  结算结果如果就是今天的边际变化,写进该事项的「边际变化」。
- 当前判断用今天的证据现判,不照搬昨天结论;「判断更新」段要写清哪条证据
  推动了哪部分判断。
- `falsifiers` 必填:每个事项的 watchboard 都要写下什么证据会推翻今天的判断,
  给明天留反向通道。
- 回写按事项逐个进行:`save_report_state.py --profile custom_<slug>`;
  结构校验的规则见 `../watchboard.md`(frame 自由结构,通用骨架必填)。
  跨天状态按事项各自滚动,合并日报只是展示层。

## 文风

文风讲人话,减少机械与僵硬:像跟懂行的人当面把一件事讲清楚,句子通顺、有因果。
同类信息(多条新闻、多个信号、多个观察点)用列表,一条一项,每条写完整句子,
不退化成"字段A - 字段B"式拼接;只有结构化对照才用表格。
长度:合并日报全篇 1500-2500 字;有增量事项板块 300-800 字;无增量事项板块
≤100 字;全部无增量时整份短报 ≤500 字。单主题深挖(按需)不受板块篇幅限制。
