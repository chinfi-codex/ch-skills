# space_daily 分析框架 · v1 运力锚

> 本文件是 space_daily **分析框架的唯一可信源**。框架契约——frame 维度、regime 失效触发器、输出板块、四条主线判定与国内/海外分工——都收敛在这里。
> 跨框架不变的方法论常量（证据分层、估值口径、简报纪律、文风）见同目录 `methodology.md`；状态机制见 `../watchboard.md`。
> **变更框架只改这一个文件。** 当 regime 质变（如运力过剩、资本窗口关闭、政策成为硬约束）时，由慢思考层生成新版本框架整体替换，经人确认后切换。

```yaml
# regime 失效触发器：慢思考层检测命中即评估"框架换代"
invalidation_triggers:
  - 运力由稀缺转为过剩（发射供给超过星座部署需求，价格战成为主旋律）→ 主线权重重排，运力锚降级
  - 资本窗口关闭（一级融资连续数月冻结或 IPO 通道实质关闭）→ 融资主线降权，订单兑现与交付能力升为主驱动

```

## 模型区 — 本框架的领域判定逻辑与写作要点

### 范式与第一性原理

把当日多信源落进一条产业进度链：

```
运力与产能 → 星座部署节奏 → 订单与收入兑现 → 资本定价 → 下一轮产能投入
```

当前范式下**运力是最稀缺的一环**：星座组网的时间表被频轨期限锁死，而发射工位、火箭产能、复用周转都跟不上，所以谁先拿到运力、谁先把复用跑通，谁就在下一轮批量发射合同里多一张牌。因此判一条新闻值不值得写，最终都回到一句：**它改变了这条链上哪个环节的稀缺程度，以及谁的相对位置因此移动了。**

脚本只负责取数与过滤（RSS 按 `category: space` 取、金十按 `item_keywords` 取、按 `item_exclude_keywords` 剥噪音）；主线归类、位置判断、是否构成增量由 Agent 判断。

### frame 字段填写约定

- **`swing_factor`**：当下产业主驱动维度（运力供给 / 需求订单 / 资本供给 / 政策与频轨），今天最值得盯的那一维。
- **`capacity_trend`**：运力供给边际方向。发射工位投产、复用周转缩短、新型号首飞 = 边际宽松；发射失利、工位排期积压、型号推迟 = 边际收紧。
- **`capital_tone`**：一级市场融资温度。看当天融资笔数与金额，以及 IPO 节点推进情况，不看单笔大额。
- **`domestic_frontier`**：国内四条主线中今天最活跃的一到两条，写主线名。用于跨天看哪条线在升温。
- **`imminent_nodes`**：临近的首发窗口、问询回复期限、募资交割时点，带日期，作为跟踪项进台账。

### 四条主线判定

每条事件必须归进下面四条之一，归不进的说明它不该进这份报告：

1. **发射与运力**：入轨成功/失败、年度发射节奏、可重复使用的复用次数与周转天数、单公斤入轨成本、发射工位与发射场产能、新型号首飞与定型进度。
2. **卫星与载荷**：星座在轨数量与组网进度、卫星批产线产能与交付节奏、载荷能力代际（相控阵、激光星间链路、直连手机、遥感分辨率与重访）、频轨资源期限压力。
3. **订单披露**：政府与军方合同（NASA、太空军、欧空局、国内政府采购与军方）的中标方、金额、周期与交付节点，发射服务与星座采购合同，卫星与载荷批量订单，上市公司公告口径的合同金额，以及订单转收入的兑现进度（签了多少、确认了多少）。
4. **产业融资**：一级市场融资轮次、金额与估值（标明口径），并购与战略投资，IPO 全流程节点（辅导备案/受理/问询/递表/注册/发行），老股转让与股权变动，地方与国家级产业基金出资，上市公司定增募投中投向航天业务的部分。

### 国内在前、海外在后

**国内按四条主线分节，顺序固定不要调换：发射与运力 / 卫星与载荷 / 订单披露 / 产业融资。** 订单排在融资前面——订单是已经发生的需求，融资是对未来需求的下注，先看谁真的拿到了钱，再看谁在筹钱。

**国内同行的具体动作门槛更低**：协议签订、活动组织与出席、火箭进场与转运、总装测试与出厂评审、试车与静力试验、发射与回收、工位与产线投产、重要人事与股权变动，这些即使单条看信息量不大也要写进去——对同行相对位置的判断就是靠它们一条条累积的。归不进四条主线的（典型如活动组织、人事变动），挂在该公司当天的段落里一并说清，不单开小节。

**海外全部合并成一节，不分主线**，按重要性排。判断要不要写，看是否满足三条之一：改变全球运力与价格基准（星舰进度、猎鹰复用节奏、星链组网与降价）；直接牵动国内主体（频轨资源竞争、出口管制与制裁、国际发射订单流向）；给国内提供可比锚（海外同类公司的估值、融资规模、订单体量）。三条都不沾的纯海外本地新闻不写。篇幅上这一节不超过国内部分的三分之一；国内与海外的对比放在这里做，不要在国内小节里穿插海外参照。

### 各输出板块写作要点

- **一句话结论**：3-5 条，每条一句话、一条一件事。写判断不写摘要——"谁的什么变了，把谁的位置推到了哪儿"，而不是"某公司发布了某消息"。国内的判断排在前面。
- **订单披露**：写清四件事——中标方是谁、合同金额多少（含税口径要标）、交付周期到什么时候、这笔订单在对方手里是新增还是替换。上市公司公告口径的合同额与实际确认收入常常差很远，两个数都拿得到时并列写出来，只拿到一个数时说明是哪一个。
- **产业融资**：按"轮次 → 金额 → 投后估值（标口径）→ 领投方 → 资金用途"把一轮说完整，拿不到的字段明写未披露。IPO 节点说清走到哪一步。
- **融资与 IPO 进度变化表**放在「产业融资」节末尾，只在当天有轮次、估值、受理/问询/递表状态变化时才出，列：公司 / 板块 / 状态 / 本轮变化 / 估值口径。没有变化就整块省掉。
- 前瞻节点（下次发射窗口、问询回复期限、募资交割时点）如果对判断实质重要，写进对应主线的正文里当事实的一部分，**不要**另立"观察点"小节。

### 重点主体

**国外**：NASA、SpaceX（Starship / Falcon / Starlink）、Blue Origin、Rocket Lab、ULA、Arianespace 与 ESA、Amazon Kuiper、AST SpaceMobile、Planet、Firefly、Stoke、Relativity，以及 ISRO / JAXA / Roscosmos 等国家机构。

**国内**：航天科技集团与航天科工（含运载火箭技术研究院、空间技术研究院、上海航天技术研究院、航天推进技术研究院等院所）、中科院微小卫星创新研究院、中国星网与垣信（千帆星座），以及蓝箭航天、天兵科技、星际荣耀、星河动力、中科宇航、东方空间、深蓝航天、银河航天、长光卫星、微纳星空、国星宇航等民营公司。完整公司名单与别名见 `config/report_profiles.yaml` 的 `space_daily.item_keywords`。

**一个易错点**：SpaceX 已与 xAI 合并并上市（SPCX.O），同名新闻里有大量 Grok、AI 编程、持仓披露的内容。`item_exclude_keywords` 会剥掉大部分，但挡不干净——只有涉及航天业务（发射、星链、星舰、订单、产能）的才算本主题增量，AI 侧进展归 `ai_daily`；13F/估值类消息只在能推断 SpaceX 航天业务估值与融资能力时才写。

**另一个易错点**：星际荣耀的公司全名是"星际荣耀航天科技集团股份有限公司"，会连带命中"航天科技集团"（CASC）这个词。两个词同时出现在一条新闻里时按民营公司算。

### 台账维护（规模与归并）

`open_budget: 6`，四条主线各留 1-2 条 open 跟踪项——订单与融资两条通常最活跃。超预算时先把同公司的细项归并进母题、或了断陈旧项，不要靠加预算解决膨胀。

`falsifiers` 必填：每条跟踪项都要写下什么证据会推翻今天的判断，给明天留反向通道。

### 冷启动

无上一期 watchboard 时（首份报告或状态被清），按下面的种子构造第一份：

- `swing_factor`：取当天证据里信息量最大的那条主线对应的维度。
- `capacity_trend` / `capital_tone`：当天证据不足时填"中性"，不要硬猜方向。
- `domestic_frontier`：填当天有增量的主线，一条都没有就填空列表。
- `imminent_nodes`：从当天正文里提出带日期的前瞻节点；提不出就空着。
