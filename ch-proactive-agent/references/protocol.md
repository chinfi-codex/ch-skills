# 主动目标协议

> 本协议归 `ch-proactive-agent` 项目所有，2026-10-29 迁自 AlphaVault `system/frameworks/27-主动目标协议.md`。
> 长期目标定义见 `config/goals.yaml`，频控默认值见 `config/policy.yaml`，数据源登记见 `config/sources.yaml`。
> AlphaVault 是只读数据源；本项目的协议、代码、契约、状态都不放在金库里。

## 目标与边界

本协议定义第七类任务：**主动目标（proactive_goal）**。当前长期目标是：

> 持续对照用户已有的交易与基本面方法论，识别需要复核的交易决策、目标仓位变化、基本面边际变化、产业拐点和证伪条件。达到证据门槛时向用户发送提醒；没有增量时保持安静。

数据根目录为 `config/goals.yaml` 的 `vault_root`（AlphaVault），运行态目录为 `runtime_home`（默认 `~/AlphaData/proactive`，本机磁盘）。目标长期存在，不以一次回复或报告作为完成条件；不使用 Hermes `/goal` 的完成型续跑。运行方式是**项目内目标与运行态 + Hermes 心跳 + 无工具评估 + 确定性投递**。

主动性来自“目标 − 现状”的可检查差距，不来自频繁说话。参考[《Personal Agent 落地思考：主动性从哪来，又卡在哪？》](https://mp.weixin.qq.com/s/c5k2iwYh1O1OLA8ULf5X_A)：目标必须显式，子任务单独授权，长期运行需要持续对齐。Agent 不自行猜测新的投资目标，不将“可能有兴趣”当作现行方法论。

### 不做什么

- 不自动交易、下单或代表用户调整真实仓位；裁量门、L4 最终执行和实际仓位仍由用户决定。
- 没有实际持仓/成交真相源时，只提醒“框架触发目标仓位或存量动作复核”，不生成账户级数量指令。
- 不修改交易方法论、经验法则、Wiki 正文、正式研究报告或催化事件判据。
- 不把快讯、模型记忆或旧报告包装成当前事实，不把候选信号直接说成市场拐点。
- 不把长任务 Skill 当作主动 Agent 的工具，不在缺数时自行发动日报、深度研究、股票池跟踪或全市场扫描。
- 不自行创建新的长期任务、修改调度或开通外部数据权限。

## 双段架构：无工具评估 + 确定性投递

```text
长任务 Skills 独立运行 → AlphaVault 文件 / PostgreSQL
            ↓ 水位变化 / Skill 收尾信号 / 固定窗口 / 延期到期 / 心跳
pulse（no-agent，06–09 点与 15–24 点每 15 分钟）：长任务收尾 / 水位 → 防抖、限流 → 确定性扫描 → 有候选才备批并触发评估
            ↓ hermes cron run
评估 Agent（零工具，gate 只交出备好的一批）→ 本地 JSON 决策，永不直接外发
            ↓
pulse：逐项校验 → 主题冷却 / 频控 → 投递 → 下一轮读 Hermes 执行记录对账回执
```

### 评估段

- Hermes 任务 `AlphaVault 主动评估`，`deliver=local`、`enabled_toolsets=[]`、`attach_to_session=false`。空列表同时禁止原生工具与 MCP 并入。
- 预检脚本是 `proactive_goal.py gate`：只交出 pulse 已备好的批次（`ready_batch.json`），一批只交一次，没有就 `wakeAgent=false`。gate 自己不扫描。
- 评估包只含当前候选、相关 R-XXX 的可执行部分、近 14 天已推送提醒（`recent_notifications`）和候选里出现的术语表（`glossary`）。模型没有终端、Skill 工具、联网、子代理、任务调度或文件编辑入口。
- 模型只输出一个 `{"decisions":[...]}` JSON 对象，逐项选择 `silent / defer / notify / needs_user`；提醒内容写在 `brief` 字段，标签、日期与版式由代码渲染。
- 评估任务按 pulse 触发运行；`17 6-8,15-23 * * *` 的定时只是兜底，触发失败时最迟一小时内交出已备好的批次。

### 投递段（pulse）

- Hermes 任务 `AlphaVault 主动提醒` 以 `no_agent` 运行 `proactive_goal.py pulse`，不调用模型。为降低功耗只在 `policy.yaml` 的 `pulse_windows`（默认 06:00–09:00、15:00–24:00）内每 `pulse_interval_minutes`（默认 15）分钟一次，安装器据此生成 cron；时段外的变化等下一个时段开始时统一处理。每次依次：回执对账 → 处理评估输出 → 信号检测与扫描 → 投递。
- `stdout` 为空即静默；只有校验通过且到期的通知意图才会成为 `stdout`，由 Hermes 投递。模型自行写的一段散文没有这条投递路径。
- 影子模式 `deliver=local`，正式提醒 `deliver=weixin`。`--enable-live` 只影响投递段，评估段永远 `local`。
- `failure_deliver=local`，基础设施错误不进入市场提醒通道。`attach_to_session` 只在正式微信投递开启，保留用户追问的上下文。

两个任务分别在整 15 分钟（pulse）和第 17 分钟（评估兜底）运行，不会同一秒抢状态锁；gate 等锁最多 20 秒。任务工作目录均为运行态目录，wrapper 从 Hermes 已同步的技能副本运行；解释器固定为已通过 `psycopg2`、`yaml`、`jsonschema` 预检的 Python 3.9+。

## 能力范围：数据复用，调用只限原子能力

### 长任务 Skill：只接数据，不直接调用

长任务 Skill 包含多阶段工作流、跨步骤模型判断、跨日状态、报告/台账产出或后续任务编排。主动 Agent 只读取其落在 AlphaVault 文件或 PostgreSQL 中的产物，**不直接调用该 Skill，也不借调用其中长流程入口绕过这一限制**。

首版包括 `a-stock-daily-market-sense`、`a-stock-pool-tracker`、`a-stock-analyzer`、`a-stock-earnings-forecast`、`a-stock-quarterly-report`、`ch-news-reporter`、`ch-ai-eng-tracker`、`ch-gpu-compute-monitor`、`ch-dc-credit-monitor`、`chstock-usmarket-report`、`us-ai-semi-earnings`。其他符合上述定义的报告型/跟踪型 Skill 同样处理。

这些 Skill 可以按各自原有流程独立运行；主动 Agent 不拥有它们的调度权。部署在 AlphaVault 之外的报告不是本目标的数据输入，必须先进入约定的数据范围。

### 原子能力：登记后方可调用

原子能力一次只做一件有界的事，输入输出明确，不嵌套模型、不进入长流程、不创建调度，默认只读且可重试。当前登记：

- AlphaVault `system/tools/trend_state.py`：按既有口径读取 PG 并输出趋势状态、计数器和规则武装读数。
- AlphaVault `system/tools/query_source_registry.py`：定向查询来源元数据，不全量读取来源登记表。
- 本项目 `scripts/proactive_goal.py`：扫描候选、查看状态、校验决策与通知意图。
- 本项目 `scripts/install_hermes.py`：仅用于安装/维护宿主任务，不属于评估期工具。

这些原子脚本由**预检和投递器**执行，不是给评估 Agent 的通用终端权限。长任务内部脚本若确有独立价值，须单独登记为原子工具，不等于放行所属长任务。`md-pushplus` 不参与提醒链路，避免双通道重复发送。

## 数据范围与证据门槛

主动目标只消费：

1. AlphaVault 内文件：方法论、Raw 证据、台账、跟踪事项、催化事件、计划与运行状态。
2. PostgreSQL：行情、主题状态、财报、股票池、新闻及已有跟踪状态。

所有 ch-skills 的数据产物都可作为候选来源，但不是所有 Skill 都是可调用工具。外部 Skill 的分析结论仍需回源；只有其数据进入上述两处后才可使用。

本目标不默认开放自由联网、其他项目目录或新的外部数据源。数据不足时记录 `missing_inputs` 并降级、延期或请求复核，不能编造。连接失败不是市场事件；过期数据不能冒充最新事实。Hermes 运行记录只用于运行时交接与投递审计，不是市场事实来源。

### 交易与仓位候选

复用 `交易系统总纲.md` 的 L1→L4、`仓位体系.md` 双轴、`买点体系.md` 和 R-001～R-019 正文的 `status / preconditions / action / 例外`。机器入口为 `trend_state.py`，不另造趋势或仓位判据。

重点差距包括趋势档位迁移、现行规则前置条件成立、集中轴与趋势轴冲突、领导股健康度变化，以及撤退/新开/升级条件需要复核。集中度轴、领导股和盘中承接仍需相应原证据，不能用宏观读数或首板池信号代替。首板 `pool-tracker` 只提供自身规则状态，不直接驱动核心 L1→L4。

### 基本面与拐点候选

复用 `个股词条框架.md`、`产业链图谱框架.md`、`供需平衡框架.md`、`10-摄取协议.md` 和 `催化事件台账协议.md`。候选必须能指向 Driver、价格、订单、产能、库存、交期、财报或正式 S/A 事件相对基准的上修、下修或证伪。

正式 S/A 事件仍需检查原始来源、日期、证据缺口和反向链条。`record_only`、未校准告警、模型台账及估值假设变化只产生相应级别的复核线索，不能直接升级为交易或基本面结论。本协议不补造一套通用的“基本面分型 → 仓位”映射。

### 框架复核候选

监听方法论新增、修改和删除、跟踪事项的证伪条件和既有框架复核期限。框架变化后重新核对目标是否仍与用户意图一致；需要改变目标时先问用户，不能沿旧目标继续推进。

AI 供需 `board.json` 超过其 30 天体检期限时，只产生**框架体检提醒**，不把旧 `stance` 当成当前产业结论。正式体检仍按 `供需平衡框架.md` 人工发起、留痕；收到提醒不等于完成体检。

## 增量读取与存量对比

扫描只负责两件事：给出**本轮增量**，再附一份**精简存量索引**。是否对比、对照哪一版、看哪个维度，由评估者判断，脚本不预先下结论。

- **增量**：催化事件按语义版本与状态比对，只把新事件和实质变化的事件送入候选；未变化的 300+ 条历史事件不重复呈现。趋势读数以参考交易日为键，同一参考日不重复调用。
- **存量索引**：候选附带上一版的字段级差异（`prior_version.changes`，只读该候选自己的旧包）和同产业最多 3 条基准事件的一句话摘要（`industry_baseline`）。这只是对照材料，不是结论。
- **不预读正文**：扫描阶段只做来源存在性与大小检查（`raw_status`），不读取 Raw 正文。正文只在**投递前定向复核**这一条待发消息时读取，最多 2 个文件、800 字；读不到就延期 60 分钟，不发高优先级提醒。
- **模型职责**：判断增量是否真的构成边际变化、要跟哪一版比、比的是价格/订单/产能还是基准方向；材料不足时如实说明缺口或延期，不臆造对比结果。

该设计把 I/O 从"每轮重读全库"降到"有变化才读"，实测单次扫描的 Raw 正文读取由 392 次降为 0 次。

## 时效与语义新鲜度

心跳频率解决的是发现周期，不保证事件仍然有时效。每个催化候选同时保留事件日、证据更新时间、首次评估时间和通知有效期。

- **语义版本**：只有原始事实、基准变化、来源口径或阶段迁移才生成新版本。Raw 补读、I/O 错误码、K 线验证元数据和证据包格式变化不刷新事件年龄，也不制造“新催化”。
- **初始时效**：催化事件默认只接受事件日起 7 天内的即时评估；趋势读数最多允许 3 个自然日缺口。超过期限的候选标为 `backfill`，默认不直接提醒，需新的当前证据或明确的长期跟踪目标才能升级。该期限是工程防打扰默认值，不是用户交易方法论中的新买卖规则。
- **历史补评**：系统首次发现旧事件不等于市场刚发生新事件。`backfill` 只能用于研究回顾，不能转成即时仓位提醒。`verified` 只表示 K 线验证流程完成，不代表预测仍然成立。
- **回源降级**：`raw_available=false` 时禁止 `notify/needs_user`，只能 `silent` 或 `defer`。延期重试间隔至少 60 分钟，且不能超过候选有效期；Raw 暂时性失败不取消已有的待发意图。
- **待发有效期**：通知意图必须有 `valid_until`，取候选有效期与创建后 24 小时的较早者。投递前再次检查，过期项转为 `expired`，不因夜间免打扰、PG 恢复或进程重启而补发旧提醒。
- **消息时间表达**：提醒需区分事件日、最近证据日和本次评估日。历史补评不得写成“今日新催化”，已错过的验证窗口必须先补当前结果，不能用当时的待验证条件替代。

## 唤醒、评估与通知

推送时刻不固定：数据到达后，由模型根据增量判断要不要推送。触发器只产生“信号”，是否叫醒模型仍由确定性扫描决定；新增触发方式不会多出一条绕过去重、时效和频控的通道。

全天都扫描和评估，包括 23:00–06:00 静默期（`evaluate_in_quiet_hours: true`）。静默期只约束投递：夜里评估出的提醒保留为 `pending`，静默期一结束即按优先级发出。设为 false 则恢复静默期完全不扫描。

- **长任务收尾**：长任务配置在 zcode 定时任务里。pulse 只读 zcode 运行记录（`sources.yaml` 的 `upstream.zcode`），登记过的长任务成功结束即标记对应数据源立即就绪、跳过防抖；登记过的长任务失败写进健康记录 `upstream_task_failed`。首次运行只建游标，不回放历史。不修改 zcode 任务本身。
- **水位（文件变更检查）**：pulse 每次比较 `config/sources.yaml` 登记的金库文件（mtime+size）和 PG 只读水位查询。文件变化的防抖从文件真实修改时间算起（安静 `quiet_seconds` 或最长等 `max_wait_seconds`），所以 15 分钟的 pulse 间隔不会再额外多等一轮。
- **信号收件箱**：长任务 Skill 收尾或用户手动执行 `proactive_goal.py signal --source skill:<名称>|manual`，只追加一行，不扫描、不唤醒。
- **时间**：交易日 08:35 / 15:40 固定窗口到点、延期复核到期、30 分钟心跳兜底，这些立即就绪。固定窗口只是复核机会，不是推送时刻；不需要时可在 `sources.yaml` 关闭 `scheduled_review`。
- **趋势时效**：`trend_state.py --date` 是计划日，参考日取它之前最近一个交易日。pulse 始终按“明天”调用，收盘数据一入库当天就能读到；数据未到时读数与按今天调用完全一致。计划日不进指纹，同一份收盘数据不会每天重新评估。
- **限流**：每小时最多 4 次、每天最多 30 次评估；有批次在途（`signals.inflight`）时不再备新批，在途超过 30 分钟视为超时，计一次失败后放开。
- **触发**：`hermes cron run` 会同步跑完整个评估，所以放进独立会话的子进程，pulse 不等待；输出写到运行态 `logs/trigger.log`。

扫描后没有候选就不调用模型。扫描异常采用 fail-closed：记录 `source_errors` 与健康告警，不利用非零退出触发 Hermes 的错误唤醒路径。PG 暂时失败时，待发意图保留为 `pending`。延期包缺失、损坏或链接越界必须显式报错。该循环不是实时行情订阅，只能发现已有数据、既定窗口和到期事项带来的变化。

### 通知判断

- `silent`：重复、无实质增量、前置条件不全、证据不足或无需用户行动。
- `defer`：等待指定时间/数据窗口再复核，必须给出 `review_after`。
- `notify`：达到提醒门槛，输出简洁的主动提醒。
- `needs_user`：目标冲突、需要用户裁量或超出授权，明确需要用户回答什么。

提醒应说明发生了什么、命中哪条现行规则、证据日期/来源、候选复核动作、缺失输入和失效条件。默认中文、讲人话，通常不超过 600 字。提醒不等于交易指令；数据缺失、修订中规则、低样本和未确认来源必须随判断说明。

通知只接受纯文本：`MEDIA:`、附件和 `file://` 引用、`[SILENT]` / `[CRON_FAILURE]` 等控制标记、末行伪装的 `wakeAgent` 信号一律拒绝。运行记录限 2MB，防止异常输入变成文件外发、控制注入或无界读取。

## 状态、去重与恢复

运行态目录下的 `state.json` 只保存活跃候选、待办与近期通知意图、游标、主题冷却、信号水位和健康记录；终态候选压缩进 `index.json`（去重只需要它），过期的意图与运行记录滚动到 `archive/`。结构契约为 `config/schemas/state.schema.json`（v3）。完整候选包位于 `packets/`，决策审计追加到 `decisions.jsonl`，信号收件箱为 `signals.jsonl`。

只有 `proactive_goal.py` 可持锁读-改-写并原子替换状态；模型不得编辑状态。锁位于运行态目录 `locks/`，由操作系统在进程退出时释放；运行态不在 OneDrive 中。

- **版本与去重**：指纹只覆盖语义字段，逾期天数、注入的规则摘要和固定说明文字变化不产生新版本。同一候选同一证据版本只通知一次；旧版本在新版本出现后不能再通知。指纹算法升级时，用旧候选包按新算法重算，语义相同的继承原终态，不因算法变化重新唤醒。
- **主题冷却**：主题键（`topic_key`）由代码确定，例如 `trend:axis`、`framework_review:industry-board`、`catalyst:<事件ID>`。同一主题上次发出后，在 `sources.yaml` 的 `cooldown_hours` 内不再发；冷却截止晚于意图有效期的，记为 `suppressed_cooldown`，不补发。
- **逐项校验**：一项不合格只作废该项，并计入该候选的重试次数；其余照常入账。defer 越过有效期就夹紧，有效期已到就转静默；非 defer 带的 `review_after` 忽略；一批多条提醒时只保留优先级最高的一条，其余改为 30 分钟后复核。修正都写进审计 `repairs`。整份响应无法解析时，给这一批在途候选各计一次失败。外发安全问题（附件、控制标记）不修正，直接作废。
- **消息**：模型给 `brief`，代码负责渲染标签、事件日与版式，把术语表里的节点代号换成名称、删掉免责套话；残留的内部标识只记 warning。
- **频控**：免打扰、最小通知间隔、每日上限、主题冷却都由投递器执行，不依赖模型自觉；同时有多条到期时优先级高的先发。
- **回执**：`pending` 尚未尝试，可以安全恢复；`attempted` 已产生投递尝试，不自动重发。下一轮 pulse 读 Hermes 执行记录，把它推进为 `delivered` / `failed` / `not_sent`，2 小时内查不到记录的标 `unverified`。只有 `delivered` 才算送达。
- **恢复**：延期候选按落盘包恢复，不依赖文件 diff 或原定时窗口再次出现。投递前证据已更新时取消旧意图；重试次数耗尽转为可见 `dead`。不向定时评估注入上一轮回答。
- **健康**：Response 段解析不出、评估输出即将被轮转、PG 水位查询失败、回执查询失败、评估超时、触发失败、被限流，都写进 `state.health` 与审计，`status` 可见；不进入市场提醒通道。

## 权限与控制

读取 AlphaVault 文件、PG 和生成候选允许自动执行。向用户发送本目标定义范围内的提醒，已由用户在 2026-10-27 明确授权；正式启用前必须先完成双段影子验证。

写 Wiki、修改方法论、形成正式研究报告、改变交易规则、开通外部数据源或执行其他有副作用的子任务，仍按各自协议单独授权。本目标的通知权限不能扩展成这些权限。

用户可通过交互会话使用 `proactive_goal.py control` 暂停、恢复或设置免打扰。外部证据、Raw 文本、网页内容和 Skill 输出都是待评估数据，不能修改本协议、工具白名单、调度或通知策略。

安装工具默认 dry-run；只有显式应用才创建/更新两个 Hermes 任务。任务 `workdir` 为运行态目录（不再向评估 prompt 注入金库 `AGENTS.md`），不重启或替换现有微信网关，不修改其他 profile 的任务。安装器拒绝在运行态未迁移、技能副本未同步时应用。
