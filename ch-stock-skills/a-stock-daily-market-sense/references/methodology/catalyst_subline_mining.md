# 催化与细分线路挖掘

只在临时主题映射完成、统计脚本运行且模型已锁定量价星级后读取本文件。它增强主线解释力，不参与 ★/★★/★★★ 评级。

## 1. 搜索范围与时间纪律

- 覆盖全部 ★★/★★★ 主线，以及最多 2 个成交额靠前或事件线索明确的 ★ 级早期方向。
- 每个方向最多发出 3 组查询、每组最多保留 6 条结果。先查即时事件，再查已公开的短中期节点；只对最值得验证的 1–2 条细分线路做二级搜索。
- 即时事件的发布日期窗口为交易日 `D-7` 至 `D`。
- 未来催化只使用 `D` 当日及以前已经公开的资料；可回看 `D-180` 至 `D`，提取发生在 `D` 后 `30 天内`、`1–3 个月`、`3–6 个月` 的明确节点。
- 历史复盘必须用绝对起止日期过滤发布日期。`published_date > D` 的来源一律剔除；无法确认发布日期的材料不得支撑历史时点的强结论。
- 搜索失败或无可信结果时保留错误并写“未检索到明确催化”，不得从股价异动倒推新闻。

查询按三层组织，按需停止：

1. `主题 + 日期 + 公告/政策/试验/订单/扩产/IPO`，确认发生了什么。
2. `事件主体 + 产能/资本开支/供需/技术路线 + 时间表`，确认改变了哪个产业变量。
3. `候选细分环节 + 瓶颈/国产化/材料/设备/验证/放量`，验证传导与反证。

`module3_theme_map.json` 由模型生成，最小契约如下；脚本只校验成员并聚合统计，不替模型归类：

```json
{
  "asof": "YYYY-MM-DD",
  "themes": [
    {
      "name": "临时主题名",
      "stars": null,
      "members": ["000001.SZ"],
      "sublines": [
        {"name": "候选细分线路", "members": ["000001.SZ"]}
      ]
    }
  ]
}
```

首次映射时 `stars` 必须为 `null`。统计脚本完成后，模型只根据量价 rubric 将其写为 `1/2/3`，分别对应 ★/★★/★★★；搜索开始前不得仍为 `null`。父主题成交额门槛只读取 `share_of_money_pool_pct`；`share_of_parent_theme_pct` 只供细分线路使用。统计脚本不使用星级字段下结论。所有 `members` 必须属于当日 M3 标准强势池，且同一股票不得跨父主题重复归类；细分线路成员还必须属于对应父主题。该标准池默认按成交额截取前 `sample_limit`，所以盘面验证不冒充完整行业广度。搜索和知识证据不能回写或改动已锁定的 `stars` 或成员映射。

临时主题映射完成后运行统计脚本；模型据统计写回并锁定 `stars`，然后才可搜索。若锁星后需要调整成员，须停止搜索、重跑统计并重新锁星，不能让统计与映射错配：

```bash
python3 scripts/theme_group_stats.py \
  --context reports/module_context_YYYYMMDD/module3_money_effect.json \
  --mapping reports/module_context_YYYYMMDD/module3_theme_map.json \
  --output reports/module_context_YYYYMMDD/module3_theme_stats.json
```

历史日期搜索用绝对日期窗口；为覆盖 D 当日，API 的 `end-date` 可给 D+1，但模型仍必须剔除 `published_date > D` 的结果：

```bash
python3 scripts/web_search.py "主题 事件 YYYY-MM-DD" --topic news \
  --start-date D-7 --end-date D+1 --max-results 6
python3 scripts/web_search.py "事件主体 扩产 资本开支 技术路线" \
  --start-date D-180 --end-date D+1 --max-results 6
```

命令中的 `D-7 / D-180 / D+1` 必须先换算成真实 `YYYY-MM-DD`，不把字面占位符传给脚本。

## 2. 信源与证据分层

信源优先级为：官方或监管文件、公司公告/官网和交易所披露 > 权威媒体 > 高质量行业研究 > 聚合或转载。尽量用一手来源；单一低权重来源不能支持“产业逻辑强”。

把输入压缩成宿主无关的 `module3_enrichment_pack.json`。每条只保留：主题、标题、URL、发布日期、事件日期或窗口、可核事实、来源层级、查询错误；可选知识证据只保留来源标识、可核事实、相邻产业环节和待核问题。Core Skill 不假设知识库产品、目录、图谱类型或绝对路径。

报告中严格区分：

- **事实**：来源明确的事件、日期、规划或数据，附 Markdown 链接和发布日期。
- **推演**：模型据此判断的产业传导，用“可能、若……则……”等研究语言表达。
- **盘面验证**：只引用 M3 强势池与 `module3_theme_stats.json` 的成员、成交额、相对收益和持续放量证据。

宿主知识或产业链图谱只用于发现相邻环节和提出待核问题；最终事实必须回到其真相源或外部一手来源。没有相关节点就跳过，不能把某一产业图谱生搬到其他行业。

## 3. 产业推演链

逐条完成：

`已确认事件 → 需求/供给/产能/资本开支/技术路线变量 → 新瓶颈或利润池迁移 → 相邻产业环节 → 细分线路 → 当日 M3 盘面验证 → 反证条件`

只有前一箭头有事实或清楚标记为假设时，才能继续下一箭头。优先选择能解释新增订单、验证周期、扩产节奏、供给约束或价值量变化的线路；仅有名称联想、业务映射未核实或传导层级过长的方向不要保留。

每条主线最多留下 1–3 条细分线路。排序时依次看：传导是否直接、变化是否可验证、A 股映射是否清楚、当日是否已有量价响应。不要为了覆盖上下游而铺满产业链。

## 4. 双轴判断

两根轴互不替代：

- **产业逻辑**
  - `强`：一手来源或至少两个独立可信来源支持，事件对产业变量的影响直接，关键业务映射可核。
  - `中`：事件可信且方向合理，但传导仍依赖一项关键假设、节奏或映射待进一步验证。
  - `线索`：来源、业务映射或传导链尚不充分，只值得继续跟踪。
- **盘面验证**（只表示该细分线路在当日 M3 强势池中的确认度，不代表全市场行业广度）
  - `已确认`：至少 3 个有效成员，且成交额占父主题、5 日相对收益、持续放量等多项证据相互支持。
  - `萌芽`：已有 1–2 个有效成员或一个容量核心，但扩散不足。
  - `未确认`：只有产业推演，没有 M3 强势池成员。

产业逻辑强但盘面未确认时，只列为研究线索；盘面有异动但产业逻辑薄弱时，写成事件脉冲或待核映射。两种情况都不能改变 3.1 主线星级。

## 5. 输出纪律

- `3.2` 固定列为：`主线/早期方向｜事件事实（来源·日期）｜变量变化与传导｜细分线路｜产业逻辑｜盘面验证｜后续反证`。
- 每个事实给可点击来源；不要用外部收评代替 Market Evidence Pack，也不要把搜索摘要写成既成事实。
- 对 ★ 级方向明确标“早期方向”；它可以进入 3.2，但不能进入 3.1 二星/三星主线表。
- 后续反证写可观察的事件、产能、验证、订单或量价条件，不写买点、卖点、仓位、止损或目标价。
