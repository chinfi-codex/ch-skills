# 双轨方法：大盘权重估值锚定 + 中小盘流动性挖掘（第 4 章维度 C）

主线锁星之后，第 4 章要回答"线里该盯谁"。大票和小票的逻辑不一样：大票是机构的压舱石，看贵不贵、下行空间多大；中小票是增量资金的试验田，看新钱在挖哪里、挖的东西新在哪。所以维度 C 拆成两条轨道，各用各的尺子。

| | 🔵 大盘轨：估值锚定 | 🟠 中小盘轨：流动性挖掘 |
|---|---|---|
| 范围 | 已锁星（★★/★★★）主线成员中，总市值 ≥ 400 亿 | 总市值 < 400 亿；主线内为主，主线外单列"潜在新线索" |
| 回答的问题 | 现在贵不贵，安全垫有多厚，拿不拿得住 | 新进资金在挖哪里，挖的东西新在哪 |
| 脚本给什么 | `valuation_anchor.json`：指数 10 年分位、个股 3 年分位、股息率 | `liquidity_scan.json`：放量倍数、换手倍数、5 日放量天数、主线成员归属 |
| 模型判断什么 | 估值档（低估 / 合理 / 偏贵），结合行业周期修正 | 边际变化类型，以及"新在哪里" |

## 取数顺序

两个脚本都在**锁星之后**跑，读同一份已锁星的主题映射：

```bash
python3 scripts/_shared/skill_runtime/runner.py --skill-root . run daily.valuation-anchor -- \
  --asof YYYYMMDD --context reports/module_context_YYYYMMDD/module3_money_effect.json \
  --mapping reports/module_context_YYYYMMDD/module3_theme_map.json \
  --output reports/module_context_YYYYMMDD/valuation_anchor.json
python3 scripts/_shared/skill_runtime/runner.py --skill-root . run daily.liquidity-scan -- \
  --asof YYYYMMDD --mapping reports/module_context_YYYYMMDD/module3_theme_map.json \
  --output reports/module_context_YYYYMMDD/liquidity_scan.json
```

产物必须落 `module_context_<日期>/`，第 4 章引用的估值与放量数字才能过数字溯源门禁。个股估值首次跑会按 ts_code 回补约 3 年 `daily_basic` 进 `dms_valuation_daily`，之后只补增量。"新细分"要看主线生命周期台账：`python3 scripts/theme_lifecycle.py context --asof YYYY-MM-DD --days 10`。

## 大盘轨：估值锚定

1. **先看指数锚定水位。** 沪深300、上证50 的 PE-TTM 在近 10 年里的分位，说明大盘整体有没有安全垫。指数只给背景，不进并集清单。
2. **再看个股锚。** PE-TTM、PB 在自身近 3 年里的分位，加当日股息率。`pe_valid=false`（亏损或 PE 失真）时改看 PB 分位；周期股盈利在顶部时 PE 分位会失真偏低，要结合行业周期说明，必要时以 PB 为准。
3. **分三档**（模型判定，脚本不给档位）：
   - **低估**：分位 ≤ 30；
   - **合理**：30 < 分位 < 70；
   - **偏贵**：分位 ≥ 70。
   分位为 null（样本不足）时写"估值样本不足"，不硬定档。
4. **怎么用。** 估值只回答下行空间与持有支撑，不回答涨跌。"低估 + 趋势锚完整"是这条主线的压舱石；"偏贵"说明估值已不提供支撑，后面要靠业绩消化——这不是卖出信号。

## 中小盘轨：流动性挖掘

1. **流动性门槛（脚本已过滤）**：当日成交额 ≥ 前 20 日均额的 1.8 倍，或换手率 ≥ 前 20 日均换手的 2 倍；且近 5 日放量日（成交额 > 前 20 日均额 1.5 倍）≥ 3 天，排除一日游。放量下跌的候选照样在名单里，属于亏钱效应的交给第 5 章，不当挖掘信号写。
2. **边际变化（模型判断，至少命中一项才算信号）**：
   - **业绩/订单边际**：最新财报、预告、订单或产能公告显示的环比改善，且是该公司第一次出现的增量来源；
   - **新技术**：产品形态或工艺第一次切入新环节（送样、通线、量产、认证），不是老产品的概念重贴；
   - **新细分板块**：生命周期台账里首次出现的细分线路，或第一次在强势池里成组出现（同一细分 ≥ 3 只）的方向。
   事件来源沿用 `catalyst_subline_mining.md` 的时间纪律（`published_date ≤ D`，搜索失败如实披露）。
3. **找不到边际变化**的，标"逻辑待验证"：可以列，但不算命中，不加信号强度。
4. **主线外候选**（`outside_candidates`）只进"潜在新线索"：按方向归并，写清量能证据、对应事件、离主线门槛还差多远；同一方向只有 1 只放量的写"个股异动，暂不构成线索"。不进主线表、不评星、不进并集清单。

## 两条轨道谁排前面

沿用 `size_preference.md` 的量能 × 趋势判定：缩量下行档中小盘轨排前面，放量趋势档大盘轨排前面，混合档不分先后。这只决定 4.1 并集清单的排序和一句话判断里的一句提示，不改变任何一只票的命中与否。规则倾向与风格因子的实际规模风格背离时，照 `style_factors.md` 并列写。

## 写法纪律

- 4.4 大盘轨：一张"指数 / 个股 | PE-TTM | 分位 | 股息率 | 估值档"表 + 一段 `==锚定判断==`；4.5 中小盘轨：一张"个股 | 细分线路 | 总市值 | 成交额/20日均 | 5日放量天数 | 边际变化 | 新在哪里"表 + 一段 `==挖掘判断==` + 潜在新线索 list。
- "新在哪里"每格用一句完整的话写清楚是什么变了，不堆关键词。
- 估值档与边际变化都是研究判断，不写买入、卖出、目标价、止损；"低估"不写成"值得买"，"偏贵"不写成"该卖"。
- 数据缺口（估值样本不足、某只换手缺失、搜索失败）照实标注，不用涨跌反推。
