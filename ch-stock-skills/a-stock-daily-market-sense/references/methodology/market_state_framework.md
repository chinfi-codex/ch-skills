# 市场状态定位框架（模块 1.1 判断手册）

配套证据块：`module1_market_trend.json` 的 `market_state`（由 `scripts/market_state_card.py` 机器生成，只含确定性读数）。脚本不给结论；本手册是模型的判断框架。状态定性写进模板 1.1 的 `==市场状态定位==` 段，不超过 150 字，不含买卖建议。

## 判断目标

回答两个问题：

1. 当前回撤属于什么量级——权重指数与成长小盘分开定性（见"位置分层"）；
2. 调整是否接近尾声（见"状态确认三要素"）。

## 状态确认三要素（调整接近尾声的确认信号）

1. **融资余额停止创新低**：`margin_trend.is_new_low_20d` 转 false，`days_since_20d_low` 开始累计，且 `chg_5d_pct` 走平或转正。融资是 T-1 口径，引用时必须带 `trade_date` 数据日。
2. **宽度从低位修复**：`breadth.pct_above_ma60`（站上 60 日线个股占比）从低位（约 17% 一线）恢复到 **50% 以上**。
3. **行业面扩散**：`sw_industries.count_positive_60d` ≥ **10** 个申万一级行业 60 日收益为正，**且伴随盈利上修**。盈利上修脚本不提供，须由模型从外部证据（业绩预告、券商一致预期等）判断；没有外部证据时写明"第三要素缺外部证据"。

三要素是"且"的关系，只满足一两条时写"修复进行中但未确认"。

前三条的**阈值算术**脚本已经替你算完，落在 `confirmation.checks` 里：每条给 `threshold`（阈值原文）、`reading`（读数）、`hit`（true/false/null）、`as_of`（该读数自己的数据日）。直接引用，不要自己重算——重算出来和卡面对不上就是两套数。`hit: null` 只有两种来源：子块不可用，或那条本来就没有数据源（`source: external`，即盈利上修）。`hits/scriptable` 是可机判部分的命中数，**它不是结论**：三要素的"且"要不要判成"接近尾声"、第四条缺外证算不算破，仍然是你在正文里说的话。

阈值改动只允许改一处：脚本里的 `BREADTH_CONFIRM_PCT` / `INDUSTRY_CONFIRM_COUNT` 与本节文字必须同步，否则卡面勾选和手册说法会分叉。

## 边际方向（状态卡的第三行）

只给水平读不出状态在往哪走，所以每项都带了前一交易日的对照：

- `breadth.pct_above_ma60_delta_1d` 等三个 `*_delta_1d`：宽度环比，单位 pct；
- `sw_industries.count_positive_60d_prev`：行业扩散的前一交易日计数；
- `index_position.indexes[].drawdown_delta_1d`：回撤环比，正值 = 回撤收窄；
- 融资本身已有 `chg_5d_pct` / `chg_20d_pct` / `days_since_20d_low`。

写"边际变化"那一行时挑真正动了的那条讲，别把六个数复述一遍；都没动就直说与前一日基本持平。

## 位置分层（回撤量级参考）

权重指数（上证综指、沪深300）与成长小盘（中证500、中证1000、创业板指、科创50）分开看，用 `index_position` 的 `drawdown_from_high_250d_pct`。归属已经写死在 `indexes[].group` / `group_label` 里，别每天重新分组。参考量级（非硬规则，脚本按同一套边界给出 `tier`）：

- 回撤 < 10%：调整；
- 10–20%：深度调整；
- > 20%：接近"技术性熊市"表述。

权重与成长小盘回撤量级明显不同时，说明是结构性出清而非系统性下跌，措辞上区分"权重护盘、成长出清"这类分层，不要用一个数字概括全市场。

另外可用 `sw_industries.industries[].high_250d_date` 与 `benchmark_high_250d_date`（上证综指 250 日高点日期）比对：领涨行业高点日期明显早于宽基高点日期，说明主线已先于指数见顶，是结构退潮的直接证据。

## 口径（会影响阈值怎么读，别换算）

- **回撤是"收盘 vs 区间盘中最高"**（`index_position.caliber`）。两端不同源是刻意的：最大回撤的参照就该是盘中最高。它比收盘价口径深 0.1–1.6pct（2026-08-06 实测），落在 10%/20% 边界附近时**按卡面的数说话，不要自己换成收盘价口径再比一次**。
- **宽度是前复权**（`breadth.price_adjustment = qfq`）。`stock_daily` 存的是未复权价，直接拿去算 MA60 会被除权除息单边压低——2026-08-06 未复权 26.14% vs 前复权 29.64%，差 3.5pct，方向恰好压在 50% 这条确认线上。若某天 `price_adjustment` 退回 `none`（拿不到复权因子），"宽度回到 50%"这条要素要注明口径已降级。
- **行业结构的分母是有效行业数**（`count_positive_60d_total` / `count_above_ma60_total`），不是恒定的 31。历史不足的行业记缺失，不记"在均线下方"。

## 新鲜度（先看这一条，再看读数）

每个子块都自报 `data_through` 与 `stale_trading_days`，块级 `stale_blocks` 列出所有超期的子块。**读数之前先看它。**

这条不是形式主义：`sw_daily` 是 Tushare 权限接口，token 掉权限后取数会静默失败，计算照常吃 PG 里的旧缓存，于是"60 日收益为正 1/31"会以今天的名义写进研报，没有任何异常、没有空值。2026-08-06 就是这么被抓出来的——行业结构当时停在 07-31，落后 4 个交易日。

处理方式：

- `stale_blocks` 非空时，模板"数据提示"那一行必写，正文引用该读数必须带它自己的数据日；
- 融资与申万行业各容忍 1 个交易日（见下，两者都是结构性 T-1），其余子块 0 容忍；
- 滞后跨了几天的读数不能拿来说"今天的边际变化"——扩散计数跟前一交易日比才有意义，而它的"前一交易日"也停在同一个旧日期上。

## 申万行业的数据源与它的 T-1

本机 token 没有 `sw_daily` 权限，行业行情实际走 **AKShare 的 `index_hist_sw`（申万宏源研究官方站）**，`market_panel.fetch_sw_daily` 里 Tushare 失败后自动兜底，权限哪天恢复会自动切回去，不用改配置。两源已验过等价：重叠区间 close/high 差 ≤0.005 指数点（四舍五入级别）。

**申万宏源官方发布滞后一个交易日**：盘后跑 D 日的复盘，行业读数最新只到 D-1。这是口径不是故障，所以容忍设成 1；但正文引用行业扩散时仍要带上它自己的数据日（`sw_industries.data_through`），别说成当日。落后超过 1 天才是真出问题了（多半是兜底也失败、又在吃旧缓存），那时 `stale` 会翻 true。

BaoStock 这条路走不通，别再试：它不提供申万指数（代码只认 sh./sz. 前缀），自带的行业分类是证监会口径 84 类，和申万一级 31 类对不上，手册里"≥10/31"这条阈值直接失去意义。

## 纪律

- 证据不足时明确写"不足以判断"；脚本没有的数（如盈利预测）只能从外部证据引入并注明来源，不得编造。
- 融资读数是 T-1 口径，引用必须带数据日（`margin_trend.trade_date`），不能说成当日资金行为。
- `insufficient_history: true` 或字段为 null 时按缺失处理，不得用缺口外的数脑补。
- 某子块 `available: false` 时披露原因，其余子块照常使用。
- 本模块只定位市场状态，不输出买卖建议、仓位或目标价。
