# 业绩预告解读与“优秀个股”判断细则

SKILL.md 只放纲要，这里放判断锚点、拆解语义、字段字典和边界处理。模型据此**逐股判断并排序**，脚本不替你下结论。

## 一、三口径增速：定义与拆解语义

业绩预告给的是**累计口径**（H1 = Q1+Q2 的归母净利，一个区间）。真正要看的是三个口径：

| 口径 | 含义 | 来源 |
|---|---|---|
| **当年累计同比** | 本报告期累计净利 vs 上年同期累计（H1 vs 去年 H1） | 预告原生（`p_change` 中值；缺失时用中值净利/上年同期推算） |
| **单季度同比** | 最新单季净利 vs 去年同一单季（Q2 vs 去年 Q2） | 用实际季报拆解 |
| **环比** | 最新单季 vs 上一单季（Q2 vs 当年 Q1） | 用实际季报拆解 |

**拆解公式**（单季 = 累计 − 上一累计期；Q1 的单季 = Q1 累计本身）：

- 本期最新单季（Q2）= H1 预告净利中值 − Q1 实际累计
- 去年同一单季（Q2 去年）= 去年 H1 实际 − 去年 Q1 实际
- 单季度同比 = 本期单季 / 去年单季 − 1
- 环比 = 本期单季 / 上一单季（当年 Q1 实际）− 1

三季报（Q3）、年报（Q4）同理：单季 = 当期累计（预告中值）− 上一累计期实际；Q3 的上一累计期是 H1，Q4 是前三季。脚本对任意季度统一处理。

**为什么单季比累计重要**：累计会被上半段拖累或抬高，最新单季才反映当下的经营边际。判断口诀：
- 单季同比 > 当年累计同比 → 增速在**抬头（加速）**，脚本 `flags.accelerating=true`。
- 环比 > 0 且逐季走高 → 景气向上。
- 单季同比 < 累计同比 → 高增长在**减速**，哪怕累计仍是大正数也要在报告里点破。

## 二、“业绩优秀”排序锚点（rubric）

不要用单一同比排序。综合下面维度分「强 / 中 / 观察」三档：

**强（第一梯队）——同时满足多数：**
- 单季度同比与当年累计同比双高，且单季 ≥ 累计（加速），环比为正。
- （若有 price_reaction）公告后出现断层且未回补，尤其"断层 + 在场主线内"是胜率最高的组合（见 §八）。
- 绝对利润规模不小（`net_profit.median_yi` 不是几千万级的小票弹性）。
- `change_reason` 指向主业驱动：销量增长、产品涨价、毛利率提升、新产能/新客户/新订单放量、行业景气上行。
- `revenue_trailing` 显示最近实际期营收同步增长（营收利润共振）。
- 不依赖低基数：上年同期本就盈利且基数不低（`type=预增/续盈`，非扭亏）。
- （若取了 cninfo 扣非）扣非净利贴近归母，高增里没有大额一次性成分。

**中（有亮点但有瑕疵）：**
- 累计同比高但单季在减速；或环比转弱。
- 高增长但基数偏低（上年同期很小）或含一次性成分。
- 利润高增但最近实际期营收没跟上（靠降本/减值转回/毛利修复，持续性存疑）。
- 扭亏但已连续两季度改善、原因是主业修复。

**观察 / 剔除：**
- 扭亏或高增主要靠**非经常损益**（见第三节关键词）。
- `type` 为预减 / 略减 / 首亏 / 续亏 / 增亏。
- 单季环比明显转弱，累计的高增只是上年低基数的镜像。
- `change_reason` 出现大额一次性收益（处置、补助、投资收益、公允价值）。

## 三、可持续性：读 `change_reason` 的关键词清单

**利好且可持续（主业驱动，含金量高）：** 销量/出货量增长、订单饱满、产能释放、新客户/新项目量产、产品价格上涨、原材料成本下降传导、毛利率提升、市占率提升、行业景气/供需改善、规模效应、费用率下降。

**需打折或剔除（一次性 / 非经常损益）：**
- 资产处置、出售子公司/股权、土地/房产处置收益
- 政府补助、税收返还/优惠、退税
- 投资收益、公允价值变动、金融资产/股权投资估值波动
- 并购并表带来的利润跳增（口径变化，非内生）
- 诉讼赔偿、保险理赔、债务重组收益
- 减值转回（此前计提的减值冲回）

判断动作：若净利高增主要由这些驱动，即便同比很高也应降档，并在报告里明确“扣非后含金量存疑”。反之，若原因是主业量价，同比哪怕“只有”30–50% 也可能优于靠一次性冲上 300% 的票。

**扣非净利是含金量最硬的量化证据（走 cninfo 增强层取）。** Tushare 结构化预告没有扣非，但预告公告原文（主板/科创普遍、部分创业板）会披露「扣除非经常性损益的净利润」。`cninfo_enrich.py` 会把它解析出来（`parsed.kf_net_profit_yi`）。用法：
- **扣非 ≈ 归母**：利润几乎全是主业，含金量高，可进强档。
- **扣非 << 归母**（差额大）：高增里有大量一次性收益，哪怕归母同比很漂亮也要降档，报告点明“扣非后大幅缩水”。
- **扣非增速 > 归母增速**：核心经营比表观更强，是加分项。
- 扣非只在少数创业板模板式预告里没有；`parsed.kf_net_profit_yi=null` 时回到读 `change_reason` 定性判断。
- 解析值要对照 `text` 全文核对（`confidence=med` 的表格口径尤其要看一眼 `raw`）。

## 四、基数与边界处理（对应脚本护栏）

- **负基数不算百分比。** 上年同期或去年同季 ≤ 0（亏损/扭亏）时，同比%无意义，脚本给 `single_q_note/qoq_note = base_nonpositive`，只输出绝对额与“扭亏/减亏”定性。报告里用“上年亏损 X 亿 → 今年盈利 Y 亿”这种绝对口径讲，别硬套百分比。
- **次新股缺可比基数。** 上年无同期数据 → `base_missing`，只有当年累计同比可信，单季/环比可能拆不全。
- **无实际季报数据。** `income` 取不到 → `cur_missing`，列入 `meta.income_missing`，只能用预告累计同比，单季无法拆。报告要如实说“单季无法拆解”。
- **`base_consistency=diverge`。** 预告的 `last_parent_net`（公司自报上年同期）与实际季报的上年同期累计差异 >5%，通常意味着上年被追溯调整/重述。此时当年累计同比（公司口径）与单季同比（实际季报口径）基期略有错位，报告里要提示，别把两者当成完全同一基准。
- **低基数弹性 vs 高基数高增。** 养殖（如益生股份类）、周期化工、资源品在底部反转时容易出几百上千%同比，这是低基数，不是经营质量。结合绝对利润规模和 `last_parent` 判断。

## 五、营收侧（trailing，务必与利润区分基期）

业绩预告**没有营收字段**。`revenue_trailing` 是**最近实际报告期**（如 Q1）的营收，用来佐证利润质量，不是本预告期的营收：

- 用途：看利润高增有没有营收支撑。营收利润同步增 = 健康；营收平淡而利润暴增 = 靠毛利/减值/一次性，持续性打问号。
- 口径提醒：净利是 H1 预告（前瞻、区间中值），营收是 Q1 实际（滞后一个季度）——报告里必须写清“营收为最近实际报告期、非本期预告”，否则会误导。
- 若公司在 `change_reason/summary` 文本里主动给了营收指引（少数会），可由模型抽取，但要标“文本口径、未经核验”。

## 六、字段字典（`forecast_scan.py` 输出 JSON）

- 单位：净利/营收类字段以**亿元**给出（`*_yi`），已从预告的万元、季报的元统一换算。
- `net_profit.median_yi`：预告净利下限、上限中值（万元→亿元）。`last_parent_yi`：上年同期归母净利。
- `profit_growth.cum_yoy_pct`：当年累计同比；`cum_yoy_source`：`p_change`（用预告披露的同比幅度中值）或 `derived`（用中值净利/上年同期推算）或 `na`。
- `profit_growth.single_q_yoy_pct` + `single_q_note`：单季度同比及其可信状态（`ok/base_missing/base_nonpositive/cur_missing`）。
- `profit_growth.qoq_pct` + `qoq_note`：环比及状态。
- `profit_growth.single_q_cur_yi / single_q_prev_yi`：拆出的本期单季、去年同季归母净利，便于核对与写报告。
- `profit_growth.base_consistency`：`ok/diverge/na`，上年基数一致性。
- `flags`（全部是机械阈值命中，不是结论）：`positive_type`（预增/略增/续盈/扭亏/减亏）、`negative_type`（预减/略减/首亏/续亏/增亏）、`turnaround`（扭亏/减亏或上年同期≤0）、`accelerating`（单季同比>累计同比）、`qoq_positive`、`cum_yoy_ge_min`（累计同比≥阈值）、`prefilter_pass`（向好方向且过阈值，仅粗筛，不代表“优秀”）。
- `valuation`（估值参照，读法见 §十一）：`total_mv_yi` + `mv_asof`（最新交易日总市值与其日期）、`annualized_np_yi` + `annualize_label`（年化净利=预告中值÷报告期季数×4）、`pe_annualized` + `pe_annualized_note`（`ok/np_missing/np_nonpositive/mv_missing`）、`rolling_np_yi`/`pe_rolling` + `pe_rolling_note`（滚动口径，基数缺失时 `base_missing`）。
- `type`：预告类型；`summary`：预告摘要（常含净利数字区间）；`change_reason`：业绩变动原因（可持续性判断的核心文本）。

> `flags.prefilter_pass` 只是粗筛开关（向好方向 + 累计同比过线），**不是“业绩优秀”的结论**。优秀与否要看单季边际、基数质量、原因可持续性、营收匹配，由模型综合判断。

## 七、cninfo 增强字段（`cninfo_enrich.py` 输出，按需对候选取）

只对初筛出的强/中候选跑，别全市场跑（每家一次 PDF 下载+解析）。每条记录：

- `announcement.title/ann_date/url`：预告公告标题、日期、原文 PDF 链接。
- `parsed.kf_net_profit_yi`：**扣非净利**（亿元，`low/high` 区间或 `point`）。Tushare 结构化预告没有，这是主要增量；判含金量看它与归母的差额。
- `parsed.parent_net_yi`：归母净利，用来和 Tushare 的 `net_profit.median_yi` 交叉核对（区间应能覆盖中值）。
- `parsed.revenue_yi` + `revenue_disclosed`：营收，多数为空/`false`（预告常态）。
- 每个 `parsed.*` 带 `raw`（原文片段）与 `confidence`：`high`=单位紧贴数字（措辞式“约3.9亿元到4.3亿元”），`med`=用表头“单位：万元”推断的表格值。**med 的一律对照 `text` 全文看一眼再用。**
- `text`：预告全文（很短，含完整业绩变动原因），是核对解析、判断可持续性的一手依据。
- `meta.missing`：orgId 没解析到 / 没找到该期预告 / PDF 为扫描件的票，报告里如实说明“未取到原文”。

口径提醒：扣非区间与归母区间的上下限不一定一一对应（公司分别给），比较时用中值对中值更稳。单位换算已统一到亿元（原文常是万元）。

## 八、业绩-股价断层（净利润断层观察）

核心命题：**业绩公布后，股价往往尚未充分反映其价值**。观察的不是业绩本身，而是「业绩 × 股价反应」的组合。脚本已在 `price_reaction` 块里给出确定性证据（以**首次披露日**为锚）：

| 字段 | 含义 |
|---|---|
| `gap_open_pct` | 公告日当天开盘 vs 公告日前一交易日收盘的跳空幅度（预告多在披露日前一交易日盘后发出，反应落在披露日当天） |
| `r_day_pct` / `r_vol_ratio` | 反应日全天涨幅 / 相对前 20 日均量的放量倍数 |
| `pre_pos_1y_pct` | 公告前收盘在近一年高低区间的分位（两型分类的依据） |
| `pre_mom_20d_pct` | 公告前 20 个交易日动量 |
| `since_ann_pct` | 公告前收盘至最新收盘的累计涨幅（是否已充分定价） |
| `gap_dir` | `up` 向上跳空=业绩超预期（**强表现**）/ `down` 向下跳空=不及预期（**弱表现**）/ `null` 无断层 |
| `gap_status` | `intact` 未回补 / `filled` 已回补 / `none` 无跳空 / `pending` 公告后尚无交易日；回补口径随方向翻转——向上断层被跌回公告前收盘下方=回补，向下断层被涨回上方=回补 |
| `trading_days_since_r` | 断层后经过的交易日数（新断层未经时间检验，要点明） |

**两型断层**（HTML 按 `pre_pos_1y_pct` 以 50 分位机械二分，最终定性仍由模型判）：

1. **趋势加速型**：公告前已在年内高位/有表现（分位≥50），业绩超预期推动跳空续升——股价原趋势 + 业绩确认，断层是"加速器"（如东山精密 2026-04 案例：Q1 预告后 4/9 跳空延续）。
2. **低位启动型**：公告前处年内低位（分位<50），业绩刺激从底部跳空——业绩是"点火器"，低位 + 断层 = 预期差修复的起点。

**判断要点：**

- **断层的有效性看"未回补"**。`gap_status=intact` 且放量（`r_vol_ratio` 高）= 市场用真金白银确认业绩；`filled`（跌回公告前收盘下方）= 断层失效，哪怕业绩很好也降档观察，在 caveat 里点明。
- **主线加持是胜率放大器**。同样的断层，标的在**在场主线内**（theme_hot）胜率显著更高——业绩 + 主线资金共振。排序时"断层 + 主线内 + 强档"排最前；断层但无主线归属的，是待验证的独立逻辑。
- **"未反应"是另一类机会**。业绩判强/中、却无跳空且 `since_ann_pct` 很小 = 市场还没定价（或市场不认，需模型分辨：原因含金量不足 vs 单纯没被看到）。这类要结合扣非/原因判断是"未被发现"还是"被识破"。
- **新鲜度诚实标注**。`trading_days_since_r` 只有 1-3 天时，"未回补"没经过检验，不要写成"断层确认"；报告期初的样本基本都是新断层。
- 位置分位需要 ≥60 根历史K线；次新股 `pre_pos_1y_pct=null`（`history_short`），两型分类不适用，单独列。

**反向断层与报告期行业趋势（自下而上）：**

个股的断层方向聚合到主线维度，就是**报告期内的行业景气趋势**的领先信号：

- **强表现 = 向上断层**（`gap_dir=up`）：业绩超预期 → 股价跳空上涨。
- **弱表现 = 向下断层**（`gap_dir=down`）：业绩不及预期 → 反向跳空下跌。
- HTML 按主线聚合成员的断层方向，机械算出每条主线的 `强N/弱M/净=强−弱`：`净≥2` 记**偏强**、`净≤−2` 记**偏弱**、强弱都有记**分歧**、否则中性/样本少。
- 这只是**确定性计数**（HTML 展示）。真正的行业趋势分析——分别观察强/弱两组、对各自的变动原因归因、交叉验证行业方向——按 §九 做，结论写成 `theme_trends[]` 落台账。

## 九、报告期行业趋势分析：强/弱表现分别归因 + 交叉验证

观察单位是主线（分类），观察窗口是一个报告期。一条主线里的预告股按断层方向天然分成两组——**强表现**（向上断层：业绩超预期、资金用跳空确认）与**弱表现**（向下断层：不及预期、反向跳空抛售）。行业趋势分析不是数人头，而是**分别读两组的业绩变动原因、归因到「行业级共性」还是「个体因素」，再交叉验证行业的发展方向与基本面变化**。`verdict.py context` 的 `to_judge_themes` 已把每条待判主线的强/弱/无断层成员连同 `change_reason` 分好组。

**第一步：强表现组归因。** 逐只读向上断层成员的 `change_reason`（有 cninfo 原文更好），提炼每只的驱动因子（涨价 / 放量 / 新产能 / 新客户 / 降本 / 一次性），然后判断组内有没有**共性**：

- 多只强表现指向同一个行业级驱动（同一产品涨价、同一下游需求放量、同一技术渗透）→ 行业向上的正面证据，而且能说出向上具体由什么驱动、在哪个环节。
- 各说各话、驱动互不相关，或主要靠一次性收益 → 只是个股 alpha 扎堆，不构成行业级信号。

**第二步：弱表现组归因。** 同样逐只读向下断层成员的原因，分辨是哪一类：

- **行业级拖累**（价格战、需求走弱、成本上行挤压、库存过剩）→ 行业趋势的反面证据。
- **个体事故**（单一客户流失、减值、事故停产、诉讼、高基数错杀）→ 不是行业信号，反而反衬"行业没问题、是它自己的问题"。

**第三步：交叉验证定方向。** 两组归因结论对照：

| | 弱侧=个体事故 / 无弱表现 | 弱侧=行业级拖累 |
|---|---|---|
| **强侧=行业级共性** | **向上**：行业景气确立，方向与驱动互相印证 | **分化**：行业在换挡——找强弱分界线（环节/价格带/客户结构/技术路线），说清谁吃到增量、谁被挤出 |
| **强侧=个体因素** | **证据不足**：只有个股逻辑，无行业级信号 | **向下**：行业基本面恶化，强表现是特例（alpha 或尚未传导），对组内强档要额外挑剔 |

**第四步：用含金量和主线状态再校验。**

- 强表现若主要靠一次性损益（扣非 << 归母）→ 从"行业级共性"里剔除，别把补助扎堆当景气。
- 已回补（`gap_status=filled`）的断层降权——资金已经收回确认。
- 与主线生命周期交叉：行业趋势向上 + 主线在场（★）= 基本面与资金共振，置信最高；向上 + 主线退潮/无主线 = 基本面领先于资金，是潜在新主线线索，报告里点名；向下 + 主线仍热 = 资金落后于基本面，警惕补跌。
- 无断层（quiet）成员是底色：只有一两只龙头跳空、其余无反应 = 龙头独走；多数成员都有正反应 = 全面开花。写趋势时要区分这两种"向上"。

**输出与克制：**

- 结论写进 verdict JSON 的 `theme_trends[]` 落台账（格式见 `verdict_and_html.md` §三）：`direction`（向上/向下/分化/证据不足）+ `strong_common`（强侧共性归因）+ `weak_common`（弱侧归因定性）+ `cross_validation`（一句话交叉验证结论）+ `confidence`。
- 样本诚实：一条主线只有 2-3 只样本就判"向上"要标 `confidence=low`；"证据不足"是合法结论，别硬判方向。
- 趋势随披露累积而演化：新成员断层出现后台账自动标待复判，下轮把新成员并入重判即可，别把季初的方向当定论。

## 十、报告期产业结构综述（全样本 → 宏观分组 → 强弱结构）

§九是"一条主线内"的显微镜，这一节是"整个报告期"的广角镜：从**全部已披露预告（正向 + 负向）**里读出产业结构——哪一类产业在获得业绩、哪一类在继续失血。目标产出是类似这样的综述：

> 1. 产业结构特征明显
>    (a) 高端制造科技（半导体、新能源、精细化工及精密零部件）都获得了较强的业绩增速；
>    (b) 消费和房地产行业预计将继续疲软，筑底难度较大。

原料是 `forecast_scan` 输出的 **`industry_summary`**（按 stock_basic 行业的确定性计数：家数、正/负向家数、扭亏与加速家数、断层向上/向下家数、累计/单季/环比增速中位数、大票成员样本）——全样本几百上千家时不可能逐股读，先读这张聚合表，再对关键行业下钻读个股 `change_reason`。

**第一步：分侧扫描。** 把 `industry_summary` 里的行业分到三个桶：

- **正向扎堆**：`positive_n` 占比高、增速中位数高、`gap_up_n` 多——业绩在获得且被资金确认。
- **负向扎堆**：`negative_n`（预减/首亏/续亏/增亏）聚集——业绩在恶化。注意默认扫描**不带** `--positive-only`，负向预告就在样本里，别只盯正向。
- **分化/样本少**：正负并存或只有一两家，暂不下行业结论。

**第二步：聚宏观组。** stock_basic 行业口径太细（半导体/元器件/通信设备/专用机械是四个行业），综述要按**业务事实**把相邻行业聚成宏观组，例如"高端制造科技"（半导体、新能源材料、精细化工、精密零部件）、"消费"（食品/纺织服装/零售/家电）、"地产链"（房地产/建材/家居/工程）、"周期资源"（有色/煤炭/化纤）——分组以**当期样本实际**为准，不硬套这四个名字，也不按申万一级机械并组。

**第三步：组内强弱结构判断（§九 逻辑抬到组级）。**

- **强组**要说清共性驱动是什么（AI/存储景气、材料涨价、出口、国产替代……），驱动要能被组内多个行业的个股 `change_reason` 交叉印证；顺带看 `gap_up_n`——业绩强 + 断层多 = 市场也认。
- **弱组**读负向预告的原因共性（需求疲软、价格下行、减值、竣工下滑），再找**筑底证据**：`qoq_median` 是否转正、`turnaround_n`（扭亏/减亏）占比是否上升、原因文本里"降幅收窄/环比改善"是否出现。有证据才说"接近筑底"，没有就说"预计延续疲软、筑底难度大"。
- 与主线台账交叉：强组若同时是在场主线（§九 判过"向上"），结构判断置信更高；强组完全不在主线注册表里 = 基本面领先于资金的方向，值得点名。

**第四步：写综述（(a)(b) 式分条 + 前瞻有据）。**

- 每条 = 宏观组 + 方向 + 依据（几家/增速中位/断层计数/原因共性各取关键的说）+ 一句前瞻判断。前瞻表述（"预计继续疲软""景气有望延续"）必须跟着依据与证伪条件（如"若下一批披露中该组扭亏/减亏占比明显上升，则筑底判断上修"）。
- **必带样本偏差 caveat**：业绩预告是触发式披露，天然偏向剧烈变化（大增/大减/扭亏/首亏），业绩平稳的公司缺席——综述反映的是**边际变化的结构**，不是全经济体量的结构；某行业"缺席"≠该行业没事。季初样本少时综述要标注初步、随披露累积更新。
- 结论写成一段成文文本，作为 verdict JSON 的 **`period_overview`** 字段落台账（一期一条，样本指纹变化后自动待复判）；HTML 页首与 Markdown 报告§二开头展示同一结论。红线不变：只判产业方向与基本面变化，不给配置/买卖建议。

## 十一、预告中值年化 PE（估值参照）

脚本在每股 `valuation` 块给两个确定性估值口径（总市值取最新交易日 `daily_basic`，一次全市场批量调用），HTML 详情页把年化PE放在头部醒目位置：

- **年化PE** = 最新总市值 ÷ 年化净利，**年化净利 = 预告中值 ÷ 报告期季数 × 4**（Q1×4、H1×2、Q3×4/3、年报预告即中值）。这是"全年都按本期节奏赚钱"的简单年化，**未调季节性**——淡旺季分明的行业（白酒 Q1 重、空调 H1 重、出版教育下半年重）会被系统性低估/高估。
- **滚动PE** = 最新总市值 ÷ 滚动净利，**滚动净利 = 上年年报实际 + 本期预告中值 − 上年同期实际**——用最近四个滚动季度消化季节性，作年化口径的对照；上年年报/同期实际缺失（次新股）时为 `base_missing`。年报预告两口径天然相等。

**扣非优先（有 cninfo 扣非时头条 PE 换口径）。** `forecast_scan` 的 `valuation` 是全市场结构化打底、只有归母口径；跑过 `cninfo_enrich` 拿到扣非中值后，HTML 渲染器（`render_period_html`）会**用扣非中值按同一年化系数（4/季数）重算年化PE，作为头条口径**，归母年化PE 退居"（对照）"。为什么优先扣非：扣非剔除了处置/补助/公允价值等一次性损益，更贴近主业真实盈利能力，PE 也就更贴近"为经营买单"的估值。三种情形：

- **扣非中值 > 0**：头条 = 扣非年化PE（label 标"扣非口径"），副行给扣非年化净利（带 cninfo `confidence`）+ 归母年化PE 对照。扣非略高于归母 PE 是常态（扣非 < 归母 → 分母小 → PE 高），差距越大说明归母里一次性成分越多。
- **扣非中值 ≤ 0**（归母正、扣非负）：利润主要甚至全部来自非经常性损益，扣非给不出 PE——头条退回归母年化PE，但**必须标注"扣非年化≤0（利润主要为非经常性损益）、归母口径 PE 参考意义有限"**，这是比任何 PE 数字都强的含金量警示。
- **未跑 enrich / 未取到扣非**：退回归母年化PE + 滚动PE（现状不变）。扣非口径只覆盖已增强的候选，别因为某票显示归母口径就以为它扣非差——多半只是没 enrich 到。

读法与坑：

- 口径优先级：**扣非年化 > 归母年化**（头条）；归母年化与滚动是对照。两口径分母都含**预告中值**（前瞻），与行情软件的静态PE（上年年报）、PE-TTM（全实际）都不是一回事，报告里引用必须注明口径（"扣非年化PE"还是"归母年化PE"）。
- **年化净利 ≤ 0 不给 PE**（`np_nonpositive`，仍亏损的减亏/首亏/续亏票）；扭亏但绝对利润很小的票，年化PE会飙到数百上千倍——那是低基数失真，不是"贵"，报告里按绝对额讲。
- **扣非解析有 confidence**（high=单位贴数字 / med=表头推断）。头条用扣非 PE 时把 confidence 一并标出，`med` 的先对照 enrich `text` 核一眼再采信（§七）。
- **两口径的差是信息**：归母年化PE 明显低于滚动PE = 本期利润节奏高于过去四个季度（加速或旺季），反之是减速或淡季——先排除季节性，再当加速/减速读。扣非年化PE 高于归母年化PE 的幅度 = 一次性成分占比的直观刻度。
- 红线：PE 只是估值参照证据，"贵不贵、值不值"要结合成长性与含金量由模型判断（个股估值深判用 `a-stock-analyzer`），不给买卖建议。
