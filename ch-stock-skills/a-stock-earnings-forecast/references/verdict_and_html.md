# 判分台账 + 主线匹配 + 行业趋势 + 产业综述 + 报告期 HTML

把模型的"优秀分档"、"归属主线"、"报告期行业趋势"和"产业结构综述"结构化落库（`forecast_verdict` / `forecast_theme_trend` / `forecast_period_overview`），再投影成一期一页的 HTML。分档锚点见 `methodology.md` §二，行业趋势归因方法论见 §九，产业结构综述见 §十；这里讲**主线匹配方法论**、两级行业判断的台账格式、判分/渲染工作流、增量与陈旧语义。

## 一、判分台账（forecast_verdict）

一条 = 一个 `(period, ts_code)` 的模型判断：`tier`（强/中/观察/剔除）+ `theme_id`（归属主线）+ `reason`/`caveat`/`theme_rationale`/`match_confidence`，外加脚本快照的 `evidence_ann_date`/`evidence_cum_yoy`（判分当时的证据指纹，用于陈旧检测）。

- **增量判分**：`verdict.py context` 只列「新披露 + 待复判」的股，老判分保留。每天只判增量，不重判全市场。
- **脑/手**：选谁哪档、归哪条主线是模型写进 JSON 的；`verdict.py record` 只做枚举/存在性校验 + 快照 + upsert。

## 二、主线匹配方法论（Agent 语义判断）

目标：把每只预告股对上 daily-market-sense 正在跟踪的**在场主线**（`theme_registry` + `theme_daily_state`），不是套行业标签。

匹配依据（context 已给全）：每条主线的 `name`、`aliases`（历年归一的别名）、`members_sample`（近日成员样本）、当前 `state`/`stars`。每只股的 `change_reason`（**最强信号**——业绩由什么驱动）、行业、名称。

判断步骤：
1. 读 `change_reason` 抓业务实质：是什么产品/环节在驱动业绩（如"电解液添加剂 VC 涨价""无人机动力系统放量""铜箔/铝加工"）。
2. 和主线的 name/aliases/members_sample 做**语义**比对，不是字面包含。例：孚日股份的 VC 属电子化学品 → 归"锂电/新能源材料"链；三瑞智能无人机动力 → 归"军工低空"。
3. 给 `match_confidence`：
   - `high`：业务实质与主线高度一致，或已是该主线成员样本。
   - `medium`：属于该主线的上下游/分支，方向对但不在核心。
   - `low`：只是沾边，渲染成"疑似【X】"，供人工复核。
4. **对不上就填 `null`**。不要硬贴。`null`=无归属，是"业绩强但暂无主线关注"的**正向信号**（潜在未被市场发现），HTML 会单列。
5. 一只股给**一条主线**（primary）。确实横跨两条，在 `theme_rationale` 里注明，`theme_id` 仍取最主要那条。
6. `theme_registry` 为空（daily-market-sense 没跑）时，`theme_id` 一律 `null`，报告说明"主线台账未填充"。

注意主线的**当前状态**由 HTML 渲染时实时 join（`theme_daily_state` 最新一日），不写进 verdict——所以看到的"在场候选★★/退潮"永远是最新的；归"退潮"主线也合法（业绩兑现但主线在退，本身是有用对照）。

## 三、报告期行业趋势台账（forecast_theme_trend）

一条 = 一个 `(period, theme_id)` 的模型判断，来源是对该主线**强表现（向上断层）与弱表现（向下断层）成员变动原因的分别归因 + 交叉验证**（方法论见 `methodology.md` §九）。判断材料由 `verdict.py context` 的 `to_judge_themes` 给全：每条待判主线的强/弱/无断层成员简报（含截断到 200 字的 `change_reason`、跳空幅度、回补状态、分档）。

模型在 verdict JSON 里与 `records` 并列写 `theme_trends[]`：

```json
{"theme_id": "TH-新能源新材料", "direction": "向上",
 "strong_common": "三只强表现均以电解液材料涨价+满产为主因，同一涨价链",
 "weak_common": "唯一弱表现为单一客户流失，个体事故、非行业信号",
 "cross_validation": "涨价传导到报表且被资金跳空确认，行业向上成立；弱侧不构成反证。下一步盯价格持续性",
 "confidence": "medium"}
```

- `direction` 枚举：**向上 / 向下 / 分化 / 证据不足**（"证据不足"是合法结论，样本 ≤2 或两侧都是个体因素时就该判它）。
- `strong_common` / `weak_common`：两侧的归因结论——共性是什么、还是个体因素；某侧无成员就填 `null`。
- `cross_validation`：一句话交叉验证结论（方向是否成立、由什么驱动、下一步看什么），HTML 详情页与组头 tooltip 直接展示它。
- `record` 校验 theme_id 存在、direction/confidence 枚举合法，并**机械快照**判断时点的强/弱/成员数（从落库后的台账 + evidence 断层方向重算，本轮新归属的成员计入在内）；主线本期无归属成员的趋势会被拒（无观察对象）。
- **哪些主线要判**：`to_judge_themes` 列出的（无趋势记录的 + 成员构成已变化的），加上**本轮你新把股票归入的主线**（context 生成于判分前，列不出它们，模型要自己补）。

## 四、产业结构综述台账（forecast_period_overview）

一期一条：模型基于**全样本**（正向 + 负向预告）的产业结构判断，成文文本直接落库。原料是 evidence 的 `industry_summary`（context 已透传）：按 stock_basic 行业的确定性计数——家数、正/负向、扭亏、加速、断层向上/向下、三口径增速中位数、大票成员。方法论见 `methodology.md` §十（宏观分组 → 强弱侧结构 → 筑底证据 → (a)(b) 式综述）。

模型在 verdict JSON 里与 `records` / `theme_trends` 并列写一个字符串字段：

```json
"period_overview": "1. 产业结构特征明显\n   (a) 高端制造科技（半导体存储/设备、锂电材料、氟化工、工业自动化）正向预告扎堆（xx家/占比xx%），单季增速中位 +xx%，断层向上 x 家——共性驱动是 AI/存储景气与材料涨价，多行业 change_reason 交叉印证；\n   (b) 消费与地产链负向预告聚集（预减/首亏 x 家），原因共性为终端需求疲软与减值，环比中位仍为负、扭亏占比未抬升，预计延续疲软、筑底难度大（证伪条件：下一批披露中减亏/扭亏占比明显上升）。\ncaveat：预告为触发式披露、样本偏向剧烈变化，综述反映边际结构而非全经济体量；截至 xx-xx 样本 xx 家，随披露累积更新。"
```

- `record` 校验它是**非空字符串**（综述要成文，不是要点碎片），并机械快照当时的样本指纹 `(总家数, 正向家数, 负向家数)`。
- context 的 `period_overview.reason_to_judge`：`no_overview`（还没写）/ `stale_sample`（指纹变了，新披露改变样本）/ `null`（当前有效）。`prev` 附上一版全文，重写时在其基础上增量修正即可。
- 综述**不依赖主线台账**（消费/地产等弱势行业本就不在上涨主线注册表里），主线台账为空也照常写。

## 五、陈旧复判（staleness）

判分后预告可能被修订、或增速大幅漂移。`context`（和 HTML）用 `evidence_ann_date != 当前 ann_date`，或 `|当前累计同比 − 判分时累计同比| > 阈值(默认 20 个百分点)` 判为**待复判**：context 会重新列出该股、HTML 打 `待复判` 徽标。模型下一轮据新证据修 tier/theme。这样分档永远知道哪些基于当前证据、哪些已过时。

行业趋势同理：台账里快照了判断时点的 `强/弱/成员数`，新披露的断层成员出现（或成员被改判到别的主线）后，`context` 把该主线以 `stale_membership` 重新列进 `to_judge_themes`、HTML 在「判·方向」上加 `†` 并注明"成员已变化，待复判"。把新成员并入原有强/弱两组重新归因即可，不用从头再判。

产业结构综述同理：快照样本指纹 `(总/正/负家数)`，任何新披露都会让它变 `stale_sample`——这是设计使然（综述本就该随披露累积演化），HTML 页首打「样本已更新，待复判」徽标，下轮在 `prev` 基础上重写。

## 六、报告期 HTML（render_period_html）

一期一个 `forecast_<period>.html` 页面入口，每次从累积缓存**整页重渲染**（幂等，不 patch DOM），并同时生成同级 `forecast_<period>.klines/` K 线分片目录。结构为「标题 → **产业结构综述**（`forecast_period_overview` 全文，判于日期 + 当时样本数，样本变化标待复判）→ 过滤条 → **左列表 + 右详情**双栏」（无 KPI 卡片），按「业绩×股价断层×主线行业趋势」组织：

**发布日期门禁（发布链路必开）**：先按北京时间计算 `NEXT_ANN_DATE=运行日+1`，扫描显式传 `forecast_scan.py --end-ann "$NEXT_ANN_DATE"`，渲染显式传 `render_period_html.py --require-ann-cutoff "$NEXT_ANN_DATE"`。渲染器会核对 evidence 的 `ann_cutoff`、`ann_cutoff_stock_count`、`clock_timezone=Asia/Shanghai`、总股票数及实际截止日公告计数；任一不一致即返回非零，不生成 HTML。这样可阻止并发扫描尚未落盘或旧 evidence 被提前发布。

页面头部必须可见展示：`公告扫描截至 YYYY-MM-DD（北京时间次日口径 · 截止日 N 家）`。即使截止日暂无公告也显示 `N=0`，让读者区分“已经查到次日但没有记录”和“根本没有扫描次日”。渲染摘要同步返回 `ann_cutoff`、`ann_cutoff_stock_count`、`evidence_generated_at`，供自动化在复制/构建前复核。

- **左侧列表**（每股两行：名称/代码/分档 + 断层强标注 + 主线内徽标；第二行 类型·三口径·公告后%·主线·披露月日），断层行整行淡色着色——**非 K 线信息展示统一红=上涨/强、绿=下跌/弱：向上断层淡红+`⬆断层+X% 未回补/已回补`**、**向下断层淡绿+`⬇断层−X%`**；字号层级要保证列表、详情、筛选器和脚注在宽屏下仍易读；分组/排序切换：
  - **按发布时间排序（默认）**：按最新公告日从新到旧排列，按日期组头展示，适合财报季每天追新增披露与修订预告；每行第二行同步显示披露月日。
  - **按主线分组**：每条主线一段，**组头显示报告期行业趋势**——机械计数 `↑偏强/↓偏弱/⇅分歧ㅤ强N/弱M`，已判过的主线再加**模型趋势 `判·向上/向下/分化/证据不足`**（hover 显示交叉验证结论，成员变化后带 `†`）；主线按净方向降序（在走强的行业排前）。
  - **平铺**。过滤器：搜索 / 向上断层(强) / 向下断层(弱) / **跳空未回补**（只保留向上跳空且未回补，即超预期未回补）/ 未反应 / 主线内 / 分档。
- **右侧详情**（sticky，点击列表切换）：
  - **年化PE醒目条**（头部正下方）：大号数字 = 年化PE，副行给总市值(含 asof 日期)、年化净利换算（中值×4/中值×2/…）与滚动PE对照。**扣非优先**：有 cninfo 扣非中值（渲染器 join enrich 得到）时，头条按**扣非中值同系数年化**重算 PE、label 标"扣非口径"、归母年化PE 退居"（对照）"；扣非≤0（归母正扣非负）退回归母并标"利润主要为非经常性损益、归母 PE 参考意义有限"；年化净利≤0 显示"仍亏损，PE 无意义"、缺市值/缺净利区间也如实说明，不硬给数。口径优先级与失真读法见 `methodology.md` §十一。
  - **K线图**（SVG 自绘，~130 根前复权 qfq 日K + 成交量，红涨绿跌）：**蓝虚线=公告日标注，落在公告日前一交易日（如公告日 7.3 则标 7.2）、橙虚线=公告前收盘**——断层缺口一眼可见；数据来自 `forecast_daily_cache`，渲染为 64 个确定性 JSON 分片，点击个股时只加载其所在分片并在浏览器内缓存，不阻塞首屏列表。
  - **股价断层**（精简，只留跳空幅度 + 公告后累计——其余走势看 K 线）。
  - **所属主线 · 报告期行业趋势**：先给机械层——该股所在主线的 `强表现(向上断层) / 弱表现(向下断层) / 无断层` 分布、净方向、强/弱成员样本；再给判断层——`forecast_theme_trend` 里模型判的方向、强侧归因、弱侧归因、交叉验证结论、confidence 与判断时点（成员已变化则标"待复判"）。个股由此放进行业景气语境。
  - 业绩块（归母中值/三口径/扣非/营收 trailing）、归属主线（状态+理由）、判分（reason/caveat）、业绩变动原因全文。
- 轻量 HTML 保留完整股票、判分、主线趋势与审计标签；左侧列表每批只创建 120 家 DOM 节点，以“再显示”按钮渐进展开；K 线放在同级 `.klines/` 分片目录，页面无 JS CDN、支持深色模式。HTML 与分片目录共同构成一期页面产物，发布时必须一起同步。断层方向与两型分类、行业趋势净值都是**机械阈值切分**（跳空≥`--gap-min`、分位 50 二分、净方向阈值 2），渲染只投影+计数；**行业趋势的定性（判·方向与归因）来自 verdict 台账里模型的判断**，渲染只是展示它，不替它判，不给买卖建议。断层新鲜度（D+n）必须可见——刚披露的"未回补"没经过时间检验。

增量落在数据层：DB 每天累积新披露 → evidence 全量 → verdict 增量判 → HTML 重渲染即"长大一点"。历史披露不因换天而丢。
