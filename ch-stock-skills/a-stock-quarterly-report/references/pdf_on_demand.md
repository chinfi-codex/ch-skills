# PDF 按需取用：什么时候开、开哪一节、怎么用

本 skill 的数值权威是 Tushare 结构化报表。PDF 不是备份数据源，是**补另一类信息**——API 里根本没有字段的那些。这份文档回答三个问题：什么时候该开、开哪一节、拿到之后怎么用。

## 一、判断标准：这个问题数字能不能回答？

**不要开 PDF**（结构化数据已经给全了）：

- 营收/利润/扣非/现金流是多少、同比多少、单季多少 → `growth`
- 毛利率、净利率、费用率、ROE、周转率 → `margins` / `quality`
- 合同负债、存货、应收、在建工程、商誉、负债率 → `balance_signals`
- 扣非和归母差多少 → `quality.non_recurring_yi`
- PE、市值 → `valuation`
- 有没有跳空、回补没有 → `price_reaction`

**该开 PDF**（API 没有这个维度）：

| 问题 | section | 典型触发 |
|---|---|---|
| 增长来自哪条产品线 / 哪个区域？ | `segment` | 营收大增但看不出结构；判断增长是主业放量还是并表 |
| 公司自己怎么解释这一期？ | `mdna` | 判可持续性；写行业趋势归因需要管理层原话 |
| 扣非和归母的差额是什么科目？ | `nonrecurring` | `dedt_ratio_pct` 明显低于 80%，必须查是处置、补助还是公允价值 |
| 收入集中在几个客户？ | `customers` | 增长很好但想知道脆弱性；大客户依赖 |
| 研发投入怎么分配、在研什么？ | `rd` | 研发增速远超营收增速，判断是投入前置还是费用失控 |
| 合同负债/存货/应收异动，公司怎么说？ | `balance_change` | `gap_pp` 报警，需要公司自述原因而不是我们猜 |
| 在手订单、产能、指引？ | `outlook` | 前瞻判断需要定性锚 |
| 股东户数、前十大变化？ | `shareholders` | 机构进出的公开痕迹 |

预设覆盖不到时用 `--find 关键词1,关键词2` 全文定位，返回命中处上下文。

## 二、季报 / 半年报 / 年报的差别（很重要）

**一季报和三季报按规定不含管理层讨论与分析，也不含分产品收入。** 它们通常只有 10–15 页：主要财务数据、股东情况、财务报表、非经常性损益明细。

- 对 Q1/Q3 请求 `segment` 或 `mdna`，脚本会返回 `text=null` 并附一句"本报告未检出该章节（季报按规定不含管理层讨论/分部数据时属正常）"。**这是正确结果，不是失败**。不要因此换个关键词硬找，更不要凭数字编一个分产品拆分出来。
- Q1/Q3 里**能**取到的：`nonrecurring`（非经常性损益明细，季报必披）、`shareholders`（前十大股东）。
- **半年报和年报**才有完整的 `segment` / `mdna` / `customers` / `rd` / `outlook`。年报常在 200–400 页，`mdna` 单节就可能十几页——这正是要分节而不是全文的原因。

**想省事可以用 `--summary`**：优先取《…报告摘要》。摘要通常 15–30 页，含主要财务数据和分产品收入，解析快得多；但没有完整 MD&A。要读管理层原话就别加这个开关。

## 三、怎么用返回结果

```bash
python3 scripts/report_pdf.py --period 20251231 --code 603986.SH --sections segment,nonrecurring,mdna
```

输出 `reports/qreport_pdf_<period>_<code>.json`：

- `announcement`：`title` / `url`（巨潮原文 PDF 链接）/ `ann_date` / `is_corrected`（是否更正后版本）/ `is_summary`
- `meta.pdf_pages`：整本页数，用来判断这次省了多少
- `sections.<key>`：
  - `label` 章节名
  - `page_span` 命中的页码区间（**引用时要标它**，如"分产品收入见年报 p.17–19"）
  - `text` 该区间正文（默认截断到 `--max-chars 12000`，不够用就调大）
  - `note` 未检出时的说明
  - `from_cache` 是否命中 `qreport_pdf_section` 缓存
- `find_hits.<关键词>`：`[{page, excerpt}]`，每页最多一条摘录

**引用纪律**：

1. 说"某产品线放量""管理层指引××""大客户占比××%"这类话，必须来自实际取到的 `text`，并标注公告标题 + 页码区间。
2. 章节边界是关键词定位的，可能多带一页或在页中切开。**关键数字要在 `text` 里核对原文**，不要只看章节标题就下结论。
3. `is_corrected=true` 说明这是更正后版本，原始披露的数字被改过——本身就是值得一提的信息。
4. 扫描件 PDF 解析不出文本时会明确报出，此时只能回到结构化数据，如实说明"未取到原文"。

## 四、缓存与成本

- 抽过的章节按 `(ts_code, period, section)` 落 `qreport_pdf_section`，再次请求直接命中缓存（`from_cache=true`），不重复下载。`--refresh` 强制重下。
- 一本年报几 MB 到几十 MB，下载 + 解析约 1–3 秒。**不要对候选池批量跑 PDF**——那既慢又没必要。正确用法是：模型先用结构化数据把候选收敛到几只，再对这几只定向开原文。
- 公告定位优先用 `report_scan.py` 已经批量扫好的溯源表；没有时才回落到按股查询，此时脚本会用 `qreport_disclosure` 里的实际披露日把查询窗口收窄到 ±4 天（否则要在公司一整年的几百条公告里翻页）。
