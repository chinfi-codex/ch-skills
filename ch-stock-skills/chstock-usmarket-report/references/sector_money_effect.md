# 板块赚钱效应引擎（纳指科技 · 移植 DMS M2/M3）

核心问题不是"哪些票涨了"，而是**今晚的钱在纳指科技的哪个方向上赚到，这个方向够不够格算主线**。这套方法论移植自 a-stock-daily-market-sense 的成交额集中度（M2）与赚钱效应主线（M3）。

## 成交额优先（dollar volume）

- `dollar_volume = close × 当日成交股数`，是 A 股"成交额"的美股对应，`scan_market.py` 已算好并按它降序。
- 一切强弱判断回到 dollar-volume：没有成交额支撑的涨幅只是弱证据。主题强弱按 dollar-volume 厚度排，不按票数、也不按涨幅。

## ① 赚钱效应池

- 来源：scan evidence 的 `market_wide_movers.rises`（已是 Nasdaq 过滤 + dollar-volume 降序 + 过了成交额下限）。
- **先剔非科技**：脚本只做了 Nasdaq 交易所过滤，池里会混入 Nasdaq 上市但非科技的票——钢铁(STLD)、生科(LEGN)、防务(KTOS)、空间(SPCX)等。模型读 `ticker + name` 判定并剔除，剩下的才是"纳指科技赚钱效应池"。认不出业务的标"业务待核验"，不硬塞主题。

## ② 模型按业务事实归纳主题（不套 ETF/GICS）

- 和 DMS 一样：按业务事实 / 产品环节 / 事件催化**临时归纳**主题——"AI 互联 / retimer"、"HBM / 存储"、"AI 服务器 / 液冷"、"光模块"、"量子计算"、"EDA / IP"……≥3 只成一组，不足的归"孤立强势股"。
- 不套现成行业或 ETF 标签。主题名要落到**具体业务环节**，不要写"半导体"这种大箩筐——除非当晚确实是整条半导体普涨，那才如实写成宽主题。

## ③ 钱在哪 = 主题 dollar-volume 占比

每个主题算：入池家数、dollar-volume 合计 + **占赚钱效应池比重**、涨幅中位、市值分布（巨头 / 中盘 / 小盘各几只）。

占比是第一门槛：dollar-volume 占比领先的主题才有资格进主线判定，不因为名字性感就抬评级。

## ④ ★ 主线确认 rubric（两遍走法）

- **Pass 1（免费）**：按主题 dollar-volume 占比排序，锁定领先 2–3 个候选主题。
- **Pass 2（有界回补）**：对候选主题成员跑 `python scripts/generate_report.py --enrich-tickers "A,B,C"`，拿 52 周位置 / 20 日趋势 / 量比 / vs-QQQ 超额，再评级。

评级锚点化，严格按此，不主观放宽：

- **★★★ 确认主线**：四条全中——① 主题 dollar-volume 占赚钱效应池领先（经验上 ≥ 25–30%，或为最大且与次席显著拉开）② 主题广度为正（池内该主题涨家数 > 跌家数）③ 成员 5 日 vs-QQQ 超额中位 > 0 ④ 成员量比中位 ≥ 1.5（放量确认）。
- **★★ 候选主线**：四条中满足 3 条。
- **★ 局部异动**：满足 ≤ 2 条，或主题内成员 < 3 只。★ 只进"资金轮动 / 局部异动"结论，不进主线表。
- 没有 ★★/★★★ 时写"今晚无确认主线，纳指科技赚钱效应偏资金轮动 / 个别巨头拉动"。

**位置（高位趋势 / 低位启动）**：看候选主题成员 `position_52w` + `drawdown_from_high_pct` 中位——多数 `position_52w ≥ 0.85`（贴近 52 周高）→ 高位趋势；多数 `≤ 0.5` 且当日刚放量 → 低位启动；证据不足默认写"高位趋势"。

**拥挤度（钱是集中还是扩散）**：按主题内前两名 dollar-volume 占该主题的比重——> 60% = 高（巨头独大）、40–60% = 中、< 40% = 低（普涨扩散）。巨头独大要点名："主题靠 X 单只拉动，广度未跟上"。

## ⑤ 领导股 / 弹性股分层

- **领导股** = 主题内最大 dollar-volume 承载者（不是涨幅最高那只），看成交额厚度 + 市场辨识度 + 收盘承接。
- **弹性股** = 仍属该主题、`position_52w` 偏低或市值不笨重、量比 / vs-QQQ 相对强、当日弹性大的中小盘。
- 每主题领导 1–3 只、弹性 1–3 只，证据不足不硬凑。产业链地位不确定写"地位待核验"。

## 与观察池的关系

板块赚钱效应是**全纳指科技**视角，不局限于池子；池子只是其中你已覆盖的部分。报告要回答"今晚钱在哪个主题、我池子覆盖到没有"——覆盖不到的部分接到 `new_direction_mining.md`。
