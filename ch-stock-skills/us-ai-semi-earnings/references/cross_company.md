# 跨公司交叉验证：这个 skill 和"逐家读财报"的区别

单看一家公司的财报，你只能知道它说了什么。这个宇宙的特殊之处在于**它是一条产业链**：超大厂的资本开支变成算力芯片的订单，算力芯片的出货受限于代工产能与 HBM 供给，代工的扩产变成设备订单，集群规模决定光互连与电力的需求。

于是**每一环都在为相邻环节的说法作证或证伪**。这是逐家读财报得不到的东西，也是本 skill 的主要价值。

---

## 四条传导链 + 一个对照组

链条定义在 `assets/universe.yaml` 的 `transmission_chains`，脚本在证据包的 `transmission_chains[]` 里把各环节的中位数按顺序排好，判定留给模型。

### 1. capex 传导链（滞后 1-2 季）
`hyperscaler_capex → ai_compute_chips → optical_interconnect → power_cooling`

超大厂的 capex 指引是整条链的需求源头，而且**领先于芯片公司自己的指引**。MSFT/GOOGL/AMZN/META 在电话会议上给的下年 capex 口径，比 NVDA 自己的展望更早、更少修饰。

- **确认**：源头 capex 上修 → 一两个季度内算力芯片营收环比加速 → 光互连与电力环节 backlog 抬升。
- **背离**：源头喊着加 capex，但光互连/电力环节营收环比平甚至掉。可能的解释按可能性排序：①钱先花在土建和电力而非 IT 设备（时序问题，看 `ppe_yoy_pct` 和 capex 结构）；②口径里塞了租赁；③下游产能还没释放，需求被压着没体现在收入。**报告要给出你倾向哪一种，以及下季看什么能证伪。**

### 2. 产能传导链（滞后 1-3 季）
`foundry_packaging → semi_equipment`

代工的资本开支指引 → 设备订单。TSM 一年给三到四次 capex 指引，是设备环节最可靠的领先量。

- **确认**：代工 capex 指引上调 → 下一两季设备公司营收与 backlog 同步抬升。
- **背离**：代工上调 capex 而设备环节平淡。常见真因是**结构而非总量**——钱去了先进封装而不是前道，或去了土建。此时看设备公司里谁在涨（封装/量测 vs 前道刻蚀沉积），差异本身就是答案。

### 3. 存储传导链（滞后 0-1 季）
`memory_storage → ai_compute_chips`

HBM 的供需与定价直接卡 GPU 出货上限。这条链的验证几乎完全靠电话会议措辞而不是数字。

- **确认**：存储端说供不应求、产能已售罄、价格继续上行；算力端同时承认供给紧张。
- **背离**：存储说紧张，算力说不缺货。**多半不是有人说谎，而是口径不同**——存储讲的是行业总量，算力讲的是自己已锁定的长约供应。报告要把这层说破，而不是简单判"矛盾"。

用 `read_source.py search "HBM" --frame CY2026Q2` 一次拉出所有提到的公司，比较各自的措辞强度。

### 4. 设计领先链（滞后 2-4 季）
`eda_ip → ai_compute_chips → foundry_packaging`

EDA 与 IP 的 backlog / RPO 反映的是**设计活动**，领先流片与产能需求两到四个季度。SNPS/CDNS 的 RPO 同比是这条链唯一有用的数字（`balance.rpo_yoy_pct`）。

这条链慢，但它是判断"这轮 AI 投资是不是还在往前铺"的最早信号：设计活动先冷，产能需求后冷。

### 5. 周期对照组（不参与传导）
`analog_power_mcu`

TXN/ADI/NXPI/MCHP/ON 这一组主要吃工业与汽车，**不在 AI 传导链上**。它存在的意义是当对照：

- **AI 链强、周期锚也强** = 半导体全面复苏；
- **AI 链强、周期锚弱** = 景气是结构性的，只集中在 AI，此时不能说"半导体周期回来了"；
- **AI 链弱、周期锚强** = AI 投资在退潮而传统需求在修复，这是最需要警惕的组合。

这个对照几乎每次都能让报告的结论更准确，别省。

## 怎么下判定

`verdict.py record` 接受的 `chains[]` 里，`state` 五选一：

| state | 什么时候用 |
|---|---|
| `确认` | 上下游数字与措辞同向，且**能点名**具体公司作证 |
| `部分确认` | 一部分环节兑现，另一部分没有，且能解释是时序还是结构 |
| `背离` | 上下游明确矛盾，且**两边都能点名** |
| `证据不足` | 关键环节本季披露太少（比如设备环节只报了 1/17 家） |
| `尚早` | 链条滞后期还没到，本季本来就看不出来 |

硬约束：`确认` / `背离` / `部分确认` 至少点名两家公司；多环节链必须覆盖至少两个环节。`确认` 把同向证据放进 `confirmed_by`，`背离` / `部分确认` 必须同时填写 `confirmed_by` 与 `contradicted_by`，而且只能引用这条链上的已披露公司。`verdict.py` 会拒绝不满足这些条件的判定。**没有链条两端名字的产业链结论就是一句正确的废话。**

## 一个具体的做法

财报季里每天做完个股判分后，跑一遍这个循环：

1. 看证据包 `transmission_chains[]`，哪几条链今天新增了成员。
2. 对新增成员所在的环节，和它上游/下游已披露的环节比 `median_revenue_yoy_pct` 与 `median_revenue_qoq_pct`。
3. 数字对不上的地方，用 `read_source.py search` 拉两边的会议措辞——**数字的矛盾，答案常在措辞里**。
4. 写进 `chains[]`，点名。
5. 下个季度回来看上次判的 `确认` / `背离` 有没有兑现。链条判断是可回测的，这是它比个股判断更有价值的地方。

## 别做的事

- **不要用一家公司代表一个环节。** 中位数是按已披露成员算的；只有一家报了的环节，`reported` 会显示 `1/17`，此时判 `证据不足` 而不是拿这一家当环节结论。
- **不要把滞后当背离。** 每条链都标了 `lag_quarters`；上游这季变好、下游这季没动，如果还在滞后期内，那是正常的，判 `尚早`。
- **不要跨链混用。** 周期对照组的疲软不能拿来证伪 capex 链，它们本来就不是一条链。
