# 科技概念拆解 · 可视化科普

把一个看不懂的科技 / 产业概念，拆碎成高中—大学教材水平能看懂的**图文动画科普**，面向做科技行情的人，只讲产业逻辑、不给买卖建议。**默认交付是一份单页 HTML**：文字稿按理解顺序成文，每镜动画 / 图片内联到对应段落；**视频是按需的次选**，用户明确要才出。

## 目标

1. **做什么**：接到一个技术或产业概念，先判断它是哪一类、用最自然的方式把机理讲明白，再落到"这事跟产业链和钱有什么关系"，最后落成一份图文并茂、动画讲解的网页(默认)；用户要视频时再出科普视频。
2. **不做什么**：不套死板模板硬拆；不在脚本里写讲解内容或调 LLM；不给目标价 / 买卖建议；不做个股估值；不杜撰未核验的参数与产业链事实。
3. **给谁用**：做科技行情、需要快速把一个新名词吃透到能判断产业链增量的投资者 / 研究员。读者画像 = 好教材里那个聪明的高中生 / 本科生：有基本科学素养，但没有行业黑话。

## 适用边界

- **认知基线**：一切讲解按高中—大学教材标尺写——先定义后使用、一镜一个新概念、先具体后抽象、旁白是"讲课"不是"带货"。详见 `references/scene_script.md`。
- **脑 / 手边界**：模型负责全部判断与表达——概念归哪一类、怎么拆、类比怎么打、动效什么时候为什么动、产业链谁受益。脚本只做确定性的事：把模型写好的文字稿 + 画面 + 时间轴装配成图文动画 HTML(默认)、按需把动画逐帧导出成视频。**绝不允许**脚本拼接讲解文案或替模型下结论。
- **取证纪律**：技术参数、产业链事实必须有据(WebSearch / 协同 `ch-news-reporter` / 已有 evidence)，带出处；拿不准的标注"存争议 / 待验证"，**不杜撰**。
- **防火墙**：只讲产业结构与受益逻辑(谁卖铲子、弹性在哪)，这是产业常识不是荐股；不点买卖、不给目标价、不做个股估值。

## 领域方法论(纲要，细节在 references)

### 1. 拆解三步：诊断形状 → 概念驱动地拆 → 投研锚点兜底

不存在一套适用所有概念的模板。流程是：

1. **诊断概念的"形状"**——它的"新"在哪？换了材料、换了架构、定义了规则、改了价值分配、造了新物种，还是突破了物理机理？不同形状有完全不同的最自然讲法。
2. **概念驱动地拆(具体问题具体分析)**——按"一个懂行的人会怎么把它讲明白"定顺序与颗粒度，围绕那个关键的反直觉点展开。这一步没有模板。
3. **收束到五条通用投研锚点(强制不可省)**——痛点 / 相对旧世界的增量 / 卡点壁垒 / 谁吃到肉+弹性排序 / 节奏与证伪信号。

形状诊断流程、archetype 库(七型，含识别信号 / 自然骨架 / 特有坑)、五条锚点的判定标准，全部在 `references/archetypes.md`。**每次拆解先读它。**

### 2. 设计规范先行(视觉 + 动效)

产物的视觉与动效遵循统一规范，规范先于具体画面：

- **视觉规范**：语义化色板、聚焦 / 背景 / 对比三态、统一知识图元库、隐喻一致性(带宽=通道宽度、堆叠=楼层、流程=管道、数据=粒子…)。见 `references/design_spec.md`。
- **动效规范(核心)**：动效必须承担教学职能，不是装饰。六类动效语法(引入 / 强调 / 对比 / 形变 / 流动 / 揭层)、节奏与缓动、伪 3D 规范、可达性(尊重 reduced-motion)。见 `references/motion_spec.md`。

### 3. 分镜脚本是中间产物

拆解结果写成两件中间产物：一份**文字稿**(把拆解按理解顺序成文，是默认网页的正文骨架)，和一份 **scene script(分镜脚本)**——每个"理解单元"一镜，每镜 = 一句口播 + 一个聚焦画面 + 一条动效时间轴(beats) + 一个 `anchor`(挂到文字稿哪个小节)。**默认图文网页和按需视频，是同一份文字稿 + scene script 的两种保真度**。数据结构与口播写法见 `references/scene_script.md`。

### 4. 技术与交付

SVG(2D / 伪 3D 等距)+ GSAP 时间轴 + CSS 3D transforms；不引入真 3D(Three.js)。

- **默认交付 · 图文动画网页**：文字稿用仓库共享的 `html_report` 框架 + **claude 主题**排版，每镜动画(conceptkit 组件或 custom 手绘 SVG，motionkit 按 beats 建 GSAP 时间轴)由 `scripts/render_explainer.py` 注入到对应小节标题之后。GSAP 内联(`assets/vendor/gsap.min.js`)，整页离线自包含。
- **按需交付 · 视频**：仅当用户明确要视频时——`scripts/build_storyboard.py` 出分镜表 + 画面，`scripts/capture_video.py` 逐帧 seek → 截帧 → ffmpeg，或交 `mmx-cli` 出片配音。

选型理由与两条管线见 `references/tech_stack.md`。

## 工作流程

1. **接概念 + 选深度**：默认产物是**图文动画网页**；只有用户明确要视频时才额外出视频。深度分电梯版 / 科普版 / 投研深挖。
2. **取证**：联网核对定义、关键数字、产业链、节奏，留出处；拿不准标"待验证"。
3. **拆解**：读 `references/archetypes.md`，走诊断三步，得到拆解大纲(已含五条锚点)。
4. **写文字稿 + scene script**：先把拆解写成按理解顺序的**文字稿**(Markdown，分小节)；再切**分镜**，每镜配口播 + 画面选型 + beats + `anchor`(挂到文字稿哪个小节)。遵循 `references/scene_script.md` 与两份设计规范。
5. **渲染(默认图文网页)**：`python3 scripts/render_explainer.py --article 文字稿.md --scenes 分镜.scene.json -o out.html` —— 出 claude 主题的单页 HTML，动画内联到对应段落。**仅当用户要视频**时，再走 `build_storyboard.py` + `capture_video.py` / `mmx-cli`。
6. **自检**：文字稿按理解顺序成文、每镜挂对锚点且只一个聚焦画面、数字有据、类比到位、五条锚点答齐、动效都有教学职能、未给买卖建议。

## 输出规范

- **文风讲人话**：像跟懂行的人当面把一件事讲清楚那样写，少模板腔；同维度的多条信息用 list，但每条说完整通顺的话，不要"字段A - 字段B"横杠拼接。结构化对照(新旧指标、上中下游)才用表格。
- **默认 · 图文动画网页**：一份单页 HTML，用 shared `html_report` 的 **claude 主题**；文字稿按理解顺序成文，每镜动画 / 图片内联到对应段落(锚点对齐)，投研锚点收尾。
- **按需 · 视频**：口播稿 + 分镜(画面 / 字幕 / 时长)，画面复用同一份 scene script，配音与合成走 `mmx-cli`；仅在用户明确要视频时产出。
- **结尾免责**：注明"科普图解，只讲产业逻辑，不构成买卖建议或个股估值"。
