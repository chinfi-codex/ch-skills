# framework.md — 投研研究框架

本文件定义投研 Agent 的研究框架、信源规则、证据规则、研究模板和评分规则。

Agent 必须遵守本文件，不得随意修改研究标准。

---

# 一、信源规则

## S 级信源 — 核心事实依据

包括：

1. 公司公告（重大事项、业绩预告、关联交易等）
2. 年报、半年报、季报
3. 招股说明书、上市公告书
4. 可转债募集说明书 / 配股说明书
5. 定增预案、重组报告书
6. 交易所问询函与回复
7. 监管机构文件（证监会、交易所处罚或问询）
8. 公司官网正式披露文件
9. 国家统计局、央行等官方统计数据

使用方式：

- 可作为核心事实依据
- 必须记录名称、日期、页码或位置
- 关键事实必须保留**原文摘录**

## A 级信源 — 交叉验证依据

包括：

1. 客户公告（对本研究对象而言是 A 级，对其自身可作 S 级看待）
2. 供应商公告
3. 政府招标 / 中标公告
4. 行业协会数据（中国半导体行业协会、汽车工业协会等）
5. 海关数据、进出口统计
6. 专利文件（国家知识产权局）
7. 招聘信息（细节透露产能、技术方向）
8. 环评文件、安评文件
9. 产能建设公示文件
10. 上下游 A 股公司财报中提到本研究对象的部分

使用方式：

- 用于验证客户、订单、产能、需求、技术路线
- 应与 S 级信源交叉

## B 级信源 — 经营动向依据

包括：

1. 投资者关系活动记录（巨潮披露的正式纪要）
2. 公司主办的电话会议纪要
3. 业绩说明会
4. 公司高管在公开场合（论坛、官方采访）的讲话
5. 主流财经媒体的署名采访（财新、第一财经、上海证券报等）

使用方式：

- 可用于判断经营趋势
- 不宜单独支撑核心结论
- 需要 S/A 级交叉验证

## C 级信源 — 研究线索

包括：

1. 券商研报
2. 第三方产业研究报告（IDC、Gartner、Counterpoint、CINNO 等）
3. 财经媒体未署名报道
4. 行业访谈（非官方）
5. 专家纪要（专家网络）

使用方式：

- 只能作为研究线索
- 不得直接作为核心事实
- 必须回到 S/A/B 级信源验证

## D 级信源 — 弱线索

包括：

1. 社交媒体（微博、X、雪球评论区等）
2. 论坛、股吧
3. 未署名纪要
4. 市场传闻

使用方式：

- 只能作为待验证线索
- 不得进入正式结论
- 不得支撑核心判断

## A 股特别提示

- **披露平台优先级**：巨潮资讯网（cninfo.com.cn） > 上交所/深交所官网 > 公司投资者关系页 > 第三方财经平台
- **业绩快报 vs 业绩预告 vs 正式财报**：业绩快报 / 业绩预告未审计前为 B-A 级，正式审计后年报为 S 级
- **券商研报**永远是 C 级，无论作者多有名
- **管理层路演纪要**：第三方撰写的非授权版本是 C 级；公司自行披露在巨潮的纪要才是 B 级

## 信源时效性规则

| 数据类型 | 推荐时效 | 上限 |
|---|---|---|
| 财务数据 | 最近一期已披露 | 不可超过 1 个完整披露周期 |
| 行业景气度 | 0-6 个月 | 12 个月（需注明） |
| 政策与法规 | 现行版本 | 已废止版本不得作为现行依据 |
| 价格、订单、招标 | 0-3 个月最佳 | 6 个月 |
| 技术路线 / 产能 | 0-12 个月 | 24 个月（需注明） |
| 市场份额 | 最新可得 | 24 个月 |

超过上限的证据，只能作为背景说明，不得作为核心结论支撑。

# 二、证据规则

证据是可以**支持或反驳某个研究判断**的可追溯事实。

每条证据必须回答：

1. 来自哪里？
2. 说了什么？
3. 支持哪个假设？
4. 是否有局限？
5. 可信度多少？

## evidence.jsonl 字段

```json
{
  "evidence_id": "EV-001",
  "entity": "珂玛科技",
  "topic": "客户订单",
  "source_name": "2024年年报",
  "source_type": "annual_report",
  "source_date": "2025-04-15",
  "source_url_or_location": "巨潮资讯，第 87 页",
  "reliability": "S",
  "original_text": "<原文摘录，必须填写>",
  "extracted_fact": "<结构化事实>",
  "supports": ["H1", "H3"],
  "contradicts": [],
  "confidence": 0.85,
  "note": ""
}
```

## reliability 取值

```
S：公司公告、年报、招股书、监管文件、官方统计
A：客户/供应商公告、政府招标、行业协会、海关、专利、招聘、环评
B：投资者关系记录、电话会、业绩说明会、署名媒体采访
C：券商研报、第三方产业报告、未署名媒体、专家纪要
D：社媒、论坛、股吧、市场传闻
```

## confidence 取值

```
0.9-1.0：强证据，来源可靠，表述明确，无歧义
0.7-0.9：较强证据，来源可靠，但需要交叉验证
0.5-0.7：中等证据，能提供方向，但不足以下强结论
0.3-0.5：弱证据，只能作为线索
0.0-0.3：不可用证据
```

## reliability × confidence 矩阵（重要）

`reliability` 是**信源**等级，`confidence` 是**该证据对当前判断的支撑强度**，两者**不可混淆**。

举例：

| 证据 | reliability | confidence | 解释 |
|---|---|---|---|
| 年报披露"主营产品 A 收入 10 亿元" | S | 0.95 | 已披露事实，强支撑 |
| 年报披露"公司将拓展 B 业务" | S | 0.55 | 公司表态，未实施 |
| 客户公告"采购公司 A 产品 X 万套" | A | 0.85 | 第三方独立验证 |
| 招聘信息"招聘 28nm 工艺工程师 10 人" | A | 0.50 | 方向证据，规模未定 |
| 投资者关系活动记录"产能利用率超 90%" | B | 0.70 | 公司表态，已定量 |
| 券商预测"明年净利润 2 亿" | C | 0.30 | 不能作为事实 |
| 股吧爆料"已拿下大单" | D | 0.10 | 不可用证据 |

**核心结论**必须满足：至少 1 条 `reliability ∈ {S, A}` **且** `confidence ≥ 0.7` 的证据。

## 证据冲突处理

当两条证据互相矛盾：

1. 信源等级高者优先（S > A > B > C > D）
2. 同级别中，时间更新者优先
3. 同时间，覆盖面更广 / 数据口径更明确者优先
4. 无法判定时，**两条都保留**，在 `gaps.md` 中标注"冲突待验证"，不得擅自取舍

## 交叉验证规则

强结论必须满足"两源独立"：

- 两条证据**不来自同一家发布主体**
- 不是同一份文件的不同段落
- 不是同一信源转载到不同平台
- 不是同一篇研报的不同版本

合规例：年报（S，公司发布） + 客户公告（A，客户发布） = 独立两源。
违规例：同一年报第 50 页 + 第 80 页 = 单源；A 券商研报 + B 券商研报且都引用同一行业协会数据 = 单源。

# 三、公司研究框架

## 1. 公司做什么

- 主营业务（产品 / 服务）
- 核心产品矩阵
- 收入结构（按产品 / 客户 / 地域）
- 毛利结构（哪个产品赚钱）
- 下游应用领域
- 所属产业链位置

## 2. 公司处在哪个产业链位置

- 上游主要供应商（议价权方向）
- 下游主要客户（议价权方向）
- 产品用于哪个环节
- 是否是关键瓶颈环节
- 是否有国产替代逻辑
- 是否受益于行业扩产 / 政策

## 3. 增长来自哪里

拆解增长来源：

| 类型 | 例子 | 持续性 |
|---|---|---|
| 行业需求增长 | AI 服务器拉动 PCB 需求 | 取决于行业周期 |
| 客户扩产 | 大客户新建产能 | 中期可持续 |
| 新产品放量 | HBM、CoWoS 等 | 取决于良率与认证 |
| 国产替代 | 半导体设备替代 | 长期结构性 |
| 价格上涨 | 涨价周期 | 周期性，注意拐点 |
| 产能释放 | 新厂房投产 | 一次性切换 |
| 并购整合 | 标的并表 | 一次性 |
| 会计口径变化 | 准则切换、分类调整 | 一次性，需剔除 |

必须区分：**一次性 / 周期性 / 结构性 / 可持续**增长。

## 4. 财务质量如何（最近 3 年）

收入、扣非净利润、毛利率、净利率、费用率、经营现金流、存货、应收账款、合同负债。

判断要点：

1. 收入增长是否转化为利润（"增收不增利"原因）
2. 利润是否转化为现金流（净利润 vs 经营现金流的差额来源）
3. 应收 / 存货是否异常（增速 vs 收入增速）
4. 毛利率是否可持续（结构变化、原材料、议价）
5. 费用率（销售、管理、研发）是否合理
6. 商誉、其他非经常性损益是否扭曲利润

## 5. 客户和订单是否可靠

- 前五大客户集中度
- 是否有大客户依赖（前一大占比）
- 客户是否为行业核心玩家
- 客户扩产是否支撑订单
- 订单是否可持续（一次性 vs 长协）
- 是否存在收入确认波动（验收节奏）

## 6. 竞争格局和壁垒

- 主要竞争对手（国内 + 国外）
- 公司相对优势（成本、技术、客户、规模）
- 技术壁垒（专利、工艺）
- 认证周期（半导体、医疗、车规）
- 客户黏性（切换成本）
- 替代风险（新技术路线）
- 价格竞争风险（产能扩张周期）

## 7. 业绩弹性和估值

尝试映射：

- 收入弹性（产能 × 产销率 × 价格）
- 毛利率弹性（量、结构、成本）
- 净利润弹性（经营杠杆 + 财务费用）
- 估值弹性（PE / PS / PB / EV/EBITDA / PEG，方法见第七节）
- 市场预期差（一致预期 vs 自有测算）
- 未来催化剂（具体事件、时间点）

不能量化时必须明确缺失数据。

## 8. 风险和反方观点

详见 `AGENTS.md` 第三节 Step 5。

# 四、行业研究框架

## 1. 行业是什么

- 行业定义（口径）
- 解决什么需求
- 属于哪条产业链
- 上中下游分别是什么
- 行业规模（量、值）

## 2. 需求来自哪里

- 技术升级（AI、新能源、汽车电动化等）
- 资本开支（运营商、晶圆厂、电网、车企）
- 政策推动（补贴、采购、限制）
- 国产替代
- 成本下降→新应用打开
- 新应用爆发（消费电子周期、AR/VR、机器人等）

## 3. 产业链怎么拆

| 环节 | 关注点 |
|---|---|
| 上游材料/设备/零部件 | 价格、供给、技术壁垒 |
| 中游制造/集成/服务 | 产能、良率、客户、成本 |
| 下游客户/应用 | 需求强度、节奏、弹性 |

每个环节识别：核心公司 / 价值量 / 壁垒 / 供需 / 边际变化。

## 4. 景气度判断

观察：订单 / 产能利用率 / 价格 / 交期 / 库存 / 资本开支 / 招标 / 客户扩产。

景气度判断必须标注**当前位置**：底部 / 上行 / 顶部 / 下行。

## 5. 利润流向哪里

- 哪个环节最紧缺
- 哪个环节议价权最强
- 哪个环节价值量最高
- 哪个环节利润率最高
- 哪个环节业绩弹性最大
- 哪个环节最容易被替代

## 6. 竞争格局

- 国内外主要玩家、市占率
- 技术路线分化
- 进入壁垒
- 替代风险
- 价格竞争风险（产能投放周期 vs 需求）

## 7. 投资映射

- 产业趋势
- 受益环节
- 核心公司（业绩弹性 vs 估值弹性）
- 高弹性公司
- 稳健公司
- 风险公司
- 跟踪指标

# 五、主题研究框架

主题研究指围绕一个**技术方向 / 政策 / 概念 / 事件**展开的研究（如"算力国产化""车路云""低空经济""DeepSeek 产业链"等）。

## 1. 主题定义

- 主题边界（包括什么、不包括什么）
- 触发事件（政策、技术突破、业绩拐点）
- 时间窗口（短期主题 vs 长期方向）

## 2. 驱动逻辑

- 政策驱动（具体文件、力度、可执行性）
- 技术驱动（突破程度、商业化距离）
- 资本驱动（资本开支或融资）
- 需求驱动（终端需求是否真实）

## 3. 受益产业链

按价值量 / 弹性梳理：

- 必受益环节（确定性）
- 弹性最大环节
- 边缘受益环节
- 不受益但容易被错认的环节

## 4. 关键节点公司

- 在确定性受益环节中的核心标的
- 在弹性最大环节中的核心标的
- 各标的的主题相关收入占比
- 主题相关业务的盈利模型

## 5. 节奏与催化剂

- 短期催化剂（订单、招标、政策落地）
- 中期催化剂（产能、客户突破）
- 长期催化剂（技术成熟、成本拐点）

## 6. 已被定价的程度

- 一致预期是什么
- 当前估值是否已反映乐观情景
- 边际变化的方向（预期向上 vs 向下）
- 拥挤度（机构持仓、换手率、舆论热度）

## 7. 反方观点

- 主题是否被证伪（技术不成立、政策落空、需求不达预期）
- 受益公司是否真受益（业务相关性可能被夸大）
- 估值是否过度透支
- 主题切换风险

## 8. 风险

- 政策风险
- 技术路线风险
- 需求风险
- 拥挤度风险
- 切换风险

# 六、核心假设框架

每次研究必须形成 3-5 个核心假设。

## 假设格式

```markdown
## H1：<假设名称>

### 假设内容

<一句话陈述，必须可证伪、可量化或半量化>

### 支持证据

- EV-001（reliability=S, confidence=0.85）
- EV-005（reliability=A, confidence=0.75）

### 反证证据

- EV-008（reliability=B, confidence=0.60）

### 财务或产业影响

- 收入：<量化或半量化>
- 毛利率：<方向 + 幅度估算>
- 净利润：<弹性测算>
- 估值：<可能的重估方向>
- 催化剂：<具体事件 + 时间窗口>

### 当前置信度

high / medium / low（必须根据 reliability + confidence 综合判断）

### 后续验证指标

- <可观察、可量化、有频率的指标>
```

## 假设质量标准

合格假设必须：

1. **可证伪**：能被某条未来证据推翻
2. **可量化**：哪怕是半量化（"收入有望提升 20-40%"）
3. **有产业含义**：不是单纯财务推理，要有业务逻辑
4. **有时间窗口**：何时能验证 / 兑现
5. **有跟踪指标**：用什么观察

不合格假设例（必须重写）：

- ❌ "公司未来发展前景广阔" — 不可证伪
- ❌ "受益于行业景气" — 不可量化
- ❌ "估值具备性价比" — 没有产业逻辑
- ❌ "中长期看好" — 没有时间窗口

合格假设例：

- ✅ "2026 年 HBM 业务收入占比将从 8% 提升至 25%-35%，毛利率比公司均值高 10pct，主要由 H 客户认证通过驱动"

# 七、估值框架（公司研究专用）

A 股二级市场常用估值方法：

| 方法 | 适用场景 | 注意事项 |
|---|---|---|
| PE | 盈利稳定、可比公司多 | 注意周期顶 / 底的反向 |
| PS | 高增长、未盈利或盈利不稳 | 必须看后续利润率假设 |
| PB | 重资产、金融、周期股 | 关注 ROE 与 PB 的匹配 |
| EV/EBITDA | 资本密集、折旧大 | 跨国比较常用 |
| PEG | 高增长公司 | G 的可信度是关键 |
| DCF | 现金流稳定、长期可预测 | A 股很少作为主估值，多作为压力测试 |
| 分部估值（SOTP） | 多业务公司 | 各业务用不同方法 |

报告中必须呈现：

- 核心方法 + 1 个交叉验证方法
- 估值锚（同行可比 / 历史分位）
- 关键假设的敏感性测算（量、价、毛利率三档情景）

```markdown
# <研究对象> 投研报告

## 一、核心结论

## 二、为什么现在值得研究

## 三、业务或行业概况

## 四、产业链位置

## 五、财务表现或行业景气度

## 六、增长来源
```

# 九、评分规则与锚点

每次研究结束后，写入 `results.tsv`。

## 评分维度与权重

| 维度 | 权重 | 说明 |
|---|---:|---|
| evidence_score | 25% | 证据是否可靠、充分、可追溯 |
| coverage_score | 15% | 是否覆盖业务、财务、客户、竞争、风险 |
| depth_score | 20% | 是否有推理深度，不只是资料堆砌 |
| counter_score | 15% | 是否充分寻找反方观点 |
| financial_score | 15% | 是否映射到收入、利润、估值 |
| actionability_score | 10% | 是否形成可跟踪指标 |

## 评分锚点（每个维度满分 100）

### evidence_score

- **90-100**：≥ 20 条 S/A 级证据，每条核心结论都有 ≥2 条独立来源，原文摘录完整
- **75-89**：≥ 15 条 S/A 级证据，核心结论基本满足两源独立
- **60-74**：S/A 级证据较少（10-15 条），部分结论单源
- **40-59**：以 B/C 级证据为主，缺少原文摘录
- **< 40**：以 C/D 级为主，存在编造或无来源结论

### coverage_score

- **90-100**：所有研究框架模块均完成，且有专门篇幅
- **75-89**：核心模块齐全，1-2 个非核心模块薄弱
- **60-74**：业务 + 财务齐全，竞争或风险薄弱
- **40-59**：仅完成业务介绍 + 财务，缺竞争 / 风险 / 客户
- **< 40**：仅完成最基础部分

### depth_score

- **90-100**：每个核心问题都做了因果分析，推理可追溯到证据，敢提出反共识观点
- **75-89**：核心问题有分析，少数缺因果链
- **60-74**：以资料整理为主，因果链较薄
- **40-59**：仅资料堆砌，缺独立推理
- **< 40**：复述他人观点

### counter_score

- **90-100**：3+ 个反方观点，每个都有证据支撑，并且有反方测算
- **75-89**：2-3 个反方观点，部分有证据
- **60-74**：有反方观点但偏模板化
- **40-59**：仅 1 个反方观点或全是模板
- **< 40**：未做反方检查

### financial_score

- **90-100**：完成收入 / 毛利 / 净利 / 估值四端映射 + 弹性测算 + 敏感性
- **75-89**：完成收入 + 利润映射，估值有讨论
- **60-74**：完成收入映射，利润和估值偏弱
- **40-59**：仅定性描述，无量化
- **< 40**：未做财务映射

### actionability_score

- **90-100**：5+ 跟踪指标，含频率、信源、触发动作
- **75-89**：3-5 个跟踪指标，含频率
- **60-74**：有跟踪指标但缺频率或触发动作
- **40-59**：仅泛泛提到要"持续跟踪"
- **< 40**：未输出 `tracking.md`

## 总分公式

```
total_score =
  evidence_score      * 0.25
+ coverage_score      * 0.15
+ depth_score         * 0.20
+ counter_score       * 0.15
+ financial_score     * 0.15
+ actionability_score * 0.10
```

# 十、反模式清单（必须避免）

1. ❌ 只写利好不写风险
2. ❌ 把券商盈利预测当业绩
3. ❌ 把媒体传闻当确定事实
4. ❌ 把"公司表态"当作"公司行为"（如把"将拓展"当成"已经在做"）
5. ❌ 用"显著""大幅""稀缺""优质""龙头"等空洞词替代数据
6. ❌ 报告里出现没有写入 `evidence.jsonl` 的数字
7. ❌ 把同一份年报的不同段落当作"两条独立证据"
8. ❌ 报告里出现"建议买入/卖出"或目标价
9. ❌ 用陈旧数据（>12 个月）作为核心结论支撑而不注明
10. ❌ 单源结论直接进 `final_report.md`
11. ❌ 假设描述模糊到无法证伪（"长期发展可期"）
12. ❌ 研究结束没有 `gaps.md` 和 `tracking.md`
13. ❌ 用同一信源在不同平台的转载充当"两条证据"
14. ❌ 把估算或推断写成"公司披露"

# 十一、核心原则

投研 Agent 的目标不是生成一篇漂亮报告，而是**形成可验证的投资假设**。

真正重要的资产是：

```
evidence.jsonl
claims.jsonl
hypotheses.md
counterpoints.md
tracking.md
gaps.md
```

`final_report.md` 只是这些资产的表达结果。当资产更新后，报告必须随之更新；当结论被推翻时，报告必须删除该结论。

研究的价值不在于"看起来全面"，而在于"经得起验证"。
