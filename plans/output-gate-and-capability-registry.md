# 能力注册 + 输出校验：让 skill 的"最终输出动作"可判定

> 状态：Phase 0–4 已实施（2026-08-09）。在原 DMS 试点基础上，按后续确认范围同时迁移 `ch-news-reporter`；通用实现收敛为 Skill Factory + Production Runtime，流程图与最终架构见 `docs/skill-production-framework.md`。
> 目标：skill 在 agent 里执行时，**结果输出这个动作的准确与完整可被机器判定**，而不是靠模型自述。

> 实施说明：下文 Phase 1–4 保留为立项时的设计记录；最终代码把其中分散的 registry / receipts / provenance 能力统一进 `shared/skill_runtime/`，把输出类型与领域规则统一编译进 `shared/output_gate/`。

## 1. 问题拆解

一个 skill 的执行分"动作"与"判断"两部分。要保障的是动作侧。DMS 的最终输出动作只有两个，且**性质不对称**：

- **写 Markdown —— 模型的动作**（直接 Write 落盘）。没有脚本，因此无能力可注册、无凭证可记。**只能靠产物校验这一条腿站着**。
- **生成 HTML —— 脚本的动作**。注册表 + 凭证管得住。

"输出不准不全"在本仓库已发生过的失败模式有六类：

1. 动作不是注册能力做的（临时脚本、手工改产物）——产物看着正常，但没有 manifest、没有 build_id，校验无从下手。
2. 动作跑了但不全（地缘台账 12 母题 → 39 条 0 母题：投影只渲顶层、守卫展平追责，两边都"成功"）。
3. 动作对了但输入是旧的（旧 evidence、旧缓存）。
4. 产物内容缺件（章节漂移、必填字段缺、文本被吃掉）。
5. 下游搬运丢件（`.klines/` 没跟着拷、Site 外部化剥脚本、线上 CSP 拦截）。
6. 模型自己宣布成功（动作失败但总结写"已生成报告"）。

**两个杠杆的分工**：能力注册范围管第 1 类（谁有资格动手），输出校验管第 2/4/5 类（动完对不对），第 3 类是接缝（输入指纹），第 6 类靠"产物自证 + 回话必须引用机器凭证"。

注册表本身不产生约束力——写在文档里的规则对模型只是劝告，跨 agent 跑（Kimi / Codex / Hermes 不受 Claude Code hook 管）更无从执行。**真正起作用的是"注册表 + 运行凭证 + 内容指纹"这条 provenance 链**：它让"有没有绕过"从不可见变成事后可判定。

## 3. 现状盘点（已核实）

### 4.3 校验从二态改三态

既然缺席语义是"降级"，校验就是：

1. **标题恒在**（19 条全 required + 顺序 + 层级）
2. **降级文案白名单**：契约为每节登记合法降级文案的正则，命中即判「已声明降级」，记进审计 `degraded` 列表，不红灯
3. **降级必须有据**：判为降级时回查 evidence 对应的 `available=false` 或空候选，**对不上就是谎报缺数据**——模型写「暂无命中」但 evidence 里躺着 12 只票，这是今天最抓不到、最伤准确性的一类

与 HTML 侧「允许缺口，但缺口要有名有姓」完全同构，只是把台账从图表搬到章节。

顺带补三类契约今天表达不了、但输出要求写得很明确的东西：

- **动态数量标题**：3.2 下的 `### [主线名称]` 数量 = 3.1 表里 **★★★** 行数。这是 `expected = matched + unmatched` 在 Markdown 侧的形态
- **必须高亮的定性段**：`output_discipline.md` 点名七处（指数趋势判断、市场风格判断、盘面定性、拥挤度判断、主线 vs 资金轮动结论、风险传导提示、特征分组一句话判断），存在性可布尔判定
- **可布尔的纪律条款**：买卖建议禁用词（买入/卖出/加仓/止损/目标价）进硬门禁；"判断段首句不以连续数字开头""同一自然段关键数字 ≤3"做软告警

**数值一致性的可行口径**（不做全文数字比对，模型会写四舍五入值、日期、引用历史统计，误报率必然失控）：

> 只校验**表格单元格**里的数字必须能在 evidence 中命中。表格是脚本喂的确定性数据，段落是模型的判断。段落数字降级为软告警——出现在段落、既不在 evidence 也不在本页表格里，列进审计 `detail`，不红灯。

回归夹具用 `report_20260807.md`，**它会红，且该红**。

## 5. Phase 1 — DMS 能力注册表

新增 `ch-stock-skills/a-stock-daily-market-sense/capabilities.yaml`。每条能力申报：

- `id` / `entry`（脚本路径）/ `kind`：`fetch` | `compute` | `persist` | `render`
- `effects`：真实副作用面，如 `net:tushare`、`db:alpha_data.*`、`fs:reports/*.html`
- `terminal`：是否直接产出用户可见交付物（预计只有 `render_report_html.py`；`run_daily_panel.py` 产 evidence 属中间物）
- `judgment`：`forbidden`（取数/渲染类）或 `allowed`——把"脚本不得替模型做领域判断"从人工评审变成可 lint 的声明
- `requires`：前置能力链
- `verify`：产物校验命令与后置条件

这一步的真实产出不是文件，是**逼出一次能力面盘点**：15 个脚本哪些还在被调用、哪些是历史遗留、`factor_*` 四个是不是同一条链。执行时删掉 `reports/crowding_analysis.py`（决策 5）。

## 9. 规范落点（三处文档 + 一处机器检查）

`skill_sync.py` 只同步 skill 目录，**AGENTS.md 既不进 agent 安装目录也不进发布包**。skill 在 Kimi / Hermes / Codex 里被触发时只看得见 `SKILL.md` 和 `scripts/_shared/`。所以运行期规则写在 AGENTS.md 里等于没写。

| 落点 | 受众 | 写什么 | 随包走 |
|---|---|---|---|
| `AGENTS.md`（§2.6 扩为「能力注册」、§2.7 加「输出校验与交付门禁」、新增 provenance 节） | 造/改 skill 的 agent | 规范本身 + 新 skill 必备清单 | 否 |
| `CLAUDE.md` | Claude Code 自动加载 | 3–5 行指针 + 红线：终端产物只能由注册能力产出 | 否 |
| `shared/output_gate/references/output_gate.md`（进 `shared.bundles`） | **运行 skill 的 agent** | 运行期契约（见下） | **是** |
| 各 `SKILL.md` | 运行期 | 只放本 skill 的具体值：契约版本、terminal 能力名、reason 闭集 | 是 |

运行期契约三条：

1. 终端产物只能由注册能力产出；手写或临时脚本触碰产物即违规，必须回到注册能力重做
2. 交付前必须跑门禁；**回话里必须报出审计文件路径、`gate_pass`、`build_id`、缺口条数与原因分布**，不允许用自然语言声称"已完成"
3. 缺口要在正文里用人话讲清楚（哪些没覆盖、为什么），不能只躺在 JSON 里

门禁失败时：不发布、不 cleanup、把 `problems` 前若干条原文贴出来。

## 10. 全局通用规则（写进 AGENTS.md，所有 skill 一体适用）

1. **契约是输出要求的机器投影，逐条可追溯**。契约里每个条目必须标出处（哪个模板文件的哪一行），`required` / 降级文案 / 动态数量的判定必须来自那处原文，不能是契约作者的推断
2. **模板没写清楚的，先补模板再补契约**。契约里不允许出现"我猜这节可以没有"
3. **lint 强制双向对齐**：模板标题集合 == 契约条目集合，任一侧改动另一侧没跟就红灯

通用的是**机制**（契约、台账、attestation、provenance、audit 形状、退出码语义），不通用的是**契约内容**（DMS 的 19 条标题表、reason 闭集、哪节配哪种图）。现有 `html_report` 已按这条线切分，继续沿用。

## 11. 边界与风险

- **不校验判断质量**。门禁只出布尔结论；结论是否站得住、文风是否讲人话归 rubric 层，两层各自聚合绝不混。混进来的那一刻门禁就开始产生假红灯
- **不追求 100% 防绕过**。目标是把"绕过"从不可见变为可判定：产物指纹与凭证不匹配就会在审计里留痕
- **缺口原因闭集要小**。天天误报的门禁三天内就会被绕过。新增 reason 是一次评审动作
- **注册表必须被读**。只被人看的注册表三个月内必腐——门禁读它、lint 守它
- **铺开当天现有链路大概率会红几次**（决策 4 的已知代价）
