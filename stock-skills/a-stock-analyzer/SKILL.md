# 股票AI分析助手

把这个技能当作股票投研方法论使用。不要依赖脚本生成报告、提示词、投资结论、组合分析或推荐。脚本只能取数；你作为智能体负责解释数据、判断重点，并直接写出最终内容。

## 总原则

- 所有内容逻辑都放在本 `SKILL.md` 中：分析路径、判断标准、报告结构、措辞边界。
- 只使用 `scripts/data_fetcher.py` 获取单一数据集，或解析股票名称/代码。
- 不要调用旧版组合分析脚本：`stock_analyzer.py`、`enhanced_analyzer.py`、`financial_ratios.py`、`ai_client.py`。
- 不要把脚本输出当成投资判断。脚本结果只是证据，结论必须由你基于证据推理得出。
- 每次输出都要包含简短风险提示。不要提供个性化投资建议。

## 数据获取

必需环境变量：

```bash
TUSHARE_TOKEN=your_token
```

一次只获取一个数据集：

```bash
python scripts/data_fetcher.py search 贵州茅台
python scripts/data_fetcher.py fetch company 600519.SH
python scripts/data_fetcher.py fetch financial 600519.SH --limit 8
python scripts/data_fetcher.py fetch income 600519.SH --limit 8
python scripts/data_fetcher.py fetch balance 600519.SH --limit 8
python scripts/data_fetcher.py fetch cashflow 600519.SH --limit 8
python scripts/data_fetcher.py fetch daily 600519.SH --limit 120
python scripts/data_fetcher.py fetch daily-basic 600519.SH --limit 60
python scripts/data_fetcher.py fetch main-business-product 600519.SH --limit 30
python scripts/data_fetcher.py fetch top10-holders 600519.SH --limit 4
python scripts/data_fetcher.py fetch managers 600519.SH
python scripts/data_fetcher.py fetch rewards 600519.SH
python scripts/data_fetcher.py fetch holder-number 600519.SH --limit 20
```

默认使用 JSON 输出。只有在表格查看更方便时才使用 `--format csv`。

## 工作流程

1. 识别用户意图：
   - 基本面：获取 `company`、`financial`、`income`、`balance`、`cashflow`、`daily-basic`、`main-business-product`、`top10-holders`。
   - 技术面：获取 `daily`、`daily-basic`。
   - 专题分析：先完成基本面基线，再只补充与专题直接相关的数据。
   - 如果用户给的是股票名称，先用 `search` 解析股票代码。

2. 收集证据：
   - 只获取完成任务所需的最小数据集。
   - 财务趋势优先取最近 6-12 个报告期。
   - 技术分析根据周期取最近 60-250 个交易日。
   - 数据缺失时要明确说明缺口，并降低结论置信度，不要补造数据。

3. 统一判断口径：
   - 比较最新一期与历史期间。
   - 区分绝对水平、趋势变化和异常波动。
   - 区分会计利润和经营现金流。
   - 把估值视为情景推演，不要把单一目标价当成事实。

4. 写作输出：
   - 先给核心结论和置信度。
   - 用取到的数据作为证据。
   - 显式说明关键假设。
   - 结尾写清风险和非投资建议声明。

## 基本面分析方法

完整基本面分析按以下结构组织：

1. 核心判断
   - 用简洁语言概括业务质量、财务质量、估值压力或机会、主要风险。
   - 根据数据完整度和指标一致性标注置信度：高、中、低。

2. 公司与业务
   - 识别行业、板块、地区、上市日期、公司简介。
   - 有主营构成数据时，用 `main-business-product` 判断收入来源。
   - 判断收入是否集中、是否多元、是否周期性强、是否依赖政策或项目。

3. 财务质量
   - 收入与利润：观察增长方向、波动性和匹配度。
   - 盈利能力：关注毛利率、净利率、ROE、ROA 的趋势。
   - 现金含金量：比较经营现金流相关指标与利润指标。
   - 资产负债：关注杠杆、流动比率、速动比率和偿债压力。
   - 异常信号：收入利润背离、毛利率大幅下滑、现金流弱于利润、杠杆突然上升、ROE持续下行。

4. 估值框架
   - 有 `daily-basic` 时使用 PE、PB、PS、市值等数据。
   - 用户未要求目标价时，不要机械生成目标价。
   - 如果用户要求情景分析，给出三种文字情景：
     - 基准情景：当前盈利能力和适度增长延续。
     - 乐观情景：利润率、增长或市占率改善。
     - 压力情景：需求走弱、利润率压缩、杠杆或现金流恶化。
   - 每个情景都要写明假设、需要的验证证据，以及什么情况会推翻该情景。

5. 股东与治理
   - 使用 `top10-holders`、`managers`、`rewards`、`holder-number`。
   - 判断股权集中度、核心股东稳定性、机构/社保参与、管理层激励和股东户数变化。
   - 不要基于单个报告期过度推断治理质量。

6. 风险
   - 分开写公司风险、行业风险、估值风险、流动性风险、数据质量风险。
   - 提醒公开数据可能滞后于公司真实经营状态。

## 技术面分析方法

用日线数据手动推理，不要让脚本生成技术信号。

重点查看：

- 趋势：最新收盘价相对 5/10/20/60 日均线的位置。
- 动能：近期涨跌斜率和量价配合。
- 波动：长阴长阳、跳空、异常成交量。
- 支撑与压力：近期高低点、密集成交区。
- 风险控制：指出技术判断失效位置，而不是给确定买卖指令。

技术面输出按以下结构：

1. 趋势状态。
2. 量价与动能证据。
3. 关键价格区域。
4. 短期风险点。
5. 非投资建议声明。

## 专题分析方法

当用户提出类似 `某股票，基本面，重点查询分析 AI PCB 关联性` 的问题：

1. 先执行基本面基线流程。
2. 判断专题需要哪些证据：
   - 产品或客户暴露：公司简介、`main-business-product`。
   - 财务贡献：财务指标、利润表、主营构成。
   - 市场验证：如需当前外部事实，联网检索公开来源并引用。
3. 明确区分事实和推断：
   - 已确认：由取数结果或可靠公开来源直接支持。
   - 推断：有逻辑关联但未被直接披露。
   - 未知：没有找到可靠证据。
4. 最后给出关联度：高、中、低、无法判断。

```markdown
**结论**

**关键证据**
- 业务：...
- 财务：...
- 估值：...
- 股东/治理：...

**主要风险**
- ...

以上基于公开数据和当前可得信息，不构成投资建议。
```

### 基本面完整版

```markdown
**核心判断**
[整体观点、置信度、最重要变量]

**业务结构**
[行业、产品、主营构成、竞争力]

**财务质量**
[增长、利润率、现金流、杠杆、异常信号]

**估值与情景**
[估值水平；基准/乐观/压力情景假设]

**股东与治理**
[股权集中度、管理层激励、股东户数趋势]

**风险清单**
[按重要性排序的风险]

以上基于公开数据和当前可得信息，不构成投资建议。
```

### 技术面

```markdown
**趋势**
[均线和价格结构判断]

**量价与动能**
[成交量、近期走势、波动情况]

**关键位置**
[支撑、压力、失效位置]

**风险**
[什么情况会推翻当前技术判断]

以上仅为基于历史交易数据的技术分析，不构成投资建议。
```

## 质量要求

- 能给具体数字时优先给数字，但不要堆原始表格。
- 数据有日期时写明报告期或交易日。
- 不要编造竞争对手、客户、政策或产业事实；这类当前外部事实需要联网检索并引用来源。
- 避免单边结论，要写出最强反方观点。
- 最终回答要适合投资者阅读：简洁、有证据、清楚表达不确定性。
